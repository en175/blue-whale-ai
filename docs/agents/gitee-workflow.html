每一步谁来点、什么时候点

#从 → 到什么时候
1未开始 → 开发中开始写代码（缺陷：开始修）
2开发中 → 测试-待测试代码合进 release、测试站部署好之后才点，并在工单里 @测试。只是本地提交 / 开了 PR 不算
3测试-待测试 → 待发布测试站验证通过
4测试-待测试 → 测试-测试打回测试站没过，评论里写清复现步骤
5测试-测试打回 → 测试-待测试修好并重新部署到测试站，直接重新提测
6测试-测试打回 → 开发中要改的比较多，先接回去
7待发布 → 生产-待验证发到生产，且需要在生产上复验（不需要就走跳步 B 直接已上线）
8生产-待验证 → 已上线生产上验过
9生产-待验证 → 生产-验证打回生产上没过
10生产-验证打回 → 开发中开发接回去修，修完重新走 2

四条规矩

1. 「已上线」才是完成；「已关闭」是作废，做完的单别点它。
2. 「测试-待测试」= 测试站上现在就能测。代码还没部署上去别点，测试会白跑。
3. 父需求：下面子任务都到「待发布 / 已上线」后，父需求改「测试-待测试」并 @测试，整体测一遍。
4. 往回退随便退；往前只能走主线和 A / B / C 三条跳步。

退役的旧状态（老单已迁走）

测试中 → 测试-待测试 · 已完成（任务）→ 已上线
已修复（缺陷）→ 已上线（近 7 天的 → 测试-待测试）
已验收（缺陷）→ 已上线 · 已拒绝 → 已关闭
