# Gitee 工作流（给 Agent 读）

本手册是本仓状态语义、有效枚举、事件条件、角色权限、跳步与例外的唯一权威。开工、恢复、返工、部署确认、提测、生产验证与收口前必读。人类说明见 [gitee-workflow.md](gitee-workflow.md)；MCP 参数、归属、认领与回读见 [issue-tracker.md](issue-tracker.md)；工程依赖与 Git 证明见 [集成工作流](integration-branch-workflow.md)。工单与 PR 全部读写仅使用 Gitee MCP。

## 判断与执行顺序

1. 读取实际类型、当前细状态、交付范围、验收安排与相关前置。粗状态仅用于检索分组，已上线表示完成，已关闭表示作废。
2. 核对真实交付事件及有效证据，确认执行角色与本轮授权。提交、工程验证、开 PR、合并均记录工程进度并保持业务状态。
3. 按下文选择满足条件的流转，用操作手册写最少字段并回读。状态池只证明 ID 有效，不证明具备流转条件。
4. 细状态未知、证据冲突、并发归属不明或结果未知时，停止依赖写入，按操作手册与渠道规则报告并核验。

## 开工、返工与恢复

下面的开发中对缺陷读作修复中。

| 当前阶段 | 条件与动作 |
| --- | --- |
| 待评审、待排期、待确认 | 有实施授权，声明前置满足、worktree 成功后，按实际类型进入开发中并认领 |
| 开发中、修复中 | 新认领先停止，报告可能已有执行者；明确恢复同一任务时按下述恢复核验处理 |
| 测试-测试打回、生产-验证打回 | 已有对应人员失败结论且返工授权覆盖本轮时，接回开发中再实施 |
| 测试-待测试、待发布、生产-待验证 | 保持阶段并报告，已有明确范围与返工授权时按定向返工处理 |
| 已上线、已关闭 | 停止普通开工，报告完成或作废及本次范围差异，由负责人决定后续处理 |

恢复同一整包时核对原实施授权与恢复意图、交接、工作区、分支、目标发布线、起点、HEAD、未保存文件、已合回子任务与 PR 进展。确认原执行者已停止或明确交接后才继续。相同 token 或 assignee 不能单独证明排他执行；归属不明时停止依赖写入。

评审修订若业务阶段仍在开发中，只记录工程返工。父测试失败须有失败行为、版本和影响范围，协调者定位需要修改的随父验收子单，明确返工授权覆盖本轮后，仅将这些待发布子单退回开发中。未受影响子单保留结论，受影响共享行为重验。父单按修复阶段保持测试打回或接回开发中，不能提前宣布通过。

修复重新完成工程验证、合入及部署覆盖后，子单按 A 恢复就绪，父单按对应提测授权重新提测。生产失败先由测试或产品记录生产-验证打回，再按失败结论与授权组织开发修复，重新核对实际部署、测试和发布要求。

## 主线与角色

| 交付事件 | 流转与条件 | 角色 |
| --- | --- | --- |
| 本地提交、工程验证、创建 PR、合并 PR | 保持业务状态；记录提交、验证、PR 或合并结果；开 PR 合并保留 ready-for-review 标签 | 开发 |
| 合入且确认测试站覆盖本票、真实验收入口可用 | 开发中到测试-待测试；已打回修复重新部署后也可提测，评论写验收范围、入口与证据 | 开发；父单需明确提测授权 |
| 测试站验收通过或失败 | 测试-待测试到待发布或测试-测试打回 | 测试人员根据实际结论 |
| 生产部署完成且需复验 | 待发布到生产-待验证，逐票核对实际版本及复验范围 | 发版人；Agent 代发版需明确授权 |
| 生产复验通过或失败 | 生产-待验证到已上线或生产-验证打回 | 测试或产品根据实际结论 |
| 明确作废 | 已关闭 | 负责人判断，开发 Agent 不自行代判 |

测试或产品的明确结论可以作为依据，开发 Agent 不自行作通过、打回或作废判断。发版授权、父单提测授权和既有发布渠道约束继续有效；已覆盖的授权不重复索取。蓝鲸测试通知沿用 `@ouweich`，通知仅在已有授权覆盖时发送。

### 部署证明

接受部署负责人的明确回执，或实际运行版本核验。记录环境、实际运行版本、覆盖工单、核验时间与来源。按实际受影响的部署单元逐个核对，前端已更新不能推断后端或 worker 已更新；各服务可使用不同 SHA，但须分别证明覆盖所需成果。

PR 合并、CI 成功或仅有分支名均不能单独证明部署。部分部署时父单保持当前阶段，逐票按实际覆盖判断子单。缺少必要证据时只记录已知进度，不提前提测。

### 跳步 A、B、C

- A：默认随父验收子单在合并且测试站部署覆盖本票后，从开发中到待发布，评论声明随父验收。此时表示交给父单整体验收，不代表独立测试通过。
- B：明确无需生产复验时，实际生产部署完成后由发版人从待发布到已上线。Agent 代发版按明确授权执行。
- C：按实际影响确认免业务测试，满足交付与验收后由开发中到已上线。纯说明文档、调研或答疑仍需工程检查与本票验收；仓库规则等需合并交付的成果，合并后才可收口，直接交付的结论在发出且满足验收后收口。运行行为配置执行对应验证，不能因文件类型直接免测。规划发布和拆单不借 C 完成产品父单。

往前只走主线及 A、B、C，需求另有待评审直接开工。返工按失败证据、实际阶段与授权处理，接口拒绝不能换状态绕过。

## 父子验收与逐票收口

父单承担完整用户行为的整体验收，子单各自完成工程验证，业务验收默认随父。独立验收例外须在子单声明范围与真实入口条件；相关改动部署就绪后按本票安排单独提测。父提测仍须确认该子交付范围就绪。

| 阶段 | 父单与随父验收子单 |
| --- | --- |
| 规格发布、拆单 | 新单保留类型初始态；既有单按实际阶段处理 |
| 子任务实施、工程验证、受控合回、整包审查、PR 入 release | 父和已开工子单保持开发中，未开工子单待排期 |
| 测试站部署覆盖本票 | 子单逐票按 A 到待发布，整包未就绪时父单保持开发中 |
| 必要范围和真实环境均就绪 | 核对当前完整范围、整包验证、部署与明确提测授权后，父单到测试-待测试 |
| 父整体测试通过 | 父单到待发布，子单关联明确覆盖本票的版本、行为和结论 |
| 生产部署及复验 | 需随父复验的子单逐票进入生产-待验证；实际结论覆盖本票后逐票已上线，明确免复验时走 B |

父状态不能替代子单证据，不按父状态批量完成。复用父验收记录必须明确版本、行为与本票覆盖范围，同一行为无需重复执行相同验收。随父验收默认也随父完成必要生产复验。

父单已上线但出现新增或未部署子单时，暂停该子上线收口，报告原验收范围、生产版本与当前关联范围的差异。由负责人判断后续增量或原承诺遗漏，不自动完成子单或回退父单。

## 证据刷新与失败处理

接手整包建立完整任务图，接手子票核对自身、父要求与直接前置。依赖变化、交付、提测、生产收口和恢复节点刷新相关证据，日常编码复用有效信息。父子集合按操作手册覆盖全部粗状态分页并按数值父 ID 筛选去重。

细状态缺字段时按操作手册做 MCP 精确筛选，核对 ident、数值身份与归属，不能从粗状态推断。结果不能唯一确定或连续读取冲突时，状态视为未知。跨仓 MCP 字段补齐不在本票维护范围。

状态更新不携带 description；正文维护先读再整体替换，标签和协作者按整体语义合并保留。已处目标态仅跳过无必要的状态写入，部署、验收与交接仍需核对。

结果未知先 MCP 回读，不重放评论、创建或合并。明确未执行的临时失败按渠道规则最多重试一次；参数、权限或枚举错误不盲目重试。未同步成功时置顶报告「⚠️ 工单状态未同步」、工单、目标名和 ID，只继续不依赖该结果的工作。

本票规则适配须分别记录规则读取路径、父子状态时序、MCP 参数与回读、Hook 真实子进程事件行为。静态检查通过不替代实际客户端读取或真实写入验收，未执行项标记 NOT_RUN。工程验证与清理证明按各自权威执行，不表示业务验收或工单完成。
