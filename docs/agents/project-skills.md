# 团队工程技能维护

`.agents/skills/<技能名>/` 是团队工程技能唯一的内容目录。每个技能包连同 `SKILL.md`、引用资料、脚本和客户端元数据一起提交 Git。`.claude/skills` 是 Git 跟踪的目录符号链接，目标固定为当前工作树内的 `../.agents/skills`。从 Agent 或 Claude 路径编辑文件，改动立即出现在另一入口。新成员检出仓库后，无需运行逐技能同步脚本。

Codex 和 Kimi Code 读取项目 `.agents/skills`。本机验证的 ZCode 0.16.9 与 Qoder 1.1.45 也扫描该目录；本仓不再配置它们的专用项目技能目录，以免同名技能重复注册。个人技能目录仍由成员管理；个人与项目同名时，客户端可能选择个人版本，需按实际来源检查。

在新的 Git 工作树根目录运行 `python3 scripts/check-project-skills.py`。该命令只读，检查权威技能包是否完整入库、Claude 链接是否保留且指向本工作树、其他项目入口是否有重复或过期副本，并列出个人同名技能的两个来源。新增技能时提交完整目录；删除技能时从权威目录删除并提交。检查报告错误后，先确认本地未知内容的归属，再修复 Git 文件或链接。检查不会复制或删除文件，也不会改个人配置。

Git 检出必须保留目录符号链接。若平台把 `.claude/skills` 检出为普通目录或文本文件，检查会失败；应使用支持符号链接的检出环境。某客户端确实不能读取目录引用时，可以为该客户端单独生成项目副本，但须先证明它不会同时扫描 `.agents/skills`，并为整个技能包的增删改和过期副本增加只读校验。本期五端没有启用这一回退方式。

客户端发现、实际来源、显式调用和未验证项分别记录在 [客户端验收记录](skill-client-validation.md)。文件树检查只能证明仓库交付，不能证明客户端调用成功。
