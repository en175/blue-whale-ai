# ADR-0129：工单状态权威与工程交付边界

日期：2026-10-18
状态：已接受
依据：IKL2X8-SPEC-20261012，工单评论 51546104

## 决策

修订 [ADR-0067](0067-issue-tracker-progressive-loading.md) 的单文件职责。继续使用渐进式加载，状态语义、有效枚举、事件条件、角色和例外统一维护在 [Agent 工作流手册](../agents/gitee-workflow-agent.md)。[工单操作手册](../agents/issue-tracker.md) 负责 MCP 参数、归属、认领、查询与回读；[集成工作流](../agents/integration-branch-workflow.md) 负责工程依赖及提交证明。根规则仅保留场景路由，人类说明、Hook 和初始化模板引用这些权威。

本地提交、工程验证、创建 PR 与合并 PR 记录工程交付并保持业务状态。同包前置在本票验证通过、受控合回且后续基线含所需成果后解锁；必须独立入 release 的外部基础设施继续先入线，验收或环境前置按声明证据判断。

子任务各自完成工程验证，默认随父业务验收。测试与生产流转以实际部署覆盖、对应人员结论和授权为准，逐票核对范围。工程 Resolve、代码承载证明与清理均不代表业务验收或工单完成。

## 影响

状态表只维护一份。既有 Git、验证、授权及 Gitee MCP 渠道入口保持原契约，不新增状态执行服务、锁或任务元数据。旧状态和旧缺陷标签只作历史识别，不批量改历史工单。
