# ADR-0030：生产进程通过 IRSA 读取、轮换并监控 KMS 凭据

- **状态**：Accepted
- **日期**：2026-07-15

生产运行单元通过官方 SDK 和各自的 IRSA 临时身份，直接读取 ADR-0020 为其授权的 KMS 凭据。凭据只保存在进程内存，不同步到 Kubernetes Secret，不注入环境变量，不写入文件、日志或转储。启动所必需的凭据缺失、无权读取或无法解密时，运行单元必须启动失败并触发告警，不能降级到共享凭据或静态兜底值。

凭据轮换采用新旧版本并存窗口。运行单元在后台读取新版本，建立新的连接池或供应商客户端并完成健康验证；验证成功后切换流量并释放旧客户端，验证失败则继续使用旧版本并告警。数据库和 Redis 使用 KMS 支持的托管自动轮换；第三方模型供应商 Token 依据供应商自身能力独立轮换，不假设 KMS 能修改第三方凭据。泄露、撤权或人员变更等安全事件不等待常规周期，必须立即轮换或吊销。

正常轮换采用分级周期：数据库和 Redis 凭据每 30 天由 KMS 托管轮换；Ark、图片与视频生成、短信等第三方 Token 每 90 天轮换，供应商支持双 Token 时无损切换，不支持时通过维护窗口和健康验证切换；KMS 主密钥材料启用平台自动轮转，周期为一年；IRSA 临时凭据由平台自动签发和续期，不设置人工轮换日历。安全负责人可以因风险缩短周期，延长周期必须通过新的架构决策。首次生产接入仍须先完成本 ADR 要求的泄露凭据即时轮换，不能从正常周期重新开始计算。

仓库中已经提交的 Ark API Key、短信服务 AK/SK、JWT 默认密钥以及数据库和 Redis 默认密码，无论当前是否仍在使用，一律按已泄露凭据处理。所有对应凭据必须先完成吊销或轮换，当前配置必须删除真实值和可用默认值；生产改为从 KMS 获取，本地示例只允许保留明确不可用的占位符。凭据轮换和当前配置清理是生产接入的阻断条件，不能以仓库私有、历史提交不可见或凭据可能已失效为理由豁免。

本 Issue 只负责旧值吊销、当前配置清理和范围内生产凭据接入，不改变 JWT 的签名算法、令牌格式或网关验签架构。全仓 Git 历史改写属于独立 P0 安全维护任务，不混入 IK10IG 的运行时代码提交，也不阻塞已经使用全新凭据的受控环境验证。

不采用 Kubernetes Secret、环境变量或文件卷作为生产凭据交付面，避免长期明文副本进入集群对象、Pod 描述、进程环境或节点文件系统。当前未确认火山引擎提供满足本项目要求的 VKE Secrets Store CSI 官方集成，因此不以 CSI 为生产前提；后续若出现经过验证的官方集成，替换本决策前仍需证明其最小权限、内存暴露、轮换和故障语义不弱于直接 SDK 方案。

所有生产 `GetSecretValue`、凭据轮换与删除及 KMS 授权变更进入火山引擎操作审计并投递到独立 TLS Topic；运行单元同时产生不含敏感值的即时指标，只记录运行单元、IRSA 角色、资源标识摘要、Action、结果、延迟和凭据版本。非预期角色、ServiceAccount、namespace 或来源访问，跨运行单元路径访问，未经批准的生产写操作，切换完成 24 小时后读取旧版本，读取频率连续 5 分钟超过历史基线 3 倍，以及审计投递连续 5 分钟无心跳，都必须告警。

单纯统计异常只告警调查，不自动吊销角色；确认错误主体或跨边界访问后，立即隔离对应工作负载、吊销其身份、轮换相关凭据并建立安全事件记录。告警触发、确认、处置和恢复均写入 AuditRecord，受控环境必须验证每类规则且证明告警内容不泄露 Secret。
