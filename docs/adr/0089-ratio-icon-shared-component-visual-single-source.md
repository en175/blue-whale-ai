# 比例示意图标视觉同源：三处收敛共享组件、统一公式画法、严格比例不设下限

- **状态**：Accepted
- **日期**：2026-09-16
- **决策者**：项目团队（经 grill 会话两轮确认，缺陷单 `IKGBTV`）
- **关联工单**：`IKGBTV`（生成面板宽高比示意图标与真实比例不符）

## 背景

产品内曾有三处各自独立的比例示意图标实现：

1. 画布图片面板（`ImageDialog/index.tsx`）：公式法，竖屏分支宽度公式写反（`(h / w)` 应为 `(w / h)`），所有竖屏比例被画成横扁矩形且突破 16px 设计上限（1:3 实际渲染 48×16，把按钮撑宽）。
2. 画布视频/音频面板（`BottomDialog/index.tsx`）：公式法，实现正确。
3. 首页输入框（`ChatBox/index.tsx`）：查表法写死 8 种比例，模型能力接口返回的表外比例（GPT Image 2 的 9:21、2:1、1:2、3:1、1:3，Banana 2 的 4:5、5:4）兜底渲染成正方形，同样失真。

三份实现各自漂移，同一概念在三处有三种正确性水平，修一处管不了另外两处。

## 决策

1. **三处收敛为一个共享组件** `web/src/components/RatioIcon/`，一处定义、三处引用（接入点共四处：ImageDialog 弹层、BottomDialog 弹层、ChatBox 视频比例下拉、ChatBox 图片比例下拉）。不允许再出现第二份比例图标实现。
2. **统一公式画法**：最长边固定，另一条边按真实比例等比缩放（`Math.round((短边 / 长边) * size)`）；废除首页查表法，任何模型能力接口返回的比例值都按真实比例渲染。
3. **尺寸分场景保留**：画布 16px、首页 22px，组件接收 `size` 参数（默认 16），各场景视觉大小与改动前一致。
4. **严格按比例渲染，不设最小边下限**。极端比例（1:3 渲染为 5×16）照实呈现，不为「好看」牺牲真实性。
5. **画法统一为 CSS 矩形**（1.5px 描边、3px 圆角、`currentColor`），首页的 SVG 写法退役，切到同一画法。
6. **非法或缺失的比例值兜底渲染正方形**（沿用首页现有兜底语义），包括空串、非数字、零或负数边、非 `a:b` 两段格式。

## 被否方案

- **只修 ImageDialog 那一行**：留下三处漂移的定时炸弹，ChatBox 表外比例失真仍在。
- **保留查表法并扩表**：模型能力接口驱动比例选项，表永远追不上新模型，表外兜底必然失真。
- **设最小边下限**（如最小 8px）：1:3、9:21 等极端比例会被画胖，与「示意图标须忠实于真实比例」的目的冲突。

## 后果

- 比例图标的正确性由共享组件一处保证，参数化测试覆盖 15 种比例 + 非法值兜底 + 双尺寸；四个接入点各留一条用户可感知断言（首页以源码断言锁定引用与 22px 传参，因 ChatBox 无整体渲染测试接缝）。
- 下发给模型的真实比例参数始终正确，本决策只涉及示意图标渲染，不影响生成行为。
- 新术语「比例示意图标（RatioIcon）」已入 `CONTEXT.md`。
