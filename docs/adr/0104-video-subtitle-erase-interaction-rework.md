# 视频智能去字幕交互推翻重做：模式前置到入口下拉、会话内开关废除、编辑态下方单条化

!756（IKGZ7V）上线的实现是「单按钮直启 + 会话内『全画面文字』开关 + 上工具条/下发送条双条」，一个发送钮靠「有无拉框 + 开关」统一推导智能/框选两种语义；Kim 以四张截图定案推翻（2026-09-19，两轮 10 问拍板）：模式选择前置到入口——「智能去字幕 ▾」下拉触发钮（交互同图片「高清 ▾」家族：悬停自动展开、120ms 移出延迟、Esc/点外关闭；固定文案不做最近工具记忆；菜单两项纯文字），选「智能去字幕」进智能模式（视频下方单条「X | 智能擦除 ⚡0 | ↑」，零框选工具、无框直发）、选「框选去字幕」进框选模式（视频下方单条「X | 框选擦除 ？ | 框选/撤销/重做/重置 | ⚡0 | ↑」，必须拉框才能发送，重置=清空全部框且可撤销，框上限 20 沿用）；两模式不提供就地互切，换模式=X 退出后从菜单重选。布局从双条统一为视频下方单条，「音视频分离」编辑态同步单条化（X | 音视频分离 | 分离格式下拉 | ⚡0 | ↑，发送条信息同款 ⚡0 徽标）。「全画面文字」开关废除：detect_mode 两模式固定 `subtitle_smart`，`text_full` 参数契约保留但本期无 UI 入口；「输出最高 1080P」挪到发送钮悬停说明。范围仅智能去字幕（入口+编辑态）与音视频分离入口/编辑态形态对齐，截图其余按钮（高清、片段重拍、逐帧拉片、主体消除、截取当前帧）不实施；后端契约零改动（job type、detect_mode 枚举、boxes 字段均不变）。

## Considered Options

- 保留会话内开关、只改布局（最小改动）：开关把「模式」与「检测范围」两个维度耦合在一个开关加有无框上，是交互混乱的根源，Kim 明确推翻，否决。
- 框选模式无框发送回落智能语义（沿用现状）：模式语义纯粹化拍板优先——要智能语义就走「智能去字幕」入口，无框时发送钮置灰（title 提示先拉框），否决。
- 智能模式固定 `text_full`（全画面检测）：智能=火山默认字幕范围（画面下半 50% 且水平居中），全画面检测本期不暴露入口，否决。
- 下拉菜单将来加第三项「全画面去字幕」：本期两问两答，不做预留设计；`text_full` 契约保留即为将来留了口子，否决。

## Consequences

- 本 ADR 推翻规格 `docs/specs/2026-09-19-video-subtitle-erase-mediakit.md` 与 !756 上线实现中的交互形态章节（入口直启、开关、双条、无框回落智能语义）；已上线前端返工，后端契约与 worker 零改动。
- 框选模式从「可选增强」变为「必框模式」：发送前置条件从恒可发变为有框才可发，占位卡建卡时机、退出丢弃口径随之只服务两条更窄的路径。
- 重置作为可撤销操作进入 undo/redo 栈：undo/redo 语义从「逐框增删」扩展为「逐框增删+整批清空」。
- 音视频分离在途工单（IKH28 系列）正文写的「上方仅 X + 下方发送条」双条形态与「本期免费」标注随之失效，规格落盘/工单修订时以本 ADR 单条化+⚡0 徽标口径为准。
- 「全画面文字开关」词条从 CONTEXT.md 移除；擦顶部字幕的途径（`text_full`）本期无 UI 入口，属已知能力回退，产品再拍板时以新入口形式回归。
