# ADR-0022：ContentReview 全量决策但按证据择路

- **状态**：Accepted
- **日期**：2026-07-15

除 ADR-0023 排除的普通用户文字消息和提示词外，Blue-Whale 要求当前产品策略纳入审核范围的输入，以及每份即将向 User 展示的输出，都由 Java Product API 形成 ContentReview 决定；这不等于人工逐条审批，也不要求每份受审内容都产生一次新的外部审核调用。首版不设置人工审核主链路，自动拒绝后由 User 修改内容重新提交。

Java Product API 按确定性策略选择 ReviewEvidence：内容摘要、模态、审核载荷和策略版本均匹配时复用既有明确通过决定；生成供应商提供可验证且满足当前产品策略的审核结果时，可以作为输出证据；证据缺失、过期、无法验证或不足以覆盖当前策略时，调用 ADR-0021 选定的大模型应用防火墙。无论证据来源如何，供应商都不能直接放行，最终决定必须由产品控制面归一化并持久化。

每个生成图片或视频在供应商返回后仍只是待产品接纳的输出结果。供应商证据覆盖最终媒体内容且足以满足当前产品策略时，Java Product API 可以据此形成明确通过决定，不再产生第二次外部审核调用；否则只对该结果调用一次大模型应用防火墙。明确通过后才创建 Asset；在此以前不得创建可见 Card 或 NodeItem，不得签发下载 URL，也不得把结果作为后续输入。

相同受审内容在策略不变时避免重复调用，以降低审核成本、延迟和吞吐压力；普通新内容在策略版本、内容或上下文变化、证据不完整时重新审核。ADR-0024 已接纳的不可变历史 Asset 是例外：后续使用不重复送审，编辑或派生形成的新 Asset 才按当时策略审核。任何受审路径无法形成明确通过决定时仍然 fail closed。该取舍保留 ADR-0018 的产品权威，同时避免把审核服务变成每次使用既有内容时都重复触发的瓶颈。
