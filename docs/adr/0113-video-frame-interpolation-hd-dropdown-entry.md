# 视频插帧：高清 ▾ 下拉第二项入口，HD 式草稿卡面板三档帧率

视频素材卡新增「插帧」工具（火山 MediaKit `video-frame-interpolation` 异步端点，出站仅 `video_url` 与 `fps` 两键；2026-09-21，两轮九问拍板）。决定：视频卡工具条首位的「高清」单按钮升级为「高清 ▾」悬停下拉，首项「HD 高清」直启原链路零变化，次项「插帧」为新入口；点插帧为源视频在右侧建插帧草稿卡并跟随弹出极简面板（帧率三档 + 本期免费 + 发送），发送后草稿卡原地转生成中，成功回填为普通成品视频卡并拉来源连线，失败原参数重试。链路骨架复用 MediaKit 异步家族（submit + 轮询 + 即收即转存 TOS 解 24 小时过期 + 心跳续租 + per-job 凭证冻结）。

**入口收纳进「高清 ▾」下拉，不做独立单按钮**。视频卡工具条已九钮（含已拍板未实施的智能抠像 ▾），继续加单按钮会持续膨胀；插帧与 HD 高清同属画质增强门类（只提帧率、分辨率码率跟随原片，官方文档明示要提清晰度须配合画质增强），归拢进同一下拉符合用户分类直觉。下拉形态照抄「智能去字幕 ▾」「音视频分离 ▾」家族（悬停展开、移出 120ms 延迟关、Esc 与点外立即关、点击触发钮直启首项、同构不共享独立组件）。与图片卡画质五工具横排常显（[ADR-0107](0107-quality-tool-family-inline.md)）方向相反但不冲突：该决策拍板时明确范围仅图片卡，视频卡下拉收纳是另一支。

**交互形态走 HD 式草稿卡加面板，不走编辑态也不免面板直发**。帧率是插帧唯一参数且 30/60/120 档间差异明显，用户必须能选档；HD 的草稿卡加极简面板骨架可整体复刻（切档即时写卡持久化、点卡与重新编辑重开面板、生成中与提交中只读）。编辑态是为去字幕、音视频分离那类空间选择功能设计的会话形态，插帧没有可编辑的空间对象；免面板直发等于替用户锁定帧率，否决。

**门槛分三层，插帧项不做任何额外前置**。触发钮整钮置灰仅因视频未关联资产（两功能公共交集，悬停仍展开菜单看两项说明，家族口径）；「HD 高清」项保留原分辨率上下限（长边 1920、短边 1080、短边下限 360），从整钮置灰降为菜单项置灰；「插帧」项无额外门槛，官方对该端点无时长与分辨率限制。仓内全链无 fps 元数据（库表、契约、节点 data 均无），源帧率前端不可知，官方「目标帧率不超过原片 4 倍」的建议无法前置判定，且官方口径为建议非硬限，越界场景由任务失败文案兜底（「视频插帧失败，请重试」）。

**触发钮直启遇高清项置灰时点击无操作**。两项门槛不同源后出现新场景：源视频超分辨率上限时高清项置灰而插帧项可用。触发钮文字是「高清」，直启就必须是高清，被拦时点击不派发、title 提示原因，悬停展开照常，用户从菜单选插帧。不直启首个可用项，点了「高清」字样却跑插帧是语义错位。

**帧率三档 30/60/120，默认 60**。Seedance 生成视频 24fps 提到 60 是官方文档点名的主场景（2.5 倍）；30 档留给低帧率上传视频；120 满足高刷诉求（对 24fps 源是 5 倍，超出官方 4 倍建议，建议非硬限故保留档位）。三档分段与 HD 面板 1080P/2K/4K 视觉结构一致。

**插帧卡名动态标注所选档，成品卡不做链式置灰**。草稿卡名「插帧 · 60fps」随切档即时更新（所见即所得，场景切分占位卡先例），占位文案「配置参数生成插帧视频」。生成成功回填后为普通成品视频卡，不再记插帧身份；成品卡可再次发起插帧（60 的卡提到 120 为合法 2 倍）与 HD 高清（分辨率未动过）。不做「fps 已达 120 置灰」的链式收紧：普通源卡帧率本就不可知全放行，产物卡单独收紧会造成两套口径，且需为此新增 fps 落库落卡元数据链路，UI 最高档即 120，到顶后用户自然无从再选更有意义的档。

## Considered Options

- **插帧做独立单按钮（不动高清）**：工具条继续膨胀，画质类工具失去归拢，否决。
- **场景切分式编辑态**：插帧无空间选择对象，单条发送条承载一个三档分段是空转，否决。
- **免面板按默认档直发**：替用户锁定唯一参数，档间差异不可见，否决。
- **帧率仅 60 单档或 60/120 两档**：低帧率上传视频与高刷诉求覆盖不足，否决。
- **4 倍建议前置拦截**：源帧率前端不可知，无法实现；官方为建议非硬限，否决。
- **触发钮直启首个可用项**：点「高清」却启动插帧，语义错位，否决。
- **产物 fps 达 120 链式置灰**：为单一场景新增 fps 元数据链路并造两套放行口径，否决。
- **卡名固定「插帧」不标档**（HD 卡名固定「HD」式）：帧率是唯一参数，卡名不带档须开面板才知道会发什么，信息量不足，否决。

## Consequences

- 「HD 高清」入口从单按钮重构为下拉组件（Toolbar.tsx 高清分支改造，新建独立菜单组件，同构不共享 [ADR-0101](0101-quality-tool-family-interaction-alignment.md)）；其分辨率门槛从整钮降为菜单项，触发钮整钮门槛收窄为未关联资产，Toolbar 既有置灰断言与测试需同步适配。
- 视频卡工具条终态为「高清 ▾ / 智能去字幕 ▾ / 音视频分离 ▾ / 场景切分 / 智能抠像 ▾（[ADR-0112](0112-video-smart-matting-entry-dropdown-edit-session.md) 已拍板待实施）/ 分隔线 / 详情 / 下载 / @」，屏幕恒定口径（[ADR-0099](0099-canvas-card-toolbars-screen-pinned.md)）下须复核视口钳制常量。
- 插帧面板随草稿卡加入生成面板会话门（打开期间悬浮工具条整条不渲染，同 HD 面板全局会话门口径），关闭与领土豁免接 dismissAllGenPanels 体系。
- 后端与 worker 同构 MediaKit 异步链（契约先行 video-frame-interpolation 章节，worker-java 新 gateway client 与 processor，即收即转存 TOS，心跳续租防长任务孤儿重投）；对客网关路径与配零价为上线前置独立票，同 HD、去字幕、场景切分先例（IKH67T、IKH3VI、IKH8BK、IKHA31）。
- 契约与代码层命名对齐火山命名（video-frame-interpolation，fps 直传整型）；本仓全链不新增 fps 元数据字段。
- 进规格阶段须补抓该端点的参数级 API 参考页（错误码、回调字段、时长与文件大小上限的权威表述），本次依据的开发指南 PDF 只含 video_url、fps 两个参数与结果四字段（video_url、duration、resolution、fps）。
- [CONTEXT.md](../CONTEXT.md) 词条同步（插帧、帧率档、插帧卡、插帧面板，并修订「HD 高清」词条的入口形态与门槛分层）；原型归档 `web/prototypes/video-frame-interpolation.prototype.html`（单文件、双击即开）。
