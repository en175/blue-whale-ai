# 代码任务先同步本地发布线

- 状态：已采纳
- 日期：2026-09-24
- 关联工单：IKIBRZ

## 背景

产品代码先进入当期 `release/*`，完成整合与验证后才进入 `master`。现有任务入口却从本地 `master` 建分支，验证、提交提醒和清理也多处默认 `origin/master`。另一种偏差发生在本地与远端发布线之间：任一方新增提交后，直接读取旧工作区会让调查和开发使用过时代码。

## 决策

每期只有一条当前发布线。本地 `master` 与 `origin/master` 保持相同提交，不承载未发布的产品提交。Agent 日常打开当前发布线的本地目录；任何依赖仓库代码的调查、调试或开发，在读取代码前都先抓取同名远端发布线，并使本地已提交历史包含本次抓取的远端提交。本地领先时保留本地提交，远端领先时快进本地，双方分叉且无冲突时将远端合入本地。遇到合并冲突或同步会影响未提交文件时停止，并保留原状态。无法读取远端时，不得宣称本地代码是最新版本。

同步完成后，Agent 核对实际工作目录的代码索引。写入任务从同步后的本地发布线精确提交建立独立 task worktree，并记录目标分支与起点提交。未提交文件可以用于注明本机状态的只读分析，但不会进入新任务的共同基线。发布任务 PR 前，入口须证明任务起点已进入远端目标发布线，避免将其他本地领先提交带入当前 PR。

标准入口识别远端新批次候选，并与团队已启用的当前发布线核对。出现新候选时，Agent 提醒发布负责人；负责人一次授权启用后，新任务自动使用新批次。仅凭分支日期不能完成切换。进行中的任务与 PR 保留原状态；Agent 集中列出待迁移项，由发布负责人一次决定去向。发布线的创建入口应拒绝在旧批次尚未收口时再开新批次。同步由标准入口执行，Hook 只拦截绕过和危险操作。

## 取舍与迁移

采纳 IKIBRZ 的文档过渡方案、批次基线开工方案与基线元数据方案；不通过加快 `release` 合入 `master` 来掩盖工具偏差。开工入口、提交安全判断、验证、PR 发布、巡检与清理须使用同一目标分支和起点提交。尤其不能只给开工入口添加参数，却保留以 `master` 判断 `--amend` 是否安全的旧逻辑。

本决策替代 ADR-0010 中本地 `master` 充当未发布集成区的规则，以及 ADR-0025 中散文文档直写本地 `master` 的例外。不能以此为由手动绕过开工入口。现有本地 `master` 领先提交、旧批次分支及未提交文件须分别核对和保全，不自动重置或删除。
