# ADR-0081：Canvas 滚轮默认平移，缩放交给平台原生修饰键与触控板捏合

- **状态**：Accepted
- **日期**：2026-09-06
- **决策者**：钟金俊（经 `/grilling` 会话共同得出）
- **关联工单**：IKDKH1

## 背景

Canvas（无限画布工作台）基于 React Flow。库默认 `zoomOnScroll=true` / `panOnScroll=false`，即无修饰键滚轮直接缩放视口：用户想滚动浏览画布却改变了缩放级别，丢失当前比例与位置，需要反复缩放找回视野。该行为与 Figma、tldraw 等主流画布产品相反，误操作率高。

本仓原实现把滚轮平移挂在「按住空格」这一条件上（`panOnScroll={spaceHeld}`），因此不按空格时滚轮落回库默认的缩放。

## 决策

1. **滚轮=平移，修饰键+滚轮=缩放**：实现为 React Flow 两个 props——`panOnScroll` 常开、`zoomOnScroll={false}`。不写自定义滚轮监听。
2. **修饰键用库的平台原生默认值**（`zoomActivationKeyCode`：macOS=Meta/Cmd，其他平台=Control），刻意不显式声明。库默认即业界约定，写死反而会在跨平台时出错。
3. **`zoomOnPinch` 保持默认开启**：macOS 触控板捏合照常缩放（浏览器把捏合以 `ctrlKey=true` 的滚轮事件上报，库走捏合路径）。因此 Mac 上 Ctrl+滚轮同样缩放，只是灵敏度高 10 倍——这是库为触控板捏合刻意设的系数，不是缺陷。
4. **Windows 的 Shift+滚轮水平平移**由库内置（`!isMacOs() && shiftKey`），不额外实现。
5. **既有入口全部不变**：空格+拖拽平移、右下角缩放按钮、双击空白画布放大；视口持久化契约 `{x, y, zoom}` 与服务端保存逻辑不动。空格+滚轮平移退化为冗余但无害，保留不删。
6. **不提供「滚轮=缩放」偏好开关**，不新增键盘缩放快捷键。

## Considered Options

| 方案 | 取舍 |
| --- | --- |
| **库内置 props（采纳）** | 两行配置，锚点/捏合/preventDefault/防抖全部由库维护；与 Figma、tldraw 一致 |
| 自写滚轮监听 + 自定义缩放 | 需自行实现锚点缩放、捏合、事件拦截与防抖，重复造库已有能力 |
| 固定用 Ctrl（不分平台） | macOS 用户失去 Cmd 肌肉记忆；且 Mac 上 Ctrl 已被触控板捏合语义占用 |
| 提供滚轮行为偏好开关 | 增加配置面与测试面，无用户诉求 |

## Consequences

- 库对「启用了滚轮平移」的视口结束事件（`onMoveEnd`）固定加 150ms 防抖，拖拽平移的视口回调随之延迟；相关测试必须用等待断言，不能同步断言。
- e2e 里缩放必须带修饰键。Ctrl+滚轮走捏合路径，macOS 灵敏度高 10 倍，测试辅助函数按平台归一 `deltaY`，才能保证同一缩放倍率。
- 库的 `preventScrolling` 默认在画布区域拦截滚轮默认行为，Ctrl+滚轮缩放不会连带触发浏览器整页缩放。
- 节点内 `nowheel` 区域（文本便签正文、资产卡）滚轮既不缩放也不平移，保持内部阅读滚动语义。
