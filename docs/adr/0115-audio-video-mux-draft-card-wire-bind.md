# 音视频合成：草稿卡会话形态与拖线绑定，音频工具栏首个跨媒体工具的形态分叉

画布音频成品卡工具条已点亮的三个功能（截取、调速、混合）全部是「源卡下方单条发送条」编辑态。音视频合成（第四钮）是家族里第一个**双输入**（固定音频源 + 一个视频）且**跨媒体产出**（音频卡会话产出视频卡）的工具。2026-09-24 两轮拍板：放弃发送条形态，改用「点按钮即从源音频卡拉出音视频合成草稿卡并默认连音频输入线，参数面板跟随」（Kim 提议）；视频绑定主交互在三方案原型评审中选定**拖线绑定**（从视频卡右侧加号拖线到草稿卡吸附），素材库选择作次级入口（选中绑定不拉线），本期不支持本地上传。

**判定依据是双输入关系必须在画布上可见。** 发送条形态下视频输入在发送前完全藏在浮层里，而音视频合成的任务身份恰恰是「那条音频 + 那个视频」，草稿卡加两条输入线把这个关系直接画在画布上，这是画布编排的核心表达力。产物是视频卡，草稿卡「生成成功后结果原地回填本卡」直接复用 HD 高清、插帧的已验证口径，卡片身份、回填语义、失败重试都有先例。参数面板也给了「原声处理、时长对齐」两组参数容身之处，胶囊发送条塞下视频槽加两组分段会拥挤。

**形态分叉的界限规则（供转码钮及后续家族参考）**：输入少、跨媒体、产物形态不同的走草稿卡+面板；输入多（混合最多 100 段，拉 100 根线不现实）或同媒体进同媒体出的走单条发送条。两种形态在音频工具栏上并存不视为不一致。

**接受的代价**：点按钮即建卡，误点会留下空草稿卡需手动删。HD、插帧已接受同一代价（草稿卡是持久工作对象，不自动清理），音视频合成沿用。

## Considered Options

- **单条发送条（截取/混合家族形态）**：发送前视频输入不可见，双输入关系丢失；条内塞视频槽加两组参数拥挤；产物是视频卡但发送条家族的占位卡全写死音频类型，仍要新建视频型承载。否决。
- **草稿卡 + 三页签浮层选材（原型方案甲）**：混合同款浮层对「只选一个视频」过重（三页签、候选清单）；输入选择过程仍藏在浮层里。原型评审否决。
- **草稿卡 + 画布点选模式（原型方案乙）**：点「选择视频」进点选模式在画布上点卡绑定，接近拖线的直观，但多一个模态状态（进入/退出点选模式），素材库入口仍要浮层。原型评审否决。
- **草稿卡 + 拖线绑定（原型方案丙，拍板）**：拖线是画布原生手势，绑定动作与输入连线一次完成，「落到草稿卡 = 绑定」的语义自解释；代价是连线落点判定要按目标卡身份分流（落合成草稿卡建 `origin=audio-video-mux` 绑定边，不落普通参考线）。
- **本地上传视频作第三来源**：外部视频需先自行入素材库，多一步但口径更窄；本期不做，拍板。

## Consequences

- 工具条 `compose` 钮从 `audioToolItems` 占位数组移出单独渲染（调速钮先例），门槛仅源音频 URL 缺失；`Toolbar.test.tsx` 的 `placeholderIds` 仅剩 `transcode`。
- `toolSessionCoordinator` 新增第 13 种会话 `audioVideoMux`，三处数组与 `editSessionActive` 派生同步；面板打开期间媒体卡悬浮工具条整条不渲染（HD/插帧全局会话门口径），发送后恢复。
- 连线落点语义分叉：落到未绑定/绑定中的合成草稿卡是绑定动作，落其他卡维持普通参考连线。
- 音频卡会话首次产出视频卡：占位卡从创建起即视频型（去字幕 `createImageDraftCard` + `mediaType:'video'` 先例），终态走通用回填分支按 `asset.type` 翻 `mediaType`。
- `origin=audio-video-mux` 语义边从音频参考推导与 @ 编号排除（音频混合同款坑位）。
- 原型两版本留存于本地分支 `chore/音视频合成交互原型`（三方案对比 `edf89a1c0`、定稿 `521e32989`），主分支只留本决策与规格。
