# 音频成品卡横矩形改版：工具条五功能置灰占位，功能交互各自另立任务

画布音频成品卡此前是 280×280 固定方形卡（MediaNode audio 分支），工具条只有「详情」「下载」两钮。2026-09-20 三轮拍板：参考外部产品的成品音频卡设计做样式改版，卡片改横矩形（宽约为高 2 倍，480×240 起步，原型阶段微调），波形竖条加密；工具条扩展为「截取、调速、混合、音视频合成、转码」五个功能钮加最右「下载」，五钮本期全部置灰占位（悬停提示「即将上线」），各功能的交互与实装由后续独立任务逐个定义，不随本次样式改版落地（「转码」钮已于 2026-09-25 撤除，见文末修正一）。

**判定依据是信息架构先行。** 五个功能（我方规划集，与参考截图的截取/变速/智能切分/自定义切分有差异）每个都涉及独立的前端交互与处理能力，混在样式改版里落地会让一次交付同时背视觉与五条功能链路的验收。先把工具条结构定死（按钮集、顺序、置灰占位形态），后续每个功能任务来时逐个点亮，样式改版本身收窄为纯视觉变更，验收面清晰。

**家族一致性守两条。** 文件名留卡外顶部标题行（参考截图放在卡内，为守图片卡、视频卡三卡一致否决）；工具条沿用「唯一选中时悬浮钉屏幕」机制（参考截图是常驻卡内栏，否决），按钮形态沿用画质家族拍板的图标加文字横排（ADR-0107）。详情钮随改版移除（音频卡信息稀薄，右键菜单与双击重命名已覆盖），参考截图右上角的替换入口第一版不做。

## Considered Options

- **功能与样式一次做完**：五个功能的交互在本轮一起定义一起实装。每条功能链路独立可验收，捆在一次交付里验收面失控，且我方功能集与参考截图有差异、需逐个单独设计，否决。
- **第一版只放下载，功能按钮随任务逐个加**：工具条始终短、无置灰占位噪音，但用户与团队看不到目标信息架构，参考截图的完整工具栏观感无从确认，否决（拍板选置灰占位）。
- **卡内标题行**（参考截图形态）：破坏三卡卡外标题行的家族一致，否决。
- **常驻卡内工具栏**（参考截图形态）：画布有缩放，常驻栏随卡缩放可读性差；钉屏幕工具条已解决缩放跟随（ADR-0099），否决。
- **纯图标按钮**：可压缩工具条宽度，但违背画质家族已拍板的图标加文字横排口径（ADR-0107），否决。
- **「裁剪」作按钮文案**：音视频主流工具用词，但专业命名「截取」与后续任务命名对齐，拍板用「截取」。

## Consequences

- 音频卡尺寸规则从「恒 280×280 方形」改为横矩形，`mediaContentSize` 音频分支、AudioPlayer 布局、波形条数三处联动变更；尺寸为渲染时计算，存量画布音频卡无迁移。
- 工具条分流规则（toolbarVisibility）音频分支从「详情、下载」改为「截取、调速、混合、音视频合成、转码（均置灰占位）、分隔线、下载」；置灰占位须建立「功能未实装钮」的置灰加悬停提示先例，后续图片卡、视频卡的未上线功能可复用。
- 五个功能（截取、调速、混合、音视频合成、转码）各自的交互设计、契约与实装均为后续独立任务，本 ADR 只锁定按钮占位与顺序，不锁定任何功能交互细节。
- 波形加密只改观感，解码与兜底链路不动。
- [CONTEXT.md](../CONTEXT.md) 词条同步（音频成品卡、音频波形、音频卡工具条）。

## 修正一（2026-09-25）：撤除「转码」占位钮

**触发**：需求方确认不再提供画布音频转码功能，原五钮中的「转码」置灰占位钮连同入口一并删除，音频卡工具条功能钮收敛为四钮（截取、调速、混合、音视频合成）。

**决策**：`Toolbar.tsx` 的 `audioToolItems` 占位数组删除 `transcode` 项与 `Repeat` 图标引用；按钮顺序、其余钮的占位与点亮状态、详情钮退役与 @ 隐藏口径均不变。本 ADR 正文与 Consequences 中「五钮」的表述以本修正为准；CONTEXT.md「音频卡工具条」词条同步。
