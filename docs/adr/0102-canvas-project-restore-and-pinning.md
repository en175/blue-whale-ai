# 画布项目恢复与置顶：恢复落点三级规则 + 后端按账号记忆上次打开 + 置顶与恢复解耦

现状 `/canvas` 无 `?project=` 参数进入时（登录后进入、侧边栏「画布」入口、直接访问），前端取项目列表第一项兜底（`pickCanvasIdAfterLoad`），而后端 `listByOwner` 按 `gmt_create desc` 排序，行为等于「恒开最新创建的项目」。本 ADR 确立三项决策。其一，**上次打开的画布按账号记在后端**：project 表新增 `last_opened_at` 列，用户进入一张画布即更新该列（打开即记，write-through），不依赖退出时机；记忆跨浏览器、跨设备、清浏览器缓存均不丢。其二，**恢复落点三级规则**：地址栏 `?project=` 显式指定 > 上次打开的画布 > 最新创建的项目（现状兜底保留）；上级失效自动落到下级，不弹提示。其三，**置顶与恢复解耦**：project 表另增 `pinned_at` 列承载置顶（多选、无上限、再点取消，组内按置顶时间倒序），置顶项目在项目列表页与画布项目下拉菜单排最前成组展示并带图钉标记，但置顶不改变恢复落点（恢复落点仍由上次打开的画布决定）。置顶入口两处：画布顶栏项目下拉悬停项目项时删除按钮左侧出现置顶按钮；Projects 页卡片 More 菜单新增「置顶 / 取消置顶」项（与重命名、删除并列，不改菜单结构）。列表排序口径为「置顶组（pinned_at desc）在前、其余 gmt_create desc 在后」，Projects 页与画布项目下拉共用；Projects 页其余项目的展示顺序保持创建时间倒序不变。

## Considered Options

- localStorage 记上次画布 id：零后端改动，但不跨浏览器、不跨设备、清缓存即丢，覆盖不了「退出电脑再回来」「换设备登录」场景；且旧的 localStorage 项目方案（bw-canvas-active 一族）已随项目迁后端退役，不应复活，否决。
- 不加存储，把兜底排序改成 `gmt_modified desc`（最近编辑优先）：打开一张画布只看不动内容不更新 gmt_modified，「上次看过但没编辑」的画布记不住，语义是「最近编辑」而非「最近打开」，错位，否决。
- 置顶参与恢复落点（存在置顶项目时优先开置顶项）：会打断「从哪退出回哪」的连续工作预期（上次在 B 工作、置顶了 A，回来落在 A）；置顶的产品价值在列表快速定位常用项目，与恢复落点解耦，否决。
- 退出/页面卸载时机写入记忆：beforeunload 在移动端、浏览器崩溃、直接杀进程时不触发，会丢记录；打开即记（write-through）永不丢且实现简单，否决退出时记。
- 只在单处放置顶入口（仅画布下拉或仅 Projects 页）：两页都能管理项目，单侧入口造成功能盲区；两处都有，各自沿用该页现有交互形态（画布下拉是悬停直接按钮，Projects 页是 More 菜单项），否决单侧。
- 置顶组内按创建时间或最近打开排序：置顶是用户手动动作，按置顶时间倒序（最近置顶在前）最贴合手动意图（飞书云文档同款），否决其他组内排序。

## Consequences

- project 表新增 `last_opened_at`、`pinned_at` 两列及配套更新与查询；两列的写入不动 `gmt_modified`（打开/置顶不是内容编辑，不干扰既有创建时间排序语义与快照乐观锁版本）。
- 项目列表接口排序口径变为「置顶组在前（pinned_at desc）、其余 gmt_create desc」：Projects 页（分页加载）与画布顶栏项目下拉共用同一口径；分页边界按新排序实现。
- 画布内切换项目（currentId 变化）触发一次轻量 last_opened_at 更新调用，仅在项目切换时发生，频率低；失败静默降级（恢复落点退回兜底链），不阻塞画布使用。
- 「无参数进入画布页」的落点从「列表第一项」改为「三级规则取值」：`pickCanvasIdAfterLoad` 的兜底语义从「取首项」扩展为「取上次打开（存在于列表时），否则首项」，既有 `?project=` 合法性校验行为不变。
- 置顶是账号级产品事实：跨设备一致，与浏览器本地状态无关；删除项目时其置顶状态随项目一并消失，无独立清理需求。
