# 画质工具离开下拉：五工具在工具条上横排，最近工具记忆退役

图片素材卡悬浮工具条的五个画质工具（高清 / 扩图 / 裁切 / 擦除 / 抠图）从「高清 ▾」下拉里提取出来，作为五个并列按钮（图标 + 文字）直接排在工具条上，顺序维持高清 / 扩图 / 裁切 / 擦除 / 抠图不变（2026-09-20，六问拍板 + 原型实测确认）。判定依据是**可见性**：「高清 ▾」在当前工具栏构成下只露一个触发钮，用户必须展开才知道有五个工具，而工具条本身因生成类按钮撤除（[ADR-0106](0106-canvas-card-toolbar-generation-buttons-removed.md)）已显得空。横排后五个工具一眼可见、一击直达。

**形态与实测宽度**。按钮复用既有 `.toolBtn`（透明底、hover 提亮、置灰 `aria-disabled`），整条工具条宽度由 227px 增至 473px（浏览器实测，非估算）。代价是工具条会宽于部分卡片：工具条钉屏幕层、任何缩放级别屏幕尺寸恒定（[ADR-0099](0099-canvas-card-toolbars-screen-pinned.md)），而卡片屏幕宽 = 画布内尺寸 × 缩放，竖图卡（280 画布内宽）在 100% 缩放时为 280px（工具条 1.69 倍）、50% 缩放时 140px（3.38 倍），横图卡（498 画布内宽）在 100% 缩放时 498px（0.95 倍，反而宽于工具条）。这是本次唯一真实的取舍：**接受工具条宽于卡片，换取五工具常显**。视口钳制的估半宽常量随之上调（`FOLLOW_ABOVE_HALF_WIDTH` 200 → 250，覆盖 473px 的真实半宽），保证卡片贴屏幕边缘时工具条不被裁。

**连带退役**。工具条上不再有单触发钮，「触发钮显示最近使用工具」的整套语义失去载体，一并撤除：`recentQualityTool.ts` 纯逻辑模块（读写订阅三入口）、localStorage 键 `bw-recent-quality-tool`、悬浮自动展开菜单、点击触发钮直启所显示工具的路径、以及「所显示工具不可用时整钮置灰仍可 hover 展开改选」的口径全部退役（[ADR-0101](0101-quality-tool-family-interaction-alignment.md) 第二条被本 ADR 取代；同 ADR 第一条「工具会话模态隐藏 chrome」与第三条「发送钮统一 Dock 主发送钮样式」继续有效）。用户浏览器中留存的 `bw-recent-quality-tool` 旧值不再被读取，无害遗留，不主动清理。

**其余口径不变**。「高清」的图标由 `Expand` 换为 `ZoomIn`——横排后它与相邻的「扩图」（`Maximize2`）在 14px 下几乎无法区分，下拉时代有行距与菜单标题辅助识别，并排则混淆；其余四项图标不变。工具可用性门槛与置灰口径完全不变（扩图 / 擦除 / 抠图各自的格式与尺寸门槛继续预检），只是展示位置从菜单项移到工具条按钮：可用时悬停出功能说明，置灰时悬停出不可用原因，点击无效，按钮保持渲染不隐藏（工具栏五格位置稳定，用户能学到「该工具存在但本图不可用」）。视频卡的「智能去字幕 ▾」下拉不在本次范围内，维持原样，待视频 HD 高清（[ADR-0105](0105-video-hd-enhance-minimal-panel.md)，IKH3VE）落地、视频卡工具条定型后单独评估。

## Considered Options

- **纯图标（约 323px）**：宽度最接近卡片，但「高清 / 扩图 / 抠图」三项图标在 14px 下辨识度不足（放大镜、对角箭头、魔棒都偏抽象），必须记忆；本 ADR 的目标是「一眼定位」，纯图标与之相悖，否决。
- **纯文字（约 373px）**：没有图标歧义、比全排窄 100px，但并未真正解决宽度问题（仍比竖图卡宽三成），同时失去图标的视觉锚点，五个按钮在灰底上排成一片文字更难扫读，否决。
- **保留下拉 + 工具条上加「常显快捷行」**：同一动作两套入口，与 ADR-0106「一个动作一个入口」的减法方向相反，否决。
- **宽度自适应（窄卡片只显图标 / 溢出折叠成「更多 ▾」）**：工具清单是编译期固定的五项，为不存在的第六项预设机制属过度设计；且同一张卡在不同缩放下按钮形态会变（缩放不改变工具条屏幕尺寸，却要按卡片屏幕宽切换形态），行为不可预期，否决。
- **给「高清」加视觉区分**（它打开面板并新建卡，其余四项进画布内会话）：五者同属画质工具家族，应平权呈现；行为差异由结果自明（一个新建卡、一个原地编辑），悬停文案已分别说明，加标记反而破坏家族一致性，否决。
- **保留最近工具记忆，让其中一项显示为「最近」**：横排后五个工具同时可见，记忆机制的唯一用途（让触发钮显示一个工具名）已消失，保留即死代码，否决。

## Consequences

- [ADR-0101](0101-quality-tool-family-interaction-alignment.md) 第二条（触发钮最近工具语义）被取代；该 ADR 第一条（会话期模态隐藏 chrome）与第三条（发送钮统一）继续有效，家族级规则仍然成立，只是承载形态从「单触发钮 + 菜单」变为「五按钮横排」。
- 五个工具的入口 handler（`onEnhanceImage` / `onOutpaintImage` / `onCropImage` / `onEraseImage` / `onCutoutImage`）、门槛预检函数与建卡口径完全不变，改动集中在承载组件与工具条渲染。
- 测试面随之改写：`ImageQualityMenu.test.tsx`（下拉展开、触发钮记忆、hover 展开口径）与 `qualityTriggerCanvas.test.tsx` 的触发钮六条用例退役，`Toolbar.test.tsx` 的菜单项断言改为对工具条按钮的直接断言；门禁口径不变。
- [CONTEXT.md](../CONTEXT.md) 词条同步：「画质工具家族」改写承载形态，「最近工具触发钮」词条整条删除，高清 / 扩图 / 裁切 / 擦除 / 抠图五处入口的位置描述从「下拉菜单中的动作入口」改为「工具条上的画质工具按钮」，「浮层菜单」词条的举例中移除「高清 ▾ 下拉」。
- 原型与实证留在仓库：`web/prototypes/quality-toolbar.prototype.html`（单文件、双击即开、四形态与缩放档位对照）与同目录 NOTES 记录本次定案，作为形态决策的原始依据。真实页面内的原型分支（`?variant=` 切换）与取证脚本已归档至一次性分支，不入主线。
- 视频 HD 高清（IKH3VE）落地时需复核：视频卡工具条届时为「HD 高清 / 智能去字幕 ▾ / 音视频分离 / 详情 / 下载 / @」，宽度与本次图片卡形态并存，若届时评估去字幕下拉也横排，应另立 ADR 而非顺延本次结论。
