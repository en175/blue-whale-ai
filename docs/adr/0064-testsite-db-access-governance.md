# ADR-0064: 测试站数据库访问治理——封公网直连，SSH 隧道为唯一应急通道

**日期：** 2026-08-03
**状态：** 已接受
**工单：** IK65BP
**关联：** ADR-0062（new-api 账户中心）、IK50GB-C 测试站探针（HTTP-only 原则）

## 背景

2026-08-03 探针首轮验证发现测试站（115.190.244.91）MySQL `Too many connections`：

- 3306 对公网暴露 + root 弱口令；
- 外部 IP（开发机）直连堆积 135 个连接（休眠/断网后僵死不释放）；
- 连锁故障：图片 image-recovery 扫描失败（任务卡 queued）、视频写事件异常、探针媒体终态失败。

"本地开发直连共享测试库"是团队习惯，但该通道无连接预算、无身份审计、无数据隔离，本次事故是其必然产物。

## 决策

采用三层访问模型，**禁止任何客户端以长期连接方式直连共享测试库**：

1. **日常开发 → 本地自足栈**：disposable MySQL（`pnpm db:fresh` + `deploy/typescript-baseline` compose），数据随便重置，不与共享环境产生任何耦合。
2. **调试测试站 → SSH 隧道（唯一应急通道）**：`scripts/tunnel-testsite-db.sh` 一条命令建立本地端口转发，用完即断。隧道走 SSH 认证（有身份、可审计），公网零暴露，连接生命周期与终端会话绑定，天然不会僵死堆积。
3. **集成验收 → 只走 HTTP**：探针与人工验收仅调用公开 API，永不接触数据库（沿用 IK50GB-C 既定红线）。

配套措施：

- 服务器防火墙封禁公网 3306，仅保留容器内网访问；
- 建立只读诊断账号（仅 SELECT），日常排查不再使用 root；
- MySQL root 密码定期轮换，凭据只存在于服务器与部署密钥管理，不进仓库、不进对话记录。

## 理由

- 直连的"便利"实质是把连接治理、数据隔离、凭据安全的责任转嫁给每个开发者；SSH 隧道保留同等调试能力，但把通道收敛为受控、临时、可审计。
- 探针 HTTP-only 原则已证明"不碰库也能完成真实验收"；直连从来不是验收的必要条件。
- 与 Java 退役方向一致：测试站最终将按 typescript-baseline 标准拓扑重建，本决策是该重建前的访问纪律。

## 后果

- 开发者本地配置中不得再出现测试站数据库连接串；存量配置需清理。
- 隧道脚本成为唯一应急入口，其可用性纳入维护范围。
- 违反通道纪律的连接会被防火墙直接拒绝，事故模式从"慢性泄漏"变为"立即显形"。
