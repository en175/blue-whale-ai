# MVP 前端问题清单（2026-07-09）

后端图片生成 MVP 已跑通（job 成功、图片存本地 `data/assets/`、`/assets/**` 静态可访问 http=200）。前端 4 个问题，3 个 agent 只读调研后根因全部锁定，未改代码。

## 确认根因（含 file:line 证据）

### 1. 图片前端不渲染（黑图）
- 后端图真实存在（url=`/assets/xxx.jpg`，:8000 静态 http=200）。
- 根因：`blue_whale_web/next.config.ts:21-27` 只重写 `/api/:path*` → 后端，**漏了 `/assets/:path*`**。前端 `<img src="/assets/...">`（`app/generate/page.tsx:49`、`app/canvas/_canvas/components/CanvasNodes.tsx:78`）被浏览器解析到前端源（:3000），Next.js 无 handler → 404 → 黑预览。「已完成」状态是真的，只是浏览器拿不到字节流。
- 修复：`next.config.ts` 加 `/assets/:path*` → `${BACKEND_API_BASE_URL}/assets/:path*`（仿 `/api` 规则）。或后端返回绝对 URL。

### 2. 模型报错「不支持的模型 doubao-seedream-5-0-lite-250723」
- 根因：前端硬编码旧 model_id。`ImageModelSettingsPopover.tsx:10` `IMAGE_MODELS[0].id="doubao-seedream-5-0-lite-250723"`（commit `2bcd34d`「前端写死」引入）。两个 Dock 默认取它（`ImageDockContent.tsx:40`、`ImageGenDock.tsx:49`），透传后端。
- 后端 `GenerationJobService.java:66` capability 表查不到该 id → 抛 GlobalException「不支持的模型: ...」，msg 原样回显到前端 Dock。文案确系后端产生（前端 grep 零命中）。
- 后端权威 id 是 `doubao-seedream-5-0-260128`（`schema.sql:85`）。lite-250723 既不在表、ARK 也不存在（404）。
- 修复两选（待用户定）：① 前端硬编码值改 260128（最小，但其余 3 个硬编码 model 仍未验证，隐患在）；② 撤回 `2bcd34d`，前端恢复从 `/generation/models` 拉（治本，单源）。

### 3. 左侧菜单栏太宽
- 根因：`components/Sidebar.tsx:31` `w-[200px]` 硬编码（非 token，DESIGN.md 无 sidebar 宽度 token）。全仓唯一处，layout 纯 flex（`shrink-0`/`flex-1`），无其他写死 offset，收窄即自动重排。
- 修复：收窄到 176px。方案 A（推荐，合规）`globals.css` 加 `--tc-sidebar-width:176px` + DESIGN.md 声明，Sidebar 用 `w-[var(--tc-sidebar-width)]`；方案 B 最小改 `w-44`。

### 4. 输入框与生成按钮未对齐
- 根因（两缺陷）：
  - A 结构：`components/ImageGenDock.tsx` textarea（L183-190，包在 `<div className="px-1">` 独占整行）和工具栏行（L195 `flex items-center gap-1.5`）是上下两个块级行，生成按钮（L284）在工具栏行 → 不在输入框同一水平线。
  - B padding：textarea 包裹层 `px-1`(4px) vs 工具栏行无水平 padding（仅外层 `p-2` 8px），左右缘各差 4px。
- 修复两选（待用户定）：① 统一 padding（小改，输入框/按钮仍上下两行但左右缘齐）；② 生成按钮挪到输入框右侧同一行（重构，类 chat 布局，参考 `AgentComposer.tsx`）。
