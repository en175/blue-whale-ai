# 周会汇报模板与每周四创建流程设计

> 日期：2026-08-07
> 状态：已获用户批准（含后续修订：团队名单、分组、概览分层）

## 背景

团队每周四召开周会，需要一份周会汇报文档。第一版（2026-08-06）为一次性生成，存在以下问题：

- 编号跳号（一~五后直接到七，缺六）
- 内容失焦（CI/CD 完整版、账号名单等长文塞进正文，全文 8000+ 字）
- 待办无闭环（结尾手写散乱待办，无责任人格式、无截止时间、无法跨周跟踪）
- 成员详情不可扫描（每人一大段纯文本）
- 元信息不完整（缺参会人、文档状态、会议决议位置）

## 目标

1. 设计一套规范的周会汇报模板，同时服务三个场景：向上汇报（管理层）、会议纪要底稿、工作留档追溯
2. 沉淀每周四的创建流程：AI 生成底稿 → 人工修改定稿 → 会上讨论 → 会后待办闭环

## 已确认的决策

| 决策点 | 结论 |
|---|---|
| 周报用途 | 向上汇报 + 会议纪要底稿 + 工作留档追溯 + 输出每周问题讨论解决（含产品对齐颗粒度） |
| 创建流程 | AI 从 Gitee 拉数据生成底稿 → 人工修改定稿 → 会上讨论 |
| 成员详情组织 | 按组组织：研发组 / 产品组 / 测试组，组内按人 |
| 产品对齐 | 不单独设章节，研发问题与产品问题统一混在「问题与风险」章节，产品项标注【产品对齐】 |
| 模板架构 | 方案 B：会议全流程式（会前 AI 预填 → 会中讨论决议 → 会后待办闭环） |
| 概览呈现 | 分层式：整体进展段 + 亮点段 + 风险信号段 + 关键数字表格（禁止一大坨） |
| PR 统计口径 | 员工口径（不含老板）；实际数字以 Gitee 拉取为准 |
| 个人量化 | **个人完全不量化**：成员详情禁止出现 PR 数/工单数；PR 与 Issue 并重，非 PR 工作（方案/救火/协调/评审）计入贡献；数字仅出现在团队层面概览表 |

## 模板结构（方案 B）

```
📄 团队周会汇报 YYYY-MM-DD
├─ 📌 元信息区（blockquote）
│    会议日期：YYYY-MM-DD（周四）
│    数据窗口：上周五 ~ 本周四
│    参会人（10 人）：研发 李述、尤康林、潘子怀、李小强；产品 徐雯倩、徐诺、严文硕、赵鑫宇；测试 豆沁伟、柚子
│    文档状态：🔄 底稿 → ✅ 定稿
│    数据来源：三项目 Gitee PR 与 Issue 工单（员工口径，不含老板）
├─ 一、本周概览（分层式）
│    ① 整体进展段：团队 PR 合并 N 个、工单关闭 M 个 + 方向覆盖
│    ② <b>亮点。</b>段：本周最有价值的 2-3 个成果（含非 PR 工作）
│    ③ <b>风险信号。</b>段：本周主要风险 2-3 条
│    ④ 关键数字表格：合并 PR / 关闭工单 / 新增工单 / 关键交付（仅团队层面）
├─ 二、成员工作详情（按组组织，10 人全部列出）
│    <h2>研发组</h2> / <h2>产品组</h2> / <h2>测试组</h2>
│    <h3>序号. 姓名（角色）</h3>（禁止出现 PR 数）
│    本周主要贡献：1-3 条，用价值语言描述（含方案/救火/协调/评审等非 PR 工作，带工单号）
│    无记录成员：人名照常列出，不写占位、不标区分，内容留待人工补充
│    - 风险 / 阻塞：（无则省略）
├─ 三、问题与风险（统一条目格式）
│    <b>🔴/🟡/✅ 状态 问题名</b>：描述｜责任人：XXX
│    产品对齐问题标注【产品对齐】前缀，会上优先讨论
├─ 四、会议讨论与决议（会中填写，生成时留空）
├─ 五、待办清单（会后填写，checkbox）
│    <checkbox done="false">任务｜责任人｜截止时间</checkbox>
├─ 六、下周计划（AI 预填建议项）
└─ 附录 A：本周工单动态（留档：已关闭缺陷 + 新需求方向）
   （本周专题长文放附录 B 存档，正文保持精炼）
```

### 设计要点

1. 编号完整：一~六 + 附录，避免跳号
2. 状态流转：🔄 底稿（AI 生成）→ 人工修改 → ✅ 定稿（开会时），文档阶段一眼可见
3. 「问题与风险」为唯一混合区：研发问题 + 产品对齐问题统一条目化，带状态标签，会上逐条过
4. 待办清单用 checkbox，创建新文档时继承上周未完成项，形成闭环
5. 附录承担留档功能，正文保持精炼，解决长文失焦问题
6. 概览分层式呈现，禁止一大坨
7. 个人不量化：成员详情禁止个人数量指标，贡献用价值语言描述（含非 PR 工作）

## 沉淀三件套

### ① 飞书模板文档（人工参考）

- 位置：wiki「研发部门 → 团队会议」目录下
- 标题：📋 周会汇报模板
- 内容：完整骨架 + 每节填写说明（灰色注释块）
- 作用：开会、写文档时对照参考；新人也能看懂格式

### ② 仓库 Skill（AI 执行流程）

- 位置：`.agents/skills/weekly-team-report/SKILL.md`（已创建）
- 内容：团队名单（定死 10 人）、数据边界、模板结构、生成步骤、排除规则
- 作用：用户每周四说「创建本周周会底稿」即可触发全流程

### ③ 周会循环约定（闭环机制）

- 周四上午：AI 生成底稿 → 用户修改定稿
- 周四会上：过「三、问题与风险」→「四、决议」→「五、待办」
- 下周四：AI 生成新文档时自动继承上周未完成待办（checkbox 未勾选项）

## 假设与边界

- 数据源仅限 Gitee 三项目 PR + Issue，不引入飞书需求池管理表格（属其他业务线）
- 周报文档每周四新建，模板文档只维护一次
- 未完成待办继承通过 AI 在创建时复制上周 checkbox 实现，不做额外自动化系统
- 团队名单固定 10 人，人员变动需人工更新 skill
