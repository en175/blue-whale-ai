## 回放方式

在任务工作树运行 `scripts/tests/replay_issue_type.py`。脚本调用已安装的真实 Codex CLI，每次使用独立临时 `CODEX_HOME` 和工作目录，不继承本次纠错对话。临时目录仅加载指定版本的仓库规则、已批准的一票场景及模拟 Gitee MCP。提示词不包含正确子票类型。

父单夹具取自 IKNB6X 的 MCP 详情，保留实际字段结构与正文，省略无关个人资料。需求、任务、类型缺失及未知场景只替换或删除 `issue_type`，其余内容相同。这样也检查 Agent 是否误按缺陷标题推断类型。拒绝夹具保存现场的 `parent_id=34679913`、`category=task`、`issue_type_id=1292680` 及 HTTP 400 回执。

模拟服务只读写本进程内存，不包含 Gitee 网络客户端或凭据。Codex 使用现有登录的临时副本调用模型；临时目录退出时删除，原登录和用户配置不变。只对这一个临时 MCP 服务设置 `default_tools_approval_mode="approve"`，Shell 仍使用 `read-only` 沙箱。该配置取值见 [OpenAI 官方配置文档](https://developers.openai.com/codex/config-reference)。不复制真实 MCP 配置、插件和纠错记忆。

```bash
python3 scripts/tests/replay_issue_type.py --scenario bug --rules-ref 1057d2819aae3469cae00c2ca9d99d1dcde683d4 --output /tmp/iknbbt-old-bug
python3 scripts/tests/replay_issue_type.py --scenario bug --output /tmp/iknbbt-new-bug
```

`--scenario` 另支持 `requirement`、`task`、`missing`、`unknown`。每个场景分别运行旧、新规则。输出目录必须尚不存在，避免覆盖既有证据。需要可用的 `codex` 和已有 `auth.json` 登录；每次最多运行 600 秒，真实模型调用不纳入普通单测自动执行。

输出包含 `rules/`、`scene.json`、`prompt.txt`、`events.jsonl`、`calls.jsonl`、`summary.json` 和 `stderr.txt`。原始对话与请求是验收依据，脚本的提问正则只是辅助筛选，Kim 仍需核对完整对话。`REPLAY1` 等标识及回放输出中的链接均为模拟结果，不能作为真实工单交付。
