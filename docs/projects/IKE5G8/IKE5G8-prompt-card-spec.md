# IKE5G8｜Prompt 方案卡画布承接与生成引用规格

## 时间

2026-09-10

## 状态与依据

本规格整合 IKE5G8 V1.1 与本次讨论中已确认的 Q1–Q9，作为实现与验收依据。按用户要求发布在本工单评论中，保留原需求正文。本评论对素材应用、生成连线、修改同步、素材复用、目标类型与失败边界作进一步裁决；与原文存在差异时，以本次明确确认的规则为准。

产品行为与下述测试边界均已由用户确认，用户已授权发布本规格评论。本文描述目标行为，不表示代码、跨服务联调或部署验收已完成。

## Problem Statement（问题陈述）

用户在右侧 Agent 对话中提供素材并讨论创意，希望把 Agent 整理的 Prompt 方案一键放入 Canvas，再自由选择生图或生视频目标完成创作。方案中的图片、视频、音频引用必须持续指向用户实际选择的素材，不能在应用、编辑、连线或提交过程中退化为素材名称或占位文字。

目前已核对的应用入口主要承接标题、文本与预览来源；文本连线成为生成附件已有基础，但这不足以承接完整素材绑定。现有素材添加入口还可能为同一素材新建不同画布卡。用户因此可能需要重复寻找素材，或看到正文、参考清单与实际生成输入不一致。

另一个问题是共享方案的编辑边界：同一方案可以用于多个目标，用户只操作其中一个目标时，不应意外改掉其他目标或历史任务。素材缺失、超限或待同步必须明确阻止生成，不能静默丢弃参考后继续。

## Solution（解决方案）

Agent 产出带明确素材绑定的 Prompt 预览。用户手动应用时，Canvas 创建富文本方案节点，并补入尚未出现在当前画布的引用素材卡；已存在的同一素材卡直接复用。应用阶段不创建生成目标、不自动生成。

用户将方案节点连到生图或生视频目标，或在该目标的 Dock 中引用方案节点时，方案以附件呈现，绑定素材逐项成为该目标的直接媒体输入，连线与参考清单同步。Dock 不全文展开并覆盖原有提示词，也不自动覆盖未提交草稿。

用户在方案节点上修改文字，下一次生成读取当前正文；修改素材标签则要求各目标分别确认同步。断开某个目标的素材连线只让该目标失效，不改共享正文。提交时验证全部引用和模型能力，冻结当次输入，随后才发起生成。

## User Stories（用户故事）

### Agent 与预览

1. 作为创作者，我希望在右侧 Agent 对话中提供素材参考，以便获得结合实际素材的 Prompt 方案。
2. 作为创作者，我希望先查看并通过对话修改 Prompt 预览，以便满意后再放入画布。
3. 作为创作者，我希望每个素材标签对应明确的真实素材，以便知道方案实际引用了什么。
4. 作为创作者，我希望保留 Agent 原有描述性标题和提示词正文，以便应用画布不会改写我的方案。
5. 作为创作者，我希望纯文字方案也能正常应用和引用，以便没有素材时仍能创作。

### 应用与素材复用

6. 作为创作者，我希望手动应用后得到一张富文本方案节点，以便在画布上继续编辑和编排。
7. 作为创作者，我希望尚未上画布的引用素材一起形成素材卡，以便无需逐个重新添加。
8. 作为创作者，我希望画布上已有的同一素材卡被复用，以便应用方案不产生重复素材卡。
9. 作为创作者，我希望素材按真实身份匹配，以便相似图片、同名素材不会被误认成同一份。
10. 作为创作者，我希望应用只准备内容，以便不会意外创建生成目标或执行生成。

### 标题、正文与标签

11. 作为创作者，我希望图片用途的方案显示 IMAGE，以便快速识别方案原本用途。
12. 作为创作者，我希望视频用途的方案显示本组序号和明确时间段，以便理解其在方案中的位置。
13. 作为创作者，我希望没有明确时间段时不显示猜测时间，以便避免误导。
14. 作为创作者，我希望素材标签显示具体缩略图与编号，以便直接核对引用对象。
15. 作为创作者，我希望编辑标签前后文字或调整展示顺序不改变绑定，以便不会用错素材。

### 连线与 Dock 引用

16. 作为创作者，我希望把方案连到目标就带入完整方案和素材，以便一次操作准备生成输入。
17. 作为创作者，我希望在目标 Dock 引用方案得到同样的输入关系，以便两种入口行为一致。
18. 作为创作者，我希望 Dock 以卡片附件呈现方案，以便保持输入区清晰。
19. 作为创作者，我希望引用方案不覆盖现有提示词和未提交草稿，以便保留已经完成的编辑。
20. 作为创作者，我希望已有素材连线不重复创建，以便参考清单与画布关系明确。

### 编辑与多目标同步

21. 作为创作者，我希望下一次生成使用方案当前文字，以便最新编辑能够生效。
22. 作为创作者，我希望新增、替换或删除素材标签后明确提示同步，以便知道目标输入需要更新。
23. 作为创作者，我希望未同步的目标暂时不能生成，以便正文与参考不会不一致。
24. 作为创作者，我希望同一方案的多个目标分别确认同步，以便操作 A 不会改变 B 的配置。
25. 作为创作者，我希望刷新后仍能看到各目标的引用和待同步状态，以便不会丢失需要处理的事项。

### 移除与共享引用

26. 作为创作者，我希望移除方案时仅移除它独自带入的素材引用，以便不会留下无用输入。
27. 作为创作者，我希望手动添加或其他方案仍在使用的素材引用保留，以便不破坏其他创作依据。
28. 作为创作者，我希望移除附件不删除画布素材卡，以便素材仍可继续使用。
29. 作为创作者，我希望只在目标 A 断线时只阻止 A 生成，以便共享方案和目标 B 不受影响。
30. 作为创作者，我希望恢复所需连线并通过校验后可以继续，以便能清晰修复失效状态。

### 类型与模型能力

31. 作为创作者，我希望实际生成类型由目标决定，以便同一方案可以用于生图或生视频。
32. 作为创作者，我希望 VIDEO 标题不会强制切换到视频 Dock，以便保留我选择的创作方向。
33. 作为创作者，我希望不支持的素材类型得到明确提示，以便主动选择合适模型或修正方案。
34. 作为创作者，我希望模型切换后重新检查引用及数量限制，以便不会提交不合法输入。
35. 作为创作者，我希望正文仍引用的超限素材不能被静默裁掉，以便生成不会偏离完整方案。

### 失败与恢复

36. 作为创作者，我希望应用时发现素材被删或无权访问就整次失败，以便不产生残缺方案。
37. 作为创作者，我希望应用失败保留已有画布且不留下新加的零散卡片，以便能安全重试。
38. 作为创作者，我希望引用时与生成前都检查素材是否完整，以便及时发现之后发生的删除。
39. 作为创作者，我希望错误明确指出失效索引，以便知道应该补充哪份素材或修改哪个标签。
40. 作为创作者，我希望修正方案或恢复引用后重新校验，以便能恢复正常生成。

### 快照、兼容与重复操作

41. 作为创作者，我希望提交给模型的素材与标签展示逐项对应，以便实际输入符合所见。
42. 作为创作者，我希望已提交任务保留当次正文和素材输入，以便后续编辑不会改写历史。
43. 作为创作者，我希望重复应用同一预览沿用既有幂等行为，以便点击或重试不会制造重复方案。
44. 作为创作者，我希望新预览应用保持既有独立节点行为，以便不会覆盖旧方案和连线。
45. 作为创作者，我希望现有添加到对话、纯文字节点和日常画布操作仍可使用，以便新能力不破坏已有流程。

## Implementation Decisions（实现决定）

### 1. 领域与职责

1. Prompt 预览仍由 Agent 提供；应用后是具有单一可编辑正文及显式方案素材绑定的 Canvas 富文本节点。不得恢复旧 SceneCard 双正文、第二份可编辑提示词或卡片自身执行生成的流程。
2. 方案素材绑定描述“正文标签对应哪份素材”；目标输入连线描述“本次目标使用什么”。两者分别维护，以明确同步动作建立一致关系，不沿文本历史递归传递媒体。
3. Agent 集成边界负责交付可信预览身份、原用途、本组展示序号、正文及真实素材绑定。元数据补充不得擅自改写 Agent 展示内容，也不得用标题、图片相似度、名称或画布位置猜测素材身份。
4. Canvas 与 Dock 负责富文本编辑、素材卡复用、附件呈现、目标连线及失效提示。业务 API 负责用户和画布归属校验、可信来源解析、并发一致性与持久化；生成服务负责接纳校验、输入快照和模型格式适配。
5. 沿用独立 NestJS 业务 API、现有持久化及生成链路；跨服务契约先对齐再实现。此规格不指定新的表名、内部模块拆分或消息队列技术。

### 2. 手动应用与整体失败

1. 用户手动应用时创建方案节点；其绑定素材尚未在当前画布出现则补入对应素材卡，已有同一素材则复用。绑定以真实素材身份判断，不做内容相似识别，不采用“最近一张卡”规则。
2. 应用只准备方案和素材，不创建生成目标、不打开并覆盖目标草稿、不自动提交生成；方案的素材绑定由正文标签表达。
3. 同一预览重复应用、新预览独立应用、删除后重新应用等沿用已有预览来源和幂等边界；扩展素材承接时仍需覆盖并发与重试，避免重复创建方案或素材卡。
4. 任何所需素材已删除、不可访问或无法完成合法承接时，整次应用失败并指出问题引用；已有画布保留，不留下本次新方案或新素材卡的部分结果。失败后允许修正并重试。
5. 现有重复卡作为兼容调查处理，不在本需求中自动删除、合并或迁移已有卡。实现须核实其精确身份与来源关系，不让 Agent 猜测选择；涉及改变已有卡归属的产品行为需另行裁决。

### 3. 富文本、标题与素材身份

1. 完整保留正文、所有索引以及索引到真实素材的绑定；素材标签为“具体素材缩略图＋编号”。同一素材被多次引用仍指向同一身份，编辑相邻文字、调整标签展示顺序不得使绑定漂移。
2. 图片用途标题为 IMAGE；视频用途为 VIDEO #序号 起止时间。序号取 Agent 本组展示顺序，与应用点击顺序无关；时间只取该方案中明确的单一起止时间段，无明确值时仅显示 VIDEO #序号。
3. 应用后的展示标题独立于正文，序号固定；编辑正文不自动改标题，编辑标题不改正文。Agent 原描述性标题和正文保持原有内容。
4. IMAGE / VIDEO 表达方案原本用途，不限制实际目标类型，不强制路由到某类 Dock。音频目标方案本期不做；图片、视频、音频可作为参考，但必须满足所选生成模型能力。
5. 纯文字方案保持可用；不从普通文本内容、历史对话或素材名称推断媒体绑定。普通文本附件不隐式携带媒体的既有规则继续成立。

### 4. 引用到目标与连线一致性

1. 用户将方案连到目标，或在该目标 Dock 中引用方案，两入口产生相同的方案附件与媒体输入关系。方案节点及其绑定素材分别直接连入目标，素材引用清单与媒体连线一一对应。
2. Dock 以方案卡片粒度呈现附件，不把全文展开覆盖输入框。目标自身提示词与方案上下文共同生效；沿用已有允许仅附件生成的行为。
3. 已有连线不重复建立，同一素材的重复标签不得重复增加同一目标的素材输入；绑定仍需保持每次正文引用的正确对应。
4. 引用方案不自动覆盖已有未提交草稿。用户自行选择新建目标草稿或编辑现有目标；引用动作在用户明确的目标中生效。
5. 引用接入、刷新恢复与再次打开 Dock 后，方案附件、媒体连线、引用清单及待处理状态必须一致。持久化不能只保存渲染用标签而丢失真实绑定。

### 5. 文字更新与素材同步

1. 下一次生成读取方案当前正文，并在提交接纳时冻结；纯文字修改不要求用户重新引用方案。提交前必须保证使用用户当前已确认的编辑，不读过期缓存。
2. 新增、替换或删除素材标签后，将受影响目标标记为素材待同步，提示“同步素材到目标”。用户确认后更新该目标的素材输入与连线，未同步时阻止生成。
3. 同一方案连接 A、B 时，各目标分别确认。在 A 的 Dock 同步仅更新 A，B 保持待同步并阻止生成，直至用户在 B 完成确认。
4. 同步应保留用户手动添加或其他方案仍需要的素材输入，不能把整个参考清单重置为当前方案的素材集合；这沿用共享引用的来源归属边界。
5. 当前方案正文、素材绑定、各目标已确认的绑定状态及其引用来源必须可恢复。已有任务和任务重试读取接纳时的快照，不回读之后的新正文或新素材。

### 6. 移除与局部失效

1. 从目标移除方案附件时，移除该方案独自带入的媒体引用；用户手动加入、其他方案仍在使用的媒体引用保留，画布素材卡不删除。
2. 系统必须能区分同一目标素材引用的来源，不能仅凭一条可见边判断它只属于某一方案。多来源共用时仍只需一条实际媒体输入关系。
3. 仅在目标 A 移除某个素材引用或断开连线，只使 A 对应索引失效并阻止 A 生成；不改共享方案正文、标签绑定或目标 B 的状态。
4. 恢复 A 所需连线后重新校验，通过后可继续；不因失效提示自动补回用户刚移除的连线。真正移除方案中的素材标签须在方案节点明确编辑，再逐目标同步。
5. 真实素材被删除与目标局部断线不同：前者按资产删除一致性规则使所有受影响引用失效，后者只影响操作目标。两者都不得静默生成或篡改历史任务输入。

### 7. 校验、模型限制与提交

1. 应用、引用到 Dock、生成提交分别执行对应边界校验。引用时发现失效立即标示；提交前再次核查权限、素材存在性、索引完整性、目标同步状态与模型能力。
2. 素材缺失提示沿用：“提示词引用的素材缺失或不完整，请补充素材或移除对应引用后再生成。”必须指出具体失效索引；单纯从参考清单移除仍被正文引用的素材，不视为修复成功。
3. 沿用所选模型的素材类型、模式和数量限制，切换模型后重新校验。若裁剪会移除正文仍引用的素材，则禁止提交并指出问题，不静默裁剪后生成。
4. 提交适配将标签或占位符转换为模型支持的格式，同时携带实际绑定素材；转换后逐项对应关系必须不变。校验或转换失败不创建有效生成任务。
5. 接纳时冻结当前正文、索引到真实素材的映射、目标输入、模型与参数，实际供应商请求必须能与该快照对应；后续编辑、断线、删除与同步不改写已接纳任务。

## Testing Decisions（测试决定）

### 测试边界

测试边界已由用户确认：以一个最高层的真实用户创作流程作为主要验收入口——真实浏览器操作 Agent 面板、Canvas 与 Dock，经真实业务 API 落到隔离测试数据库。只在外部 Agent 和生成供应商边界使用可记录请求的可控替身。

公开业务接口集成测试作为补充，用于浏览器难以稳定制造的并发应用、失败回滚、权限拒绝、提交瞬间素材变化及历史快照。不得为每个内部 helper、组件或数据库表另建产品验收边界。

### 好测试与已有基础

1. 断言用户可见的节点、正文标签、附件、连线、提示和操作结果，并通过公开 API 回读持久化事实及任务输入；不以内部 state、函数调用次数、组件结构或 CSS 快照证明业务正确。
2. 复用已有 Prompt 预览应用、文本附件生图/生视频、画布保存恢复与对话引用的浏览器和业务 API 集成测试基础；保留已有隔离数据库装配及外部服务替身边界。
3. 扩展记录式 Agent 替身提供带真实身份绑定的预览；生成供应商替身记录最终请求，逐项比对正文引用、素材身份和冻结快照，不用随机成片质量代替输入一致性验证。
4. 替身测试不能证明独立 Agent 已发布兼容协议；还需在集成环境验证真实 Agent 预览到 Canvas 应用的身份贯通，并分别记录自动化证据、真实联调与人工 UI 验收。
5. 代码实施阶段按仓库影响面策略执行检查与测试；本次规格发布不宣称产品测试、迁移或部署已通过。

### 验收矩阵

| 场景 | 必须观察到的结果 | 主要验证入口 |
| --- | --- | --- |
| A 已在画布、B 未在画布，应用引用 A/B 的方案 | 复用 A、补入 B、方案绑定完整；不创建生成目标、不提交任务 | 浏览器＋API 回读 |
| 重复、并发和失败后重试应用 | 无重复有效方案和重复新增素材卡；不覆盖已有编辑 | 公开 API 集成 |
| 应用时素材被删或无权访问 | 指出具体引用；整次零新增，已有画布保留 | API 集成＋浏览器 |
| 图片／视频标题与应用顺序 | IMAGE 或 VIDEO 序号和明确时间正确；不猜时间、不按点击顺序编号 | 浏览器 |
| 标签相邻编辑、排序与同素材多次引用 | 缩略图、编号和真实素材对应不漂移 | 浏览器＋提交请求记录 |
| 连线入口与 Dock 引用入口 | 完整输入相同；附件式展示；媒体连线与参考清单一致 | 浏览器＋API 回读 |
| Dock 已有提示词和未提交草稿 | 引用不覆盖既有输入；已有连线不重复 | 浏览器 |
| 纯文字修改后提交 | 请求使用当前正文；旧任务仍保留旧快照 | 浏览器＋API 集成 |
| 素材标签变化，方案连接 A/B | 两目标待同步；只确认 A 时仅 A 更新，B 仍阻止生成 | 浏览器＋刷新回读 |
| 方案与手动引用、另一方案共用素材 | 移除方案仅清理独占引用；共用引用和素材卡保留 | 浏览器＋API 回读 |
| 仅 A 断开必要素材连线 | A 标记具体失效并阻止生成；共享正文和 B 不变 | 浏览器＋API 回读 |
| 修复标签或恢复连线 | 按目标确认与重新校验；不自动改其他目标，不静默恢复已断线 | 浏览器 |
| VIDEO 方案用于生图目标 | 不强制切换目标类型；按实际模型校验媒体支持 | 浏览器＋供应商请求记录 |
| 切换模型、超限裁剪、素材后续删除 | 必要素材缺失或不支持时不提交，指出问题索引 | 浏览器＋API 集成 |
| 标签转换与生成接纳 | 模型请求中的素材与标签及快照逐项对应 | API 集成＋供应商请求记录 |
| 生成后编辑、同步、删除与重试 | 历史任务及其重试保留原输入；新任务采用当前有效输入 | API 集成 |
| 纯文字方案与日常操作回归 | 仍可引用、添加到对话、选择、编辑、拖动、保存与恢复 | 现有浏览器回归 |

## Out of Scope（范围之外）

### 产品范围

1. 音频目标方案的标题与画布承接；本期只覆盖生图、生视频目标，音频参考受模型能力约束。
2. Agent 对话面板的引用交互改造、擅自修改 Agent 描述性标题和正文、自动执行生成或递归执行整张画布。
3. 图片相似度判断、按名称或距离选卡、清理或合并既有重复素材卡。
4. 恢复旧 SceneCard 双正文、第二套活动生成卡流程、为每个目标复制一份可编辑方案正文。
5. 修改计费、模型素材上限、整体画布布局或既有底部固定入口与连线路径的并存策略。
