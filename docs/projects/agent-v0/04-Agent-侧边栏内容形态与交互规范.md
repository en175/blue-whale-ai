# Agent 侧边栏内容形态与交互规范

## 1. 目的

这份规范定义 Agent v0 侧边栏里会出现哪些用户可见内容、哪些内容需要卡片化、哪些内容只作为流式信息展示，以及用户在每类内容上可以做什么动作。

PRD 负责定义 v0 要做什么和怎么验收；《独立 Agent 工作流程说明》负责定义后端对象、执行边界和状态事件；《Agent Workflow / Skill 编排说明》负责定义 AgentRun 内部 Workflow / Skill 编排；本规范负责定义 Agent 侧边栏的内容形态和交互规则。

本文对齐《Agent 实现 v0 PRD》：Agent 侧边栏 v0 只跑通“需求理解确认与分镜提示词生成卡”主链路。用户确认需求理解后，Agent 直接生成带分镜提示词的生成卡；用户手动应用生成卡后，侧边栏只告知生成卡内容已进入 Canvas dock。Canvas dock 之后是否发送生成、如何确认参数、如何创建生成任务、如何展示生成状态和如何处理生成失败，不属于 Agent 侧边栏 v0 主责，也不回传 Agent 侧边栏。

## 2. 内容形态分类

| 类型 | 定义 | 是否需要用户动作 | 展示形态 |
| --- | --- | --- | --- |
| 思考过程 | Agent 当前正在做什么的过程信息，例如正在理解需求、判断信息、读取授权素材、整理分镜、生成提示词 | 不需要 | 流式、小字、可折叠 |
| 流式消息 | Agent 普通回复、追问、补充说明、轻告知 | 视内容而定 | 对话流 |
| 需求理解总结 | Agent 在信息充分时，对创作目标、素材使用和内容方向的结构化总结 | 需要用户确认 / 修改 / 补充 | 结构化消息或轻量确认区 |
| 分镜总览说明 | 用户确认需求理解后，Agent 对整组视频方向、节奏、镜头数量和素材使用的自然语言说明 | 不需要，用户可直接提出修改 | 对话流 |
| 生成卡 | 用户确认需求理解后生成的单镜头分镜提示词卡，承载可应用到 Canvas dock 的镜头内容 | 需要用户修改或手动应用 | 卡片 |
| 应用状态提示 | 用户手动应用生成卡后的状态反馈，告知生成卡内容已进入 Canvas dock | 不需要，除失败重试外 | 状态条或轻告知 |
| Canvas 结果边界说明 | 告知用户生成结果后续只在 Canvas 展示，Canvas 生成状态不回传 Agent 侧边栏 | 不需要 | 可并入应用状态提示的文字说明 |

## 3. 思考过程

思考过程保留这个产品名称。它只表示 Agent 的用户可见过程透明度，不等于模型原始内部推理，也不等于需求理解总结或生成卡正文。

思考过程适合展示：

- 正在理解用户需求
- 正在判断信息是否充分
- 正在读取用户授权素材
- 正在整理需求理解
- 正在整理分镜
- 正在生成分镜提示词
- 正在生成生成卡
- 正在应用生成卡到 Canvas dock

思考过程不承载用户确认动作。用户不需要对每条思考过程点确认。

思考过程禁止展示：

- 模型原始内部推理
- 内部提示词中间态
- 工具参数、接口字段、日志、资源 ID
- 未经过用户授权的素材内容

## 4. 需求理解总结

需求理解总结是 v0 的核心确认门。Agent 判断信息充分后，必须先总结需求理解并等待用户明确确认；用户未确认前，不生成分镜提示词生成卡。

需求理解总结至少包含：

| 内容 | 说明 |
| --- | --- |
| 创作目标 | 用户想生成什么类型的图片 / 视频 / 内容 |
| 主体与素材 | 使用哪些用户输入、图片、视频或 Canvas 引用 |
| 内容方向 | Agent 对风格、节奏、卖点、结构方向的理解 |
| 基础规格 | 时长、比例、平台、画面方向等用户已说明或 Agent 默认补全的内容 |
| 不确定点 | Agent 仍不确定但不阻塞继续的问题，需要明确展示 |

用户动作：

| 动作 | 结果 |
| --- | --- |
| 确认需求理解 | Agent 进入生成卡生产，直接生成分镜提示词生成卡 |
| 修改或补充 | 形成新的用户输入，进入新的 AgentRun 继续理解 |
| 取消 | 当前流程停止，保留历史对话 |

交互规则：

- “确认需求理解”是进入生成卡生产的前置动作。
- 用户修改需求理解时，不应直接覆盖历史总结，应形成新的版本或新的 AgentRun 结果。
- 信息不足时，应优先追问关键缺失信息，而不是产出空泛总结。
- 需求理解总结不是生成卡，也不是最终媒体。

## 5. 生成卡

用户确认需求理解后，Agent 先用自然语言给出整组分镜总览，说明整体方向、节奏、镜头数量和素材使用。总览说明不是生成卡。

生成卡是单镜头级的分镜提示词卡，承载可被用户检查、修改并手动应用到 Canvas dock 的镜头内容。视频场景下，生成卡需要按视频时间顺序展示多张；图片或单镜头场景下，可以展示一张或少量生成卡。生成卡不是最终图片、视频或文本结果，也不等于生成任务。

### 5.1 生成卡内容

生成卡至少包含：

| 内容 | 说明 |
| --- | --- |
| 卡片标题 / 镜头编号 | 例如“镜头 1 / 开场钩子”，用于按时间顺序识别 |
| 画面描述 | 单个镜头的时长、画面内容、主体动作、场景、口播 / 字幕、关键视觉 |
| 分镜提示词 | 可用于后续生成的提示词内容 |
| 素材引用 | 该卡使用的图片、视频或 Canvas 素材引用 |
| 手动应用按钮 | 用户点击后，生成卡内容进入 Canvas dock |

### 5.2 用户动作

| 动作 | 结果 |
| --- | --- |
| 自然语言修改 | 用户说明想改哪里，进入新的 AgentRun，重新整理对应生成卡 |
| 手动应用单张生成卡 | 单张生成卡内容进入 Canvas dock |
| 手动应用整组生成卡 | 整组生成卡内容按顺序进入 Canvas dock |
| 取消 / 不使用 | 保留生成卡历史，不进入 Canvas dock |

交互规则：

- 生成卡必须保留手动应用按钮，不能自动应用。
- 手动应用不能自动触发生成任务。
- 用户可以继续用自然语言指定修改某一张分镜提示词卡，不要求用户进入字段表单编辑。
- 修改单张卡时，优先只更新该卡；修改整体结构时，Agent 先用自然语言说明影响范围，再重新整理整组分镜提示词卡。
- 生成卡版本需要可追踪，方便知道它来自哪次需求理解确认和哪组素材。

## 6. 依附型交互

追问、确认、修改、应用、取消通常不单独做成独立卡片，而是依附在当前内容下面。

示例：

- 需求理解总结下面出现：确认需求理解、继续补充、修改方向
- 生成卡下面出现：手动应用、修改这张、修改整组、取消
- 应用状态提示下面出现：查看 Canvas dock、重试应用

不得出现：

- 脚本卡下面确认脚本
- 分镜卡下面确认分镜
- 提示词卡下面进入生成准备
- 生成准备卡下面确认生成

这些旧动作不属于 v0 侧边栏主链路。

## 7. 状态型内容

v0 至少需要覆盖以下用户可见状态：

| 状态 | 用户感知 | 下一步 |
| --- | --- | --- |
| 等待输入 | 侧边栏等待用户输入需求或引用素材 | 用户发送需求 |
| Agent 处理中 | Agent 正在理解需求、读取授权素材或整理内容 | 进入追问、需求理解确认或生成卡展示 |
| 等待用户补充 | 信息不足，Agent 返回追问 | 用户补充需求 |
| 等待用户确认理解 | Agent 已整理需求理解总结 | 用户确认、修改或补充 |
| 生成卡生成中 | 用户确认需求理解后，Agent 正在整理分镜提示词生成卡 | 展示生成卡 |
| 生成卡已生成 | 带分镜提示词的生成卡已展示 | 用户自然语言修改或手动应用 |
| 生成卡应用中 | 用户已点击应用，系统正在写入 Canvas dock | 应用成功或失败 |
| 生成卡已应用 | 生成卡内容已进入 Canvas dock | Canvas 侧决定是否发送生成；后续生成状态不回传 Agent 侧边栏 |
| Agent 端处理失败 | Agent 理解、素材读取、生成卡产出或应用失败 | 展示可理解原因和下一步动作 |

不作为 Agent 端 v0 主状态：

- 生成准备中
- 等待用户确认生成
- 生成任务创建中
- 生成中
- Canvas 侧生成失败

Canvas dock 之后的生成状态由 Canvas 侧展示，不回传 Agent 侧边栏。Agent 侧边栏只保留生成卡应用是否成功的状态，不展示最终结果正文。

## 8. 与 Canvas 的关系

Agent 侧边栏承载对话、思考过程、追问、需求理解总结、生成卡、自然语言修改和应用状态提示。Canvas 承载用户素材、Canvas dock 和最终生成结果。

边界规则：

| 边界 | 规则 |
| --- | --- |
| 生成卡展示 | 生成卡正文展示在 Agent 侧边栏 |
| 手动应用 | 用户点击应用后，生成卡内容进入 Canvas dock |
| Canvas dock | 承接生成卡内容，后续是否发送生成由 Canvas 侧决定 |
| 最终结果 | 图片、视频或文本结果只在 Canvas 展示，生成状态不回传 Agent 侧边栏 |
| 侧边栏应用后提示 | 用户手动应用后只提示生成卡内容已进入 Canvas dock，不展示缩略图、预览或结果正文 |
| 生成失败 | Canvas 侧生成失败处理不属于 Agent 端范围；Agent 侧边栏只保留与生成卡应用相关的失败提示 |

生成卡进入 Canvas dock，不等于已经生成最终媒体，也不等于已经扣费或创建生成任务。

## 9. 与工程流程的关系

后端不需要把每一种内容形态都做成完全不同的流程，但需要保留这些用户可见内容与 `AgentRun`、用户确认动作、素材引用、生成卡版本和手动应用动作之间的追踪关系。

最低要求：

| 能力 | 说明 |
| --- | --- |
| 内容类型识别 | 前端能知道当前返回的是思考过程、普通消息、需求理解总结、生成卡还是状态提示 |
| 确认动作追踪 | 能追踪用户是否确认了哪次需求理解总结 |
| 生成卡版本追踪 | 能追踪生成卡来自哪次 AgentRun、哪次需求理解确认和哪些素材 |
| 应用动作追踪 | 能追踪用户手动应用了哪张或哪组生成卡 |
| Canvas dock 承接 | 能把生成卡内容可靠带入 Canvas dock，且不自动触发生成 |
| 不接收 Canvas 生成状态 | Canvas dock 之后的生成状态和结果展示由 Canvas 侧处理，不回传 Agent 侧边栏 |

## 10. v0 不做

以下内容不属于 Agent 侧边栏 v0：

- 不展示独立 Brief 卡、脚本卡、分镜卡、提示词卡、生成准备卡。
- 不要求用户按“确认脚本 → 确认分镜 → 确认提示词”逐步过门。
- 不在 Agent 侧边栏确认最终生成参数、数量或扣费。
- 不由 Agent 侧边栏创建生成任务。
- 不由 Agent 侧边栏调用生成工具。
- 不在 Agent 侧边栏展示最终生成图片、视频缩略图或文本结果正文。
- 不处理 Canvas 侧生成失败的完整恢复链路。
