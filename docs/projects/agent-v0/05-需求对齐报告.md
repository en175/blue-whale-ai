## 1. v0 主链路（PRD-agent-v0 核心）

用户在 **Agent 侧边栏**输入创作需求（文本/图片/视频/画布引用）→ Agent 展示**可折叠思考过程** → 信息不足**追问** → 信息充分**总结需求理解并等确认** → 用户**确认后**直接产出**分镜提示词生成卡**（按视频时间顺序多张）→ 用户**自然语言修改**或**手动应用** → 生成卡内容进 **Canvas dock** → 侧边栏只提示"已进入 dock"，Canvas 生成状态**不回传**。

关键边界：Agent 端 v0 **不自动生成、不调用生成工具、不自动扣费**；生成卡不是最终媒体；手动应用前不进入 dock。

## 3. 现状 vs 需求 —— 汇总

### 已做（✅）
- 侧边栏对话 + SSE 流式（A2、A10）
- Canvas dock 手动发送生成（C2、C3）
- agent-assets presign 上传流程（部分 D1）

### 部分 / 机制在但未接线（🟡）
- 后端确认门协议（A5、B2）：contracts/agent-runtime 有，前端无 UI，且将退役

### 未做 / 核心缺口（❌）
- **可折叠思考过程**（A3）
- **需求理解确认 UI**（A5 前端）
- **分镜提示词生成卡 + 自然语言修改**（A6、A7）
- **手动应用到 Canvas dock**（A8、A9、C1 通道、C4）
- 意图路由/Workflow/Skill 编排在平台侧（B1~B7）
- 图片/视频理解在 ai 侧（D2）
- SSE 新事件类型（E1~E3）
- 侧边栏状态机（F1）

### 会被新架构取代（⚠️）
- `packages/agent-runtime` 的 plan-card 协议 → 独立 Mastra 服务（blue-whale-agent 仓）接管，blue-whale-ai 保留 UI + BFF + dock + 生成冻结

## 4. 关键架构缺口（影响 v0 主链路闭环）

1. **新后端无 `/api/agent/v1` 路由/代理**：web dev 下 `/api/agent/v1/*` 代理到 `localhost:3100`，但 backend/apps/blue-whale 无该控制器，也无到 agent 服务（4111）的代理 → Agent 对话链路在本地 dev 不通。需要 backend 补 agent BFF 路由（透传/代理到 Mastra agent 服务）。
2. **agent-assets resolver 契约变更**：旧 `POST /api/internal/agent-assets/resolve`（blue-whale-agent V3 已实现依赖）在重构后不存在，新流程是 `/api/agent/assets/presign`。V3 素材分析的生产读取链路需按新契约对齐。
3. **生成卡产物形态未定**：新需求是"单镜头分镜提示词生成卡"，Mastra V3 产出的是 `PromptCardRevision`（任务卡）。两套卡片形态需要对齐（是否复用 PromptCard 协议，还是新的 generation_card 协议）。
