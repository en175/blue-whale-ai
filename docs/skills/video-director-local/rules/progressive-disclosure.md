# 渐进式披露

目标：让用户用最少负担完成高质量创作。

## 核心规则

1. 每次只问当前阶段必须知道的信息。
2. 当前阶段必须知道的信息要问清楚为止，不设每轮问题数量上限。
3. 如果可以从用户原话中推断，先给出推断并请用户确认。
4. 不要在创作开始前一次性问完整长问卷。
5. 不要把后面阶段的问题提前问完。
6. **细节偏好不追问，走默认 + 预览**：品种、颜色、姿势、风格等不影响「结果方向」的细节，默认补全并在给用户的预览里展示，用户可直接修改，不算追问。

## 追问边界：方向歧义 vs 细节偏好

**只在「默认会决定结果方向」时追问**——一旦默认错，整条链路 / 整个结果就废，事后确认也救不回来。

| 场景                                                                | 处理                            |
| ------------------------------------------------------------------- | ------------------------------- |
| **方向歧义**（视频类型 / 用途 / 主体不明，默认会选错链路或错主体）  | **追问**                        |
| **细节偏好**（品种 / 颜色 / 风格 / 姿势，默认值合理，预览改得回来） | **不追问**，默认补全 + 预览确认 |

正例（该追问）：「做个视频」→ 追问类型；「做个广告」→ 追问主体。
反例（不追问）：「生成一张猫图」→ 不问品种颜色，默认补全 + 预览。

## 分阶段问题

### 新任务启动

只确认：要做什么类型的视频？主体是什么？用途或平台是什么？用户已说就不重复问。

### Brief 阶段

只补：产品 / 人物 / 服务是什么、核心卖点或情绪方向、是否有图片或参考视频。

### Skill 阶段

默认告知，不设确认门：

- **用户未选 Skill**：自动匹配后一句话流式告知选了什么套路 + 白话简短解释这个套路长什么样（用户不识风格名，如"UGC 种草——真人出镜讲使用场景那种"），不出确认卡，用户想换随时说。Skill 不是确认点产物，频繁确认卡拖沓。**告知即视为已确认 Skill**（用户未反对即采纳），满足后续 storyboard 前置。
- **用户已选 Skill 且分歧大**（核心 pattern 与结果方向跨类别 / Skill 适配链路 ≠ 需求链路，判据同「方向歧义」）：陈述分歧点 + 开放问需求内核，每轮聚焦一个维度，方向厘清后再收敛确认，不二选一。
- **轻分歧**（同方向同链路内风格不最优，判据同「细节偏好」）：直接用用户选的，不追问。

### 脚本分镜阶段

只确认：脚本方向是否对、镜头结构是否满意、是否有必须保留或删除的内容。

### 提示词交付阶段

只确认：提示词方向是否对、哪些镜头要改。

## 标准追问格式

```text
我先补齐当前阶段最关键的信息（按当前阶段实际缺口，有几个问几个，不固定数量）：
- {问题一}
- {问题二}
- …
```

## 推断确认格式

```text
我先按这个方向理解：
- 视频类型：{推断}
- 主体：{推断}
- 风格：{推断}

如果没问题，我会先进入 {下一阶段}；如果要改，直接告诉我。
```

## 禁止

- 禁止把多个阶段的问题合并成一次性长问卷抛给用户。
- 禁止问和当前阶段无关的问题。
- 禁止用技术字段问用户，比如 `stage_id`、`workflow_type`。
- 禁止让用户自己选择复杂内部流程。
