# 轻量生成编排（Direct Generation Workflow）

目标：处理用户要「要好」的直接生成——简单图 / 轻量视频，帮补全维度、优化提示词，**止于可复制的提示词**（本地版不生成）。

## 适用判断（Director 自主）

- 目标清楚、不涉及复杂营销策略
- 不要求多版本脚本
- 结果可以一次出提示词

示例：

- 「生成一个小猫跑步的视频」
- 「做一张赛博朋克城市图」
- 「让这张图动起来」
- 「做一张保温杯产品图」

不适用于（→ `full-canvas-creation.md`）：需要完整广告策略、多阶段分镜、复杂 Skill。

## 流程

| 步骤 | 名称 | 执行者 | 产物 | 确认 |
|---|---|---|---|---|
| 1 | 识别生成意图 | Director | generation_intent | 否 |
| 2 | 轻量补问 | brief（轻量） | minimal_brief | 视情况 |
| 3 | 图片理解 | image-understanding | asset_understanding | 有图时 |
| 4 | 提示词草案 | image-prompt / Director | prompt_draft | 否 |
| 5 | 提示词优化 + 交付 | prompt-optimizer | 提示词交付包 | 否 |
| 6 | 自检 | review | 审核摘要 | 视情况 |

### 步骤 1：识别生成意图

Director 从用户消息识别：生成类型（image / video / image-to-image / image-to-video）、主体、动作、场景、风格、是否有参考图。

### 步骤 2：轻量补问

描述够则直接默认补全。默认：图片商业写实高质量；视频 5 秒、写实、稳定镜头、无字幕无水印；画幅短视频 9:16。只有关键缺失才追问。

### 步骤 3：图片理解

用户提供图片或说「这张图」，先进入 image-understanding（`agents/image-understanding.md`）。没有 asset_understanding 不做图生图 / 图转视频。

### 步骤 4：提示词草案

- 直接生图 → image-prompt agent
- 直接生视频 → 由 Director 整理视频提示词草案（主体 / 动作 / 场景 / 镜头 / 风格 / 时长 / 必须避免）
- 图转视频 → 引用图片理解结果，明确哪些主体不变、怎么动、镜头怎么运动

### 步骤 5：提示词优化 + 交付

prompt-optimizer 按目标模型优化，按交付包格式（`../references/generation-action-guide.md`）输出可复制的提示词。**本地版到此为止**。

### 步骤 6：自检

review 快速检查提示词是否对齐意图、能不能直接复制用。

## 示例：小猫跑步视频

用户：

```text
我想生成一个小猫跑步的视频
```

visible_reasoning：

```text
我理解你要一个轻量视频，不需要完整广告编排。
我把主体、动作、场景整理成视频提示词，做模型适配，给你可直接复制到即梦/Seedance 的提示词。
```

默认补全 + 交付：

```text
主体：小猫 | 动作：草地上轻快跑步 | 场景：自然户外草地 | 风格：写实明亮自然光 | 时长：5s | 画幅：9:16 | 镜头：低机位轻微跟拍

【提示词】（复制到即梦/Seedance）
一只毛茸茸的小猫在阳光下的绿色草地上轻快跑步，低机位轻微跟拍，小猫动作自然连贯，耳朵和尾巴随跑动轻微摆动，背景有柔和的自然虚化。写实风格，明亮自然光，画面稳定，细节清晰，动作不卡顿，小猫身体不变形。保持无字幕，不要生成水印，不要生成 Logo。
```

## 禁止

- 不把简单任务升级成 full-canvas。
- 不跳过 prompt-optimizer 直接把草案当最终提示词。
- 不在缺少图片理解时做图转视频。
- 不调用生成 API（本地版止于提示词）。
