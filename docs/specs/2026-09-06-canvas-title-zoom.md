# Canvas 四类卡片外部标题行分段缩放

## 时间

2026-09-06

## Problem Statement

Canvas 用户在缩小查看多张卡片时，外部标题随卡片一起变小，名称、分辨率和时长难以辨认；放大查看内容时，标题又过大，消耗视觉空间。始终固定字号也不合适：远景总览时，文字会相对卡片过大，造成拥挤。

当前名称为 11px、辅助信息为 10px；在 63% Canvas 缩放下，屏幕显示约为 6.93px 和 6.3px。这是由现有字号和倍率推导的数值。用户已确认前轮卡片布局基本符合预期，本需求只改善外部标题行的缩放体验。

## Solution

四类卡片的整条外部标题行采用连续的分段缩放：常用倍率保证可读，放大到上限后停止增长，缩到总览阈值以下后继续随卡片缩小。标题保持在卡片宽度内，文字放不下时单行截断；标题不突然隐藏，也不扩大卡片。

## User Stories

### 阅读与层级

1. 作为 Canvas 用户，我希望图片卡片名称在常用缩放范围保持可读，以便辨认素材。
2. 作为 Canvas 用户，我希望视频卡片名称和元信息一起适配，以便辨认视频及其规格。
3. 作为 Canvas 用户，我希望音频名称和时长一起适配，以便识别音频。
4. 作为 Canvas 用户，我希望文本卡片外部标题与其他卡片使用统一规则，以便浏览时保持一致体验。
5. 作为 Canvas 用户，我希望类型图标随标题适配并保留名称与辅助信息的层级，以便快速识别内容类型。

### 缩放行为

6. 作为 Canvas 用户，我希望在 75%～100% 缩放时标题保持标准阅读大小，以便无需反复放大辨认。
7. 作为 Canvas 用户，我希望超过 100% 后标题适度增大，以便自然跟随查看动作。
8. 作为 Canvas 用户，我希望名称、辅助信息和图标分别封顶，以便放大内容时标题不会过大。
9. 作为 Canvas 用户，我希望低于 75% 后标题继续随卡片缩小，以便远景总览不被文字占满。
10. 作为 Canvas 用户，我希望跨越各阈值时尺寸连续且标题不突然消失，以便缩放体验稳定。

### 排版与信息

11. 作为 Canvas 用户，我希望长名称在卡片宽度内单行截断，以便不会伸入邻近卡片。
12. 作为 Canvas 用户，我希望极窄卡片仍受原有宽度约束，以便空间编排不被标题撑开。
13. 作为 Canvas 用户，我希望完整视频元信息和名称共存时仍限制在标题行内，以便卡片边界清楚。
14. 作为 Canvas 用户，我希望分辨率和时长仍显示真实媒体信息、缺失项留空，以便不会把显示尺寸误认为源文件规格。
15. 作为 Canvas 用户，我希望标题行高度和间距适配字号，以便字形不被裁切且工具栏不遮挡标题。

### 交互与范围保持

16. 作为 Canvas 用户，我希望缩放不改变已保存位置和自由编排，以便保留空间关系。
17. 作为 Canvas 用户，我希望在拖动、选中和媒体加载期间缩放时卡片不回跳、不丢失状态，以便连续操作。
18. 作为 Canvas 用户，我希望连线端点保持与内容区对应，以便标题变化不破坏连接关系。
19. 作为 Canvas 用户，我希望文本正文、播放器和工具栏保留现有大小行为，以便本次优化不改变内容操作。
20. 作为 Canvas 用户，我希望画布继续使用现有缩放范围和名称，以便沿用当前使用习惯。

## Implementation Decisions

### 范围与现有模块

仅调整图片、视频、音频共用的媒体节点和文本节点的外部标题行，复用 Canvas 现有实时视口倍率。外部标题行包括类型图标、现有名称、有值时的分辨率和时长。标题宽度仍由内容区宽度约束。

现有 Canvas 最大倍率为 800%，最低倍率沿用库默认 50%；本需求保留 50%～800% 的可操作范围，不调整默认视口或双击定位行为。媒体卡片已有宽度约束、名称及元信息省略规则，文本标题与正文是独立元素，均应在现有基础上修改。

### 尺寸契约

屏幕大小指经过 Canvas 缩放后看到的 CSS 像素大小，不是设备物理像素，也不是未经变换的局部字体值。标准阅读倍率为 100%，总览阈值为 75%。

| 元素 | 标准大小及可读下限 B | 放大上限 M |
| --- | ---: | ---: |
| 名称字号 | 12px | 16px |
| 分辨率、时长字号 | 11px | 14px |
| 类型图标边长 | 14px | 18px |

令 z 为 Canvas 倍率（100% 为 1），S 为屏幕大小。z 小于 0.75 时，S 等于 B × z ÷ 0.75；z 在 0.75～1 之间时，S 等于 B；z 大于 1 时，S 等于 B × z 与 M 的较小值。各元素独立应用规则。

若标题仍受父级 Canvas 变换，局部尺寸须补偿为 S ÷ z。具体样式或变换方案由实现决定，不新增服务端接口、持久化字段或用户配置。

| Canvas 缩放 | 名称 | 辅助信息 | 图标 |
| --- | ---: | ---: | ---: |
| 50% | 8px | 7.33px | 9.33px |
| 63% | 10.08px | 9.24px | 11.76px |
| 75%～100% | 12px | 11px | 14px |
| 125% | 15px | 13.75px | 17.5px |
| 150%～800% | 16px | 14px | 18px |

名称在 133⅓% 封顶，辅助信息约在 127.27% 封顶，图标约在 128.57% 封顶。计算保留精度，表内小数为近似值，允许正常亚像素误差。连接处尺寸连续，不要求变化速率连续。低于总览阈值后取消可读下限，继续缩小而不主动隐藏；宽度不足产生的截断仍适用。

### 排版与交互

标题行高度、图标间距随字号适配，避免纵向裁切。名称及元信息保持单行省略；极窄卡片优先遵守内容区宽度，不能为显示完整标题撑宽节点。名称、元信息与图标保持原有排列关系。

操作工具栏保留原有大小行为，仅调整相对位置以避开标题。内容区尺寸契约、卡片位置、选中状态、拖动状态和连线端点与内容区的对应关系保持不变。缩放只影响信息呈现，不改变真实分辨率、时长或名称，缺失元信息继续留空。

## Testing Decisions

### 入口与原则

用户已确认以现有 Canvas 组件集成为主要自动化入口，覆盖四类标题、倍率边界以及拖动和选中状态；真实浏览器验收实际字号、连续变化、窄卡片截断和工具栏遮挡。

复用现有画布交互测试的真实组件、手势事件及媒体加载回归方式，以及媒体卡片和文本卡片已有浏览器布局验收场景。优先复用入口，不为测试引入新业务接口。测试可观察的尺寸、显示信息和交互结果，不绑定内部 hook、状态变量、CSS 类名或渲染次数。纯数值测试不能替代浏览器布局验收，jsdom 的模拟尺寸不能作为视觉正确性的证据。

### 自动化与浏览器验收

1. 四类卡片在 50%、63%、75%、100%、125%、150%、800% 下满足尺寸契约；真实浏览器结合实际变换验证屏幕大小，不能只读取未变换的字体样式。
2. 在 75%、100% 与三个封顶倍率两侧连续缩放，验证尺寸连续、无突然隐藏、低于 75% 仍继续缩小。
3. 覆盖长名称、完整视频元信息、缺失元信息和极窄竖图，验证标题不撑宽、单行截断、图标文字不被纵向裁切。
4. 在选中、拖动、连线和媒体加载期间缩放，验证位置和状态稳定、连接点与内容区关系正确、工具栏不遮挡标题。
5. 回归正文内部滚动、播放器操作、工具栏原有大小行为、内容区比例及画布 50%～800% 范围；不将本次测试扩展为无关功能重写。

## Out of Scope

1. 文本正文、媒体内容、音频播放器和操作工具栏的缩放大小策略。
2. 扩大 Canvas 缩放范围、修改默认视口或新增缩放控件。
3. 自定义命名、自动编号、元信息内容变化和新的标题信息项。
4. 自动排列、避让、改变既有卡片位置或内容区尺寸策略。
5. 其他类型节点、后端/API/数据库变更及用户自定义阈值设置。

## Further Notes

本需求为 IKDICP 四类卡片布局优化后的独立体验迭代。用户已确认所有设计决策及测试入口，可进入任务拆分和实现；此 spec 发布不代表产品代码已实现。

本地设计规格与工单正文保持一致。本次为可逆展示策略，不创建架构 ADR，也不将通用缩放技术术语加入领域词汇表。
