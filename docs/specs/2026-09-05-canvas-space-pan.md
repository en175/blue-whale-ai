# Canvas 空格平移交互约定

## 时间

2026-09-05

## 背景与目标

选择模式下，空格键原本只启用 React Flow 的视口平移，没有关闭节点拖拽。
用户从卡片主体开始拖动时仍会移动卡片。修复后，鼠标按下时的操作意图决定
整个手势，避免误改卡片位置。

以下边界由用户在本次 `grill-with-docs` 对齐中确认（Q1–Q3 均采用建议）。

## 行为约定

| 场景 | 预期行为 |
| --- | --- |
| 选择模式，未按空格，从卡片主体按下左键并拖动 | 移动卡片 |
| 先按空格，再从卡片主体、图片、正文或内部按钮按下左键并拖动 | 平移 Canvas 视口；节点坐标和选中集合不变 |
| 空格平移期间点击卡片内部按钮 | 不触发按钮，不触发节点点击或空白点击行为 |
| input、textarea 或可编辑正文有焦点时按空格 | 保持文字输入，不接管为平移 |
| 已按下鼠标开始拖卡片，再按空格 | 本次继续拖卡片；松开鼠标后，下次手势重新判断 |
| 已按下鼠标开始平移，先松开空格 | 本次继续平移；松开鼠标后恢复当前工具模式 |
| 工具栏已选拖拽模式，再按下并松开空格 | 仍保留工具栏拖拽模式 |
| 窗口失去焦点 | 清理临时空格状态，防止松键事件丢失后卡在平移模式 |
| 抓手态（空格按住或工具栏拖动模式），在卡片几何范围（含组内与组框空白）按下左键并拖动 | 平移视口；不选中、不补选中任何卡片，既有选中集合保持不变 |
| 抓手态，组框空白处按下拖动 / 双击组内空白 | 整体让位给平移：不拖动整组、不进入组内编辑 |
| 抓手态，点击组徽标、组操作条、缩放控件、小地图 | 控件照常响应，不受抓手态影响 |

“卡片移动”改变节点的布局坐标；“视口平移”改变用户看到的 Canvas 位置，
不改变节点的布局坐标。沿用现有 Canvas 与节点术语，不新增领域实体。

## 实现与验证

空格与工具栏拖拽在 Canvas 容器统一决定是否平移；卡片无需各自监听空格。
鼠标按下时固定操作，鼠标松开后的点击处理结束后解除固定。保留现有
空格加滚轮平移能力。

自动回归使用真实 React Flow 与卡片组件，覆盖按键状态、视口和节点坐标、
编辑焦点、按钮点击、选中状态与手势期间的模式固定。jsdom 不执行 CSS 命中测试，
因此从卡片及其内部控件开始拖动的鼠标命中行为仍需在浏览器人工回归。

定向测试：

```sh
cd web
npm test -- src/pages/CanvasPage/components/Canvas/spacePan.test.tsx
```

人工验收：在 `/canvas` 放置图片、生成卡、文本节点，逐项执行上表场景；
尤其检查按钮上起拖、框选多个节点后从选中区域起拖、先松空格后松鼠标、
文字编辑中输入空格。

此修复是可逆的交互行为校正，不引入新的架构取舍，因此不新增 ADR。

## 2026-10-01 选中泄漏回归（IKJFH1）

**现象**：抓手态在卡片上按下左键拖动，画面平移了，但被点击的卡片同时被选中
（出现选中态与工具条联动），与上表「节点坐标和选中集合不变」相悖。

**根因一（框选武装未关门）**：抓手态节点层 `pointer-events: none`，点击穿透到 pane；
React Flow 的框选武装（`selectionOnDrag`）未排除抓手态，穿透拖动被当作框选，
矩形扫过的卡片被选中。
修复门：`selectionOnDrag` 在既有排除（参考选取、整组拖动）同位置追加抓手态条件。

**根因二（组框穿透补选中）**：GroupOverlay 在「几何命中卡片但事件 target 落在 pane」时
执行程序化补选中（组框穿透分支，含 `groups: []` 的无组画布——空数组同样挂载
GroupOverlay）；抓手态下点击必然穿透，因此必触发，按下即刻选中。
修复门：GroupOverlay 接收抓手态标识（`isPanning`，与框选门共用同一抓手状态来源），
抓手期间 window 捕获的 pointerdown 与 dblclick 处理器整体放行——补选中、双击进编辑、
组框拖组三类内容区交互一并让位，事件穿透到 pane 由平移接管。
组徽标、组操作条、缩放控件、小地图等控件层不受影响。

**验证口径**：jsdom 集成测试锁定外部行为（选中集合与视口变化）——
spacePan 族新增「空格/工具栏拖动模式穿透平移不选中未选中卡、既有选中保持不变」
（pointer 序列武装框选 + mouse 序列驱动平移，节点需显式 width/height 供几何命中）；
GroupOverlay 族新增「抓手态穿透卡盒不补选中、组空白不拖组、双击不拦截」。
jsdom 不执行 CSS 命中测试，穿透行为的最终确认走浏览器人工回归：
按上方行为约定表逐项执行，重点新增「未选中卡上按空格起拖，全程不出现选中」。
