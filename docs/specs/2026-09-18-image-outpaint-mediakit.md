# 图片扩图（火山 AI MediaKit 智能扩图）规格

> 需求共识来自 2026-09-17 两轮 grilling（15 项拍板，Kim 已确认）。需求工单 IKGOQ0（ready-for-agent）。术语以根 CONTEXT.md「画布图片扩图」节为准，关键取舍见 ADR-0093。

## Problem Statement

用户在画布上拿到一张图片后，经常需要改变画面比例或构图：竖图想变横图做封面、方图想加出血做海报、主体太挤想留出文案空间。现有能力只能重新生成或去外部工具处理，无法在画布上对一张已有图片直接向外扩展画面，更做不到扩展区域与原图内容自然衔接。

## Solution

图片素材卡悬浮工具条的「高清放大」按钮升级为带下拉的「高清 ▾」菜单，菜单含「高清」（既有高清放大，行为不变）与「扩图」两项。点「扩图」后源图卡进入扩图模式：卡上出现 4 边 + 4 角的可拖拽扩展框，用户在原图上直接拖出想要扩展的范围（只允许向外扩，框永远完整包住原图），卡片下方同时浮出扩图面板，提供比例预设（原图比例 / 1:1 / 4:3 / 3:4 / 16:9 / 9:16，手动拖拽后显示「自定义」状态）与发送入口。发送后系统经 new-api 网关的 MediaKit 渠道调用火山引擎 AI MediaKit 智能扩图接口，按四个方向的扩展比例补全原图外区域，生成一张扩图结果卡并与源卡拉一条来源连线。源卡不动。本期扩图免费：不显示积分预估，也不扣用户余额（网关上该工具单价配 0）。

## User Stories

入口与菜单：

1. 作为创作者，我希望选中一张图片卡后，工具条上的「高清放大」变成「高清 ▾」下拉按钮，以便在一个入口里找到画面增强类能力。
2. 作为创作者，我希望点开下拉后看到「高清」和「扩图」两项，不看到尚未实现的功能，以免误点。
3. 作为创作者，我希望点「高清」的行为与此前的「高清放大」完全一致，不受本次改造影响。
4. 作为创作者，我希望只有图片卡显示该入口，视频卡、音频卡、文本卡不显示。
5. 作为创作者，当卡片正在生成、已失败或素材缺失时，我希望看不到该入口（沿用工具条既有口径）。
6. 作为创作者，多选卡片时我不看到该入口（与工具条整体口径一致）。
7. 作为创作者，当源图长边超过 4160px 或文件超过 10MB 时，我希望「扩图」菜单项置灰并悬停告诉我原因，而「高清」项是否可用不受扩图门槛影响。
8. 作为创作者，当图片真实尺寸信息缺失时，我希望「扩图」置灰并说明原因，而不是进去之后才发现不能用。
9. 作为创作者，我希望点空白处、点菜单外区域或再点一次按钮都能收起下拉菜单，与其他下拉一致。

扩图模式与扩展框：

10. 作为创作者，点「扩图」后我希望原图卡上立刻出现带手柄的边框，下方浮出参数面板，初始边框与原图重合，一眼明白「往外拖就是扩」。
11. 作为创作者，我希望拖动 4 条边的手柄可以单独向外扩展对应方向，拖到与原图边缘重合就停下来（不允许拖进原图内侧）。
12. 作为创作者，我希望拖动 4 个角可以同时调整宽和高，自由改变比例。
13. 作为创作者，我希望按住 Shift 拖角时按开始拖动那一刻的比例等比外扩，不按 Shift 时自由调整。
14. 作为创作者，我希望不按 Shift 的手动拖拽后，面板上的比例位置显示为「自定义」，让我知道当前不是标准比例。
15. 作为创作者，我希望每个方向最多能扩到原图短边的 40%，拖到极限就拖不动，而不是发送后才发现超限失败。
16. 作为创作者，我希望扩展框永远完整包住原图，不会出现框把原图裁掉一块的状态。
17. 作为创作者，拖框时我希望面板上的比例状态实时跟着变（命中预设就高亮预设，否则显示自定义）。
18. 作为创作者，扩图模式期间我希望画布的平移和缩放仍然可用，方便我调整视野看全扩展范围。
19. 作为创作者，扩图模式期间我不希望误拖动其他卡片或触发框选，免得把刚调好的框弄乱。

退出扩图模式：

20. 作为创作者，我希望点面板上的 X 退出扩图模式，边框和面板消失，图片卡回到普通选中态。
21. 作为创作者，我希望按 Esc 也能退出，与其他面板的关闭习惯一致。
22. 作为创作者，我希望点选其他卡片时自动退出扩图模式并选中那张卡。
23. 作为创作者，我希望点画布空白处也能退出扩图模式。
24. 作为创作者，只要我还没点发送，退出就不留下任何痕迹：不建卡、不连线、不产生任务。
25. 作为创作者，退出后再次点「扩图」进入时，我希望从零开始（边框与原图重合、默认原图比例），不残留上次的拖拽状态。

面板与参数：

26. 作为创作者，我希望参数面板跟随在源图卡下方，拖动卡片时面板跟着走。
27. 作为创作者，我希望比例下拉提供原图比例、1:1、4:3、3:4、16:9、9:16 六个选项，覆盖主流平台尺寸。
28. 作为创作者，进入扩图模式时我希望默认选中「原图比例」，边框与原图重合。
29. 作为创作者，点 1:1、16:9 这类预设后，我希望边框以原图中心为锚点自动外扩到「能完整包住原图的该比例最小框」，不用我手工对齐。
30. 作为创作者，点「原图比例」时我希望边框收回到与原图重合，等于一键重置。
31. 作为创作者，当某个比例预设对当前图片达不到（受每方向 40% 上限限制）时，我希望该项置灰并悬停说明原因，而不是选了之后得到一个不对的比例。
32. 作为创作者，我希望「自定义」只是手动拖拽后的状态展示，不是一个可以主动点选的选项；点任一预设就退出自定义。
33. 作为创作者，我希望张数位置显示「1张」且不可更改，知道多张生成还没开放。
34. 作为创作者，本期我不想看到积分预估数字，也不希望余额因此减少（面板显示「本期免费」）。
35. 作为创作者，当边框与原图重合（没有扩展任何内容）时，我希望发送按钮置灰，避免发出一个什么都不做的任务。
36. 作为创作者，我希望面板上没有分辨率、画质档位、提示词、参考素材这些与本功能无关的控件。

提交与结果：

37. 作为创作者，点发送后我希望画布上立刻出现一张扩图结果卡显示生成中，离开或刷新页面任务不丢。
38. 作为创作者，我希望结果卡与源卡之间自动出现一条连线表示来源，但它不占用参考位、不参与 @ 编号。
39. 作为创作者，发送成功后我希望扩图模式自动退出，我可以直接看结果卡的进度。
40. 作为创作者，成功后我希望结果卡展示扩展后的完整画面（原图加 AI 补全区域），并能看到新的分辨率。
41. 作为创作者，我希望源卡内容全程不变。
42. 作为创作者，我希望扩图结果自动进入我的资产库，可以在别处继续使用。
43. 作为创作者，失败时我希望在结果卡上看到失败状态和能读懂的原因，并提供重试入口，重试沿用上次参数。
44. 作为创作者，我希望能对扩图结果卡再发起扩图或高清放大，形成链式处理。
45. 作为创作者，我希望扩图结果卡的生成图片、生成视频、下载、@、删除、复制等操作与普通图片卡一致。

## Implementation Decisions

前端：

- 工具栏「高清放大」按钮改为「高清 ▾」下拉按钮，菜单只含「高清」「扩图」两项；节点工具栏此前无下拉先例，交互模式参考左侧工具栏的按钮加弹出菜单（点外关闭）与共享的点外关闭 hook，可见性沿用既有工具条可见性机制的图片专属键。
- 「扩图」菜单项按当前图片做可用性预检（源图长边 ≤4160px、文件 ≤10MB、真实宽高已知），不满足时置灰并悬停说明，与高清放大版本档门槛同口径。
- 扩图模式是新的画布会话状态，管理模式参考既有框选参考会话（统一退出函数、Esc 优先级链、点空白处置）；模式期间禁用框选与其他卡片拖动，画布平移缩放保留。
- 扩展框为自研的屏幕空间覆盖层（仓内无节点级 resize 设施，参考对齐吸附线与整组拖动把手的做法）：4 边 + 4 角手柄，框永远包住原图，每方向扩展量钳制在 [0, 原图短边 40%]；拖边单边调整，拖角自由比例，Shift 拖角锁定开始拖动那一刻的比例。
- 拖拽的像素扩展量实时换算为四个方向的扩展比例（相对原图短边），这是提交参数的唯一来源；比例预设命中判定、最小包含框计算（以原图中心为锚）、预设可达性判定（受 40% 上限约束）都是纯函数，便于测试。
- 扩图面板是新的轻量面板组件，骨架照搬高清放大面板（跟随锚定、统一关闭体系、防回弹、Esc 链、置灰守卫、底栏「本期免费」文案与发送钮）；比例选项用共享宽高比图标组件渲染；张数控件禁用展示固定「1张」；无积分预估、无分辨率、无档位、无提示词与参考栏。
- 进入扩图模式不建卡；点发送时才创建扩图结果草稿卡并拉纯视觉来源线（连线来源标记与高清放大同族，不参与参考推导与 @ 编号），发送成功即退出模式；结果回填走既有通用轮询；重试沿用现有重试分流（上次参数重发创建接口）。
- 前端任务类型联合扩展新类型 image_outpaint；提交时冻结源素材身份与四个扩展比例。

后端（NestJS）：

- 新增生成任务类型 image_outpaint（任务类型字段是自由字符串，无需数据库迁移）。
- 创建路径仿 image_enhance 的独立轻量入口：直接落任务，不写成本预留、不接成本估算、不走素材库合规门、不经余额拦截（免费工具口径同 media_extract / image_enhance）。
- 服务端复核全部参数合法性：四个扩展比例值域 [0, 0.4] 且至少一个大于 0、源素材归属与媒体类型、源图长边 ≤4160px、文件 ≤10MB；前端预检只是体验层，不作权威。
- 供应商调用经 blue-whale-api 网关的 MediaKit 渠道（同步路由，对客模型名 mediakit-expand-image-canvas），不在本仓直连火山、不新增凭证配置项；渠道与上游 API Key 在网关侧配置（见 Further Notes）。

执行（worker-java）：

- 新增一个 MQ tag 与对应的消费者/处理器（以 image_enhance 接线为模板），含领取 SQL 与 CAS、租约、恢复扫描、终态收口 payload 组装；任务来源白名单登记新来源。
- 调用网关同步路由 POST {网关地址}/v1/mediakit/sync/expand-image-canvas，鉴权与图片生成同构（携带任务冻结的用户 sk-）；入参映射为 image_url（源素材公网对象存储地址）与 expand_top / expand_bottom / expand_left / expand_right 四个比例值；queue_id 不传，用默认队列。
- 响应成功即下载结果图（URL 仅 24 小时有效，须立即落对象存储并设公开读），随后建 Asset、终态收口、向前端投影进度，全链路与高清放大任务同构。
- 调用失败、超时、供应商错误（网关对 success=false 返 400 且不扣费）统一映射到任务失败与既有错误码投影，不提供自动重试，由用户在结果卡手动重试。
- 参数快照随任务输入冻结，重试沿用首次提交参数。

契约与数据：

- 无数据库 schema 变更；任务输入冻结在既有任务记录的 input 字段。
- 跨进程字段（任务类型、来源值、四个扩展比例键名、连线来源标记）先在契约文档定死后双端实现，遵守「同族工单串行、契约先行」。

## Testing Decisions

好测试的标准：只测外部可见行为（渲染结果、提交参数、状态流转、错误呈现），不测内部实现细节；一份视觉/口径定义只在一处断言，防漂移断言用于「两处必须同源」的约定。

- 前端组件与画布链路（vitest + jsdom）：下拉菜单两项渲染与置灰矩阵（卡类型 × 卡状态 × 源图门槛）、扩图模式进入与四种退出、扩展框拖拽换算（拖边/拖角/Shift 锁比例/40% 上限钳制/永远包住原图）、比例预设联动（默认原图比例、最小包含框、不可达置灰、自定义被动状态）、面板字段（张数禁用、本期免费、零扩展发送置灰）、提交 payload 冻结内容、发送后建卡与连线。既有先例：高清放大面板组件测试、对齐吸附纯函数测试、宽高比共享组件防漂移断言。
- 后端创建入口：参数校验矩阵（四比例值域与至少一项为正、源素材归属与媒体类型、长边与大小门槛复核）、免费口径（无成本预留、不经余额拦截）、任务输入冻结。既有先例：image_enhance / media_extract 服务测试。
- worker-java：MediaKit 扩图请求映射与错误分类（mock 网关端点）、结果下载落库与 Asset 创建、终态收口事件；以接口级 mock 隔离真实网关调用。既有先例：高清放大处理器单测。
- 契约层：任务类型、参数键名与来源标记的双端一致性断言（同 IKGM8U 打法）。

## Out of Scope

- 分辨率选择（1K/2K/4K），含「扩图后自动串联高清放大」的组合链路；需要更大图时用户对结果卡再点一次高清放大即可。
- 一次生成多张（张数控件仅禁用展示留位）。
- 多次串联扩图突破单方向 40% 上限（如 9:16 竖图扩成 16:9 横图）。
- 向内裁剪（框永远包住原图；裁剪是菜单中留给未来的独立动作）。
- 重绘、擦除、抠图、裁剪菜单项（菜单本期只放高清与扩图）。
- 积分预估展示与实际扣费（后续单独工单一并补上，同高清放大口径）。
- 队列分账（queue_id）、视频画面扩展、后台配置界面。

## Further Notes

- 上线前置条件在网关（blue-whale-api）侧：网关新增 expand-image-canvas 同步工具（对客模型名 mediakit-expand-image-canvas），本期 model_price 配 0 即免费，复用高清放大已配置的 MediaKit 渠道与平台级 API Key。注意网关同步工具未配价会被硬拦 400，免费形态是配零价而不是不配价；网关缺工具或缺定价时，本侧任务以失败呈现。配置动作建议照高清放大网关单（IKGOKL）同流程办理。
- MediaKit 结果图 URL 有效期 24 小时，执行侧必须在响应后立即下载落库，这一约束已在 ADR-0092 / ADR-0093 记录。
- 计费粒度已知限制同高清放大：网关按模型名按次计费；本期免费无影响，放量前须补计费工单。
- 本期免费期间火山账单由平台自担。
- 接口四个扩展参数官方默认各 0.1，但本产品总是显式传值（初始框零扩展即传 0），不依赖官方默认。
- 供应商同步接口，处理耗时数秒级，与高清放大同量级。
