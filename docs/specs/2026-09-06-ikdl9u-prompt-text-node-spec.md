# Prompt 预览、文本节点与连线生成规格

## 时间

2026-09-06

## 状态

关联需求：IKDL9U。产品设计、Q4–Q14 及测试边界均已由用户确认；用户授权以本规格直接覆盖原工单正文，并标记 ready-for-agent。
本规格编写不包含产品代码实施、子任务创建或产品发布。

## Problem Statement（问题陈述）

用户在无限画布中创作，希望让 Agent 整理 Prompt，再自由组合文本和媒体输入完成生图、生视频。
当前生成卡却要求用户理解“画面”和“提示词”两份正文，以及应用、引用到 dock、给 Agent 等重复或含糊的动作。
修改画面不影响生成，画布中修改的提示词又没有随原卡片版本指针一起交给 Agent；用户无法判断哪份内容真正生效。

画布连线目前只表现为局部交互，未在已核对的保存和生成入口中形成持久化输入关系。现有生成卡固定进入视频入口，无法表达由用户决定生图或生视频的创作方式。卡片到生成请求的转换也没有完整保留文本来源与当次正文。

本需求要消除这套特殊生成卡工作流，让用户看见的文本、连接的输入与实际使用的生成内容一致。

## Solution（解决方案）

Agent 根据用户资料、回复和上下文整理最终 Prompt，在 Agent 面板先展示预览。用户不满意就继续用自然语言修改，满意后手动点击“应用”，在 Canvas 中得到普通文本节点。

文本节点只有标题和一份可编辑正文。用户将其连至生图或生视频目标，作为文本附件提供上下文；多个文本附件可以排序，图片素材必须独立连入。目标节点自己的提示词表达本次任务，与附件共同生效；仅有文本附件也允许生成。

用户选中目标，在生成面板检查附件、填写补充提示词、设置模型参数，再手动生成。每次提交使用文本当前正文并冻结快照；编辑、断开或删除来源不改写已提交任务。Agent 后续修改仍产出新预览，经手动应用形成新节点。

## User Stories（用户故事）

### Agent 产出与预览

1. 作为创作者，我希望通过自然语言提供需求和资料，以便 Agent 整理可复用的 Prompt。
2. 作为创作者，我希望先在 Agent 面板预览 Prompt，以便在进入画布前检查内容。
3. 作为创作者，我希望不满意时继续让 Agent 修改，以便逐步得到符合意图的 Prompt。
4. 作为创作者，我希望只有手动应用才创建画布文本节点，以便自主决定哪些内容进入画布。
5. 作为创作者，我希望每条 Prompt 独立预览和应用，以便从多镜头方案中选择所需内容。

### 应用身份与版本

6. 作为创作者，我希望同一预览重复应用时定位原节点，以便不会产生重复内容。
7. 作为创作者，我希望新版预览应用时创建新节点，以便保留旧方案及其连线。
8. 作为创作者，我希望 Agent 修改不会自动覆盖已应用节点，以便现有创作流保持稳定。
9. 作为创作者，我希望删除已应用节点后可以再次应用原预览，以便重新使用该 Prompt。
10. 作为创作者，我希望重新应用已删除节点时不恢复旧连线，以便重新决定它的用途。

### 文本内容与编辑

11. 作为创作者，我希望文本节点只有标题和一份正文，以便不必判断画面与提示词哪个生效。
12. 作为创作者，我希望直接编辑正文并使用换行、复制和粘贴，以便快速调整 Prompt。
13. 作为创作者，我希望长内容可以折叠查看和展开编辑，以便兼顾画布浏览与全文修改。
14. 作为创作者，我希望超出限制时得到明确提示，以便不会在不知情时丢失文本。
15. 作为创作者，我希望编辑并刷新后仍能看到保存的内容，以便继续创作。

### 文本连线与附件

16. 作为创作者，我希望同一文本可以连接生图或生视频目标，以便由我决定生成类型。
17. 作为创作者，我希望同一文本可以供多个目标使用，以便复用角色设定等共同背景。
18. 作为创作者，我希望一个目标可以接收多个文本附件，以便组合角色、场景和镜头要求。
19. 作为创作者，我希望在目标中查看附件并调整默认连入顺序，以便明确上下文组织方式。
20. 作为创作者，我希望同一文本对同一目标不重复添加，以便避免重复输入。

### 目标提示词与媒体输入

21. 作为创作者，我希望文本附件与目标提示词共同生效，以便同时提供背景和本次任务。
22. 作为创作者，我希望仅有文本附件时也能生成，以便不必重复填写完整 Prompt。
23. 作为创作者，我希望图片只有在独立连入目标时才参与生成，以便能从连线看清实际素材输入。
24. 作为创作者，我希望选中目标后设置该类型的模型和参数，以便生图不会误入视频操作流程。
25. 作为创作者，我希望点击生成才执行，以便连接或编辑不会意外启动任务。

### 当前内容与历史事实

26. 作为创作者，我希望每次生成使用当前文本正文，以便下一次生成反映最新修改。
27. 作为创作者，我希望当次文本与最终参数被保存，以便查清结果使用了什么输入。
28. 作为创作者，我希望之后修改来源不会改变已提交任务，以便历史结果仍有准确解释。
29. 作为创作者，我希望断开或删除来源后下一次不再使用它，以便控制当前输入集合。
30. 作为创作者，我希望刷新后恢复连线和附件顺序，以便不必重新搭建创作关系。

### 回到 Agent 继续修改

31. 作为创作者，我希望通过统一的“添加到对话”入口引用文本，以便不用分辨重复按钮。
32. 作为创作者，我希望 Agent 得到引用当时的正文，以便它能看到我在画布上的修改。
33. 作为创作者，我希望之后编辑画布不改写已发送的引用内容，以便对话依据保持清楚。
34. 作为创作者，我希望 Agent 修改后展示新预览，以便先检查再应用。
35. 作为创作者，我希望应用新预览保留旧节点的用途，以便比较和独立使用不同方案。

### 旧卡片与日常操作

36. 作为已有项目用户，我希望旧生成卡转为普通文本节点，以便统一后续创作方式。
37. 作为已有项目用户，我希望迁移保留标题、位置与实际提示词，以便不丢失原有编排和内容。
38. 作为已有项目用户，我希望旧画面描述及其编辑可以在历史记录中查阅，以便重要内容不会消失。
39. 作为创作者，我希望文本节点继续使用普通节点的选择、拖动和删除方式，以便不用学习特殊卡片操作。
40. 作为创作者，我希望应用失败后重试不会制造重复节点，以便可以安全恢复操作。

## Implementation Decisions（实现决定）

### 职责与现有架构

1. Agent 面板负责沟通、预览与修改，不承担媒体生成；Canvas 负责文本节点和连线编排；目标生成面板负责参数与显式提交。
2. 复用现有普通文本节点、画布交互、图片与视频参数面板、生成任务和持久化能力。新增输入语义，不引入独立“生成卡”资源类型或第二套卡片编辑器。
3. 业务 API 与持久化继续归独立 NestJS 产品后端；沿用 Prisma 及共享契约。按 ADR-0074、ADR-0075 的现行边界接入生成流水线，不恢复退役运行时或改造队列技术栈。
4. 独立 Agent 服务继续拥有预览产出，本仓通过现有集成边界消费；以稳定预览身份与实际正文对齐协议，不以旧 revision 指针替代当前文本。跨服务契约先于功能实施对齐。
5. 此规格在本场景取代旧“应用卡片直接进入 dock”、双字段正文与连线仅作展示的行为约束；保留与本需求无冲突的节点布局、编辑、媒体能力及项目权限规则。

### 预览、应用与普通文本节点

1. 一条预览对应一份 Prompt 正文与稳定的来源身份；多条预览分别应用。本轮无整组应用，无应用后自动生成。
2. 应用结果持久关联预览与创建的文本节点。节点仍存在时，同一预览的重复点击、重试和刷新后应用都返回或定位它；不能只凭前端内存去重。
3. 新预览创建新节点；原节点删除后，原预览可以重新创建节点，但不恢复旧连线。应用的重复请求不得同时创建多个有效结果。
4. 正文以用户确认的 Prompt 初始化，此后画布正文独立可编辑；Agent 继续修改不自动覆盖它。只有一份可写正文，格式渲染不成为另一份提示词。
5. 保留标题、换行、复制粘贴及普通节点操作；长文预览与全文编辑区分。兼容现有编辑器时必须正确提取实际文本，不能把 HTML 标记作为上下文送给模型。

### 连线与附件持久化

1. 用户能建立文本节点到生图或生视频目标的直接连接；同一文本可供多个目标使用。目标拥有明确生成类型，连接文本不会强制改成视频。
2. 持久保存来源、目标及附件顺序，使刷新或重新打开后仍能恢复。当前只有局部连线状态的实现不足以验收。
3. 一个目标的多个文本附件默认按连入顺序排列，用户可调整；按来源节点身份去重，不按正文或同名标题合并不同节点。
4. 只消费直接连入目标的文本与显式媒体输入，不沿文本的历史素材引用隐式传递图片，也不递归执行上游图。
5. 断开或删除来源后，后续提交不再消费该附件；已有任务快照不受影响。文本及图片引用沿用项目归属、权限与模型能力验证。

### 生成输入与快照契约

| 边界 | 必须表达的事实 | 可观察结果 |
| --- | --- | --- |
| 预览应用 | 预览来源、创建的节点、重复应用结果 | 重试与刷新后不重复创建；删除后可重新应用 |
| Canvas 保存与读取 | 节点当前正文、连线来源及目标、附件顺序 | 重新打开恢复内容和输入关系 |
| 目标提交 | 目标类型、目标提示词、模型参数、有序文本来源与正文、显式媒体输入 | 两类目标使用实际配置和连接输入 |
| 生成任务接纳 | 当次文本快照、最终参数、文本节点与预览来源（存在时） | 来源修改或删除后仍可解释该次生成 |
| 添加到对话 | 操作当时的正文快照及来源信息 | Agent 接收实际编辑内容，后续修改不改写已发送上下文 |

1. 生成前处理当前文本保存与读取的一致性，冻结同一次接纳所使用的正文、顺序、目标提示词和参数；不得使用打开面板时的过期缓存，也不能静默漏掉未保存的编辑。
2. 文本附件与目标提示词在产品契约中分别表达。只有附件时允许提交；不把“目标提示词非空”当作唯一文本输入条件。全部有效文本为空时仍沿用实际生成能力的输入校验。
3. 供应商适配可根据已有接口能力将有序文本上下文与目标提示词确定性组织为实际请求，不要求供应商原生支持文本文件上传，不额外引入隐藏的模型改写步骤。实际请求内容应可与已冻结的产品输入对应。
4. 服务端接纳任务时确定快照，执行和已有任务重试不回读来源的最新文本；用户再次发起新生成才读取最新正文。只在用户点击目标的生成动作时提交。
5. 保存与模型输入限制分别处理，端到端统一校验并给出明确错误；超过限制不能静默截断或删除附件。具体数值依据当前模型能力及存储契约落实，不虚构统一无限长度。

### 添加到对话与旧数据迁移

1. 统一保留“添加到对话”操作。引用时捕获当前正文，不再提供功能相同的“给 Agent”入口，也不继续依赖原始卡片版本取回正文。
2. Agent 的修改结果回到新 Prompt 预览，继续遵循手动应用和新节点规则；对话中的正文快照不随来源后续编辑或删除而被改写。
3. 旧画布生成卡迁移为普通文本节点：保留标题、位置以及迁移时实际保存的提示词正文，不从 Agent 原始版本覆盖用户编辑。
4. 旧画面描述及用户编辑在可查阅的只读历史中保留；迁移必须先保存历史内容再完成转换，重复执行不得新增重复节点或覆盖已迁移后的编辑。无来源记录的普通文本仍可正常使用，不伪造预览来源。
5. 历史预览可通过兼容映射提供单正文预览和应用；旧资料缺失或损坏应明确反馈并保留原数据，不用画面描述静默代替缺失提示词。具体数据结构与版本变更在实施前形成相互匹配的契约，不保留两套活动生成卡流程。

## Testing Decisions（测试决定）

### 测试边界确认

当前状态：用户已明确确认以下测试边界，作为实施与验收依据。

主要验收入口为真实浏览器中的 Agent 面板与 Canvas 完整用户流程，使用真实业务 API 和测试持久化，只在外部 Agent 与生成供应商边界使用可控替身。围绕“应用—编辑—连接—目标提交—刷新恢复”组织场景，不为每个内部组件或 helper 新建验收边界。

服务端公开接口集成测试作为补充，验证浏览器难以稳定制造的重复请求、快照一致性及旧数据迁移。优先复用现有业务服务和存储边界，不为测试重写生产行为。

### 有效测试与既有先例

1. 断言用户看到的正文、附件列表、顺序、节点数量、操作结果，以及公开接口可读取的任务与历史事实；不测试内部 state、组件层数或私有函数调用次数。
2. 现有文本节点浏览器测试覆盖编辑、保存、拖动、删除与刷新恢复；媒体节点浏览器测试覆盖目标呈现和操作，可复用它们的页面驱动与异常请求检查方式。
3. 这些已有浏览器测试模拟业务 API，仅能证明前端行为；本需求不能把这种模拟当作持久化、服务端去重和真实生成输入正确的证据。
4. 自动化生成使用可记录请求的外部替身，分别断言图片与视频接收到的文本、顺序、目标提示词及媒体引用，不以随机成片视觉质量判断文本是否实际送达。
5. 保留现有画布选择、拖动、文本编辑和媒体状态回归；不以 DOM/CSS 快照或纯映射函数测试代替完整交互与接口事实验证。

| 旧卡迁移与重复执行 | 标题、位置、实际提示词、历史画面描述完整保留，不重复转化 | 公开接口集成＋浏览器查阅 |

## Out of Scope（范围之外）

1. 整条创作流程自动运行、递归执行、连线或编辑自动生成，以及 Agent 直接创建媒体生成任务。
2. 整组 Prompt 一键应用、Agent 自动覆盖已应用节点、两份可写画面与提示词正文。
3. 文本节点自动传递图片素材、新共享资产库、完整文本版本管理或协同编辑产品。
4. 重做画布整体视觉与布局、替换模型供应商或队列技术、修改既有计费与审核职责。
