# 图片擦除（火山 AI MediaKit）规格

> 需求共识来自 2026-09-17 至 2026-09-18 两轮 grilling（14 项拍板 + 2 项技术设计，Kim 已确认共享理解）。需求工单 IKGOSZ（ready-for-agent）。术语以根 CONTEXT.md「画布图片擦除」节为准，关键取舍见 ADR-0094。

## Problem Statement

用户在画布上生成或上传的图片里常有想去掉的内容：多余的路人、水印、杂物、字幕或文字。目前画布没有任何图像局部处理能力，用户只能把图导出到外部工具处理再传回来，或者接受瑕疵。用户希望能直接在图片卡上涂抹或框选不想要的部分，或者一键清掉图中所有文字，AI 自动把抹掉的区域填成自然的背景，且不离开画布。

## Solution

图片素材卡悬浮工具条的「高清放大」按钮改为下拉菜单「高清 ▾」，菜单新增「擦除」入口。点击后源图卡进入擦除编辑态：卡上方浮出擦除工具条（「清除文字」一键按钮、画笔、框选、橡皮擦、笔刷大小、撤销重做），卡下方跟一条窄条（「本期免费」+ 发送钮）。用户用画笔涂抹或框选标出想去掉的区域（棋盘格标示），或直接点「清除文字」一键擦除全屏文字，然后发送。系统经 new-api 网关的 MediaKit 渠道调用火山引擎 AI MediaKit 图像擦除修复接口，把抹除区域智能填充后产出一张新的擦除结果卡，与源卡拉一条纯视觉来源线。源卡不动，结果卡是普通图片素材卡，可以再次擦除、扩图、高清放大。本期擦除免费：不显示积分预估，也不扣用户余额。

## User Stories

入口与菜单：

1. 作为创作者，我希望图片卡工具条上的「高清放大」变成下拉菜单「高清 ▾」，以便在同一位置找到所有画质类工具。
2. 作为创作者，我希望菜单里有「高清」和「擦除」两项，「高清」就是原来的高清放大，行为不变。
3. 作为创作者，我希望只有正常状态的图片卡在唯一选中时能看到该菜单，视频卡、音频卡、文本卡与多选时不显示。
4. 作为创作者，当我的图超过 2560×1440 或超过 10MB 时，我希望「擦除」菜单项置灰，悬停告诉我原因。
5. 作为创作者，当我的图是 webp 或 gif 格式时，我希望「擦除」置灰并说明该格式不支持擦除。
6. 作为创作者，当图片尺寸信息暂时缺失时（存量老图），我希望「擦除」不置灰，图片加载后系统会自动补上实测尺寸再判断。

擦除编辑态：

7. 作为创作者，点「擦除」后我希望源图卡上方出现擦除工具条，下方出现发送条，一眼知道进入了擦除状态。
8. 作为创作者，我希望用画笔在图片上直接涂抹想去掉的内容，涂抹区域显示为棋盘格。
9. 作为创作者，我希望调节笔刷大小，以便既能涂大块区域也能描细小杂物。
10. 作为创作者，我希望用框选拉一个矩形来标记要擦除的区域，比涂抹更快。
11. 作为创作者，我希望可以涂多笔、拉多个框、框和涂抹混用，它们都叠加生效。
12. 作为创作者，涂错的地方我希望能用橡皮擦擦掉，而不是全部重来。
13. 作为创作者，我希望能撤销和重做我的涂抹操作，逐步回退误操作。
14. 作为创作者，我希望棋盘格不会完全挡住底下的画面，我还能看清自己涂到了什么。
15. 作为创作者，框落笔后我不期望能再拖动它，画错了撤销或擦掉即可，操作模型越简单越好。
16. 作为创作者，我希望我的画布视角不被打扰，需要放大涂抹时我自己滚轮缩放。
17. 作为创作者，我希望点 X、按 Esc、点其他卡、点画布空白都能退出擦除编辑态。
18. 作为创作者，只要我还没点发送，退出后我希望涂抹的内容全部丢弃，画布上不留任何痕迹、不产生任何提交。

清除文字：

19. 作为创作者，我希望工具条上有一个「清除文字」一键按钮，不用涂抹就能去掉图中所有文字。
20. 作为创作者，点「清除文字」后我希望它直接开始生成，和涂抹后点发送走同一条结果链路。

发送与结果：

21. 作为创作者，我希望点发送后才在画布上出现结果卡，发送前不建任何卡。
22. 作为创作者，我希望结果卡与源图卡之间自动出现一条纯视觉连线，看得出新卡从哪来，且不占用参考位、不参与 @ 编号。
23. 作为创作者，发送后我希望编辑态立即关闭，回到画布看结果卡的生成进度。
24. 作为创作者，生成中我希望结果卡显示生成中状态，离开或刷新页面任务不丢。
25. 作为创作者，成功后我希望被抹掉的区域被自然地填上背景，看不出痕迹。
26. 作为创作者，我希望结果卡的分辨率、比例与原图一致。
27. 作为创作者，我希望源图卡全程不变。
28. 作为创作者，我希望结果卡是 png 格式，能再次对它擦除、扩图、高清放大。
29. 作为创作者，我希望结果自动进入我的资产库，可以在别处继续使用。
30. 作为创作者，失败时我希望在结果卡上看到失败状态和重试入口。
31. 作为创作者，因源图超门槛被供应商拒绝时，我希望看到能读懂的失败原因。
32. 作为创作者，生成任务一旦发出我不期望能中途取消（同步接口），等几秒就有结果。

费用：

33. 作为创作者，本期我不想看到积分预估数字，也不希望余额因擦除而减少。

## Implementation Decisions

前端：

- 「高清放大」单按钮改下拉菜单「高清 ▾」，与 ADR-0093 的下拉改造同一次落地；菜单先放「高清」「擦除」两项，扩图就绪后插入中间，最终顺序 高清/扩图/擦除。可见性沿用既有工具条可见性机制（正常态图片卡唯一选中）。
- 菜单项门槛预检：图源超过 2560×1440、超过 10MB、或格式为 webp/gif 时「擦除」置灰并悬停说明原因；尺寸缺失（存量图 null）不拦，图片 onLoad 实测回填后再判定。预检口径与高清放大版本档门槛同源。
- 擦除编辑态是新的模式化交互（仓内无绘图设施，全部自研）：进入后接管源图卡区域的指针交互，不影响画布其他操作；退出途径为 X、Esc、点其他卡、点画布空白，未发送退出丢弃遮罩、不建卡不提交。
- 擦除工具条跟随源图卡上方浮出，承载「清除文字」一键按钮、画笔、框选、橡皮擦、笔刷大小滑杆、撤销重做；发送条跟随源图卡下方浮出，仅含「本期免费」与发送钮。跟随锚定、点外关闭、Esc 关闭等沿用既有面板约定。
- 遮罩模型为独立纯逻辑模块：笔迹与矩形框的叠加并集、橡皮擦除、撤销重做栈、棋盘格渲染数据；框落笔即固化进遮罩，无活框选中态；撤销/重做只作用于未发送的遮罩编辑。
- 发送时把全部框与笔迹按源图自然分辨率（非卡片显示尺寸）栅格化成一张黑白遮罩 PNG，复用既有资产上传链路取得公网 URL，随任务提交。
- 「清除文字」不经过遮罩：点击直接以「全屏文字擦除」场景发送，与涂抹发送共用同一条任务链路。
- 点发送才创建擦除结果卡并拉纯视觉来源线（区别于高清放大的草稿卡先行，与扩图同口径）；连线为纯视觉来源线，不进媒体索引与 @ 编号体系；发送即退出编辑态，结果卡生成中→成品/失败可重试沿用既有终态约定。
- 结果卡是普通图片素材卡（png），其工具条行为与高清放大、扩图、下载、@ 等与普通图片卡完全一致，可再次作为擦除/扩图/高清放大的源图。
- 本期不渲染积分预估；擦除提交不经过余额拦截门（免费工具口径同 media_extract、image_enhance）。

契约：

- 新增 image-erase 契约（与 image-enhance 契约同构、前后端共享）：任务类型常量 image_erase、来源标记、输入键枚举（源素材身份、擦除场景、遮罩素材身份）、擦除场景枚举（full_screen_text_erase / selected_area_erase）、输出格式固定 png、输入限制常量（≤2560×1440、≤10MB、png/jpg/jpeg/heic）。
- 契约附带防漂移对账测试，与 image-enhance 契约对账测试同打法；worker 侧镜像常量同例。

后端创建入口：

- 新增擦除任务创建入口（与高清放大创建入口同构）：请求方凭证冻结、zod 复核输入键、资产归属校验、尺寸/格式门槛复核（宽高 null 放行）、插 generation_jobs（type/source=image_erase）、入队失败回拨标记失败。
- 不写成本预留、不接成本估算、不走余额拦截门（本期免费口径同 image-enhancements）。

worker 执行：

- 复用 MediaKit 客户端链路，端点换为擦除同步接口，对客模型名 mediakit-erase-image，Bearer 用户凭证、X-Trace-Id、超时与错误分类同高清放大。
- 场景映射：full_screen_text_erase 不传遮罩与指定文字（擦所有文字）；selected_area_erase 只传 mask_url（不传 selected_area），遮罩 URL 为前端上传的遮罩素材公网地址。
- 请求固定 output_format=png（不取接口默认 webp）。
- 响应成功后在结果 URL 24 小时有效期内立即下载并转存对象存储，建成品 Asset（type=image/source=generated）并回写终态；下载与转存沿用高清放大处理器同套实现。

网关侧（本仓代码外，另建配置单）：

- 网关新增 erase-image 同步工具，对客模型名 mediakit-erase-image，本期 model_price 配 0（配零价而非不配价，未配价会被网关硬拦 400）；复用已配置的 MediaKit 渠道与平台级 API Key。

## Testing Decisions

好测试的标准：只测外部可观察行为，不测实现细节；一个行为一条断言主线；测试数据就地构造不依赖环境。

经 Kim 确认，本需求共五层测试接缝，全部复用现有测试打法，不新增测试设施：

1. **前端组件与画布链路**（vitest + jsdom，先例：ImageEnhanceDialog 测试与 CanvasPage 定向套件）：菜单可见性与门槛置灰（超尺寸/超大小/webp/gif/null 不拦）、编辑态进入与四种退出、未发送退出丢弃遮罩、工具条各控件行为、「清除文字」与涂抹两条发送路径的提交参数、发送时建结果卡与纯视觉连线、mediaRefs 推导跳过该连线。
2. **遮罩纯逻辑层**（vitest 纯函数）：笔迹与框的并集叠加、橡皮擦除、撤销重做栈、显示坐标到原图自然分辨率的换算、栅格化输出尺寸等于原图分辨率。这层是涂抹质量的主要保险。
3. **后端创建入口**（先例：image-enhancements service 测试）：输入复核、资产归属、门槛复核（含 null 放行）、免费口径（无成本预留/余额拦截）、凭证冻结、入队失败回拨。
4. **worker 执行与回填**（Docker maven 镜像跑 Java 测试，先例：ImageEnhanceJobProcessor 测试）：两种场景的请求映射、output_format=png、结果下载与 TOS 转存、Asset 与终态回写、错误分类。
5. **双端契约一致性**（先例：image-enhance 契约对账测试）：契约常量、输入键、场景枚举前后端一致。

## Out of Scope

- 全屏图标/logo 擦除、指定文字内容擦除（接口支持，结构留扩展位，后续单独立项）。
- 框的活编辑（选中后拖动、调大小、Delete 删除）。
- 进入编辑态自动缩放居中画布视角。
- 任务中途取消（同步接口本身不支持）。
- 「重绘」「抠图」「裁剪」（截图菜单其余三项，与扩图同批不展示）。
- 积分预估展示与实际扣费（本期免费，计费另见 ADR-0092 的后续计费工单结论）。
- 网关侧渠道与价格配置（另建配置单，对标 IKGOKL）、火山平台级 API Key 的创建与配 env（复用高清放大已配的 Key）。
- 多张输出、批量擦除、视频擦除。

## Further Notes

- 上线前置条件：网关完成 erase-image 工具配置（含零价）后，先在网关验证连通性，再在 3000 页面提交测试任务确认完整回填效果（与高清放大同一验收路径）。
- 结果图 URL 仅 24 小时有效，worker 必须在响应成功后立即下载落 TOS，不得延迟处理。
- 遮罩图必须与源图同分辨率（接口硬性要求），前端按源图自然分辨率栅格化；遮罩经资产上传链路产生的中间素材的归属与展示口径由实现工单明确（不进入用户资产列表的可见内容）。
- 接口失败响应中出现 standard_erase_locations 字段名，暗示实际接口可能支持多矩形数组；文档正文只定义单矩形对象，本规格不依赖该未文档化行为（统一遮罩路径已绕开）。
- 与扩图的先后关系：擦除先行落地「高清 ▾」下拉（高清+擦除），扩图（IKGOQ0）就绪后插入菜单中间位置；两者共用下拉组件但无其他代码耦合。
