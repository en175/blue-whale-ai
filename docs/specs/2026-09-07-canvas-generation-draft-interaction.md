# Canvas 生成草稿与引用交互规格

## 时间

2026-09-07

## 背景与状态

用户反馈：侧栏图片、视频、音频入口只打开 Dock，画布中没有生成目标，无法先建立参考连线再编辑生成参数。
本规格记录 grill-with-docs 讨论中已确认的产品决定；首轮 Q1–Q4 已由用户回复“全部按推荐”确认，第二轮 Q5–Q9 已确认，其中 Q7 按用户修正禁止 Dock 上传素材。其余边界仍待讨论，不表示实现完成或已确认全部设计。

## 已确认决定

| 编号 | 决定 | 用户可见行为 |
| --- | --- | --- |
| Q1 | 先建立生成草稿节点，首次结果填回原卡片 | 点击侧栏媒体入口后先在 Canvas 放入对应类型节点，再通过 Dock 编辑；首次生成成功沿用节点、位置和连线，不额外创建结果卡 |
| Q2 | 草稿持久保留 | 关闭 Dock 或刷新后保留未生成卡片、已填写参数与参考关系；关闭 Dock 仅结束当前编辑，删除卡片才移除草稿 |
| Q3 | 侧栏每次新增 | 每次点击图片、视频、音频入口新增并选中一张对应卡片；点击已有卡片继续编辑该卡片 |
| Q4 | Dock 引用与连线双向同步 | 在 Dock 添加画布素材时建立对应连线，移除引用时断开对应连线；画布建立、断开参考连线同步更新 Dock 参考列表 |
| Q5 | 成功后的再次生成另建卡片 | 修改参数再次生成时另建一张生成卡，复制参数与输入连线；原成功结果保留，新结果填入新卡，便于比较 |
| Q6 | 失败或取消后保留草稿 | 首次生成失败或取消后保留卡片、参数与连线；失败显示原因并允许重试，取消后回到待生成状态 |
| Q7 | 移除 Dock 素材上传 | Dock 不允许上传素材，仅允许选择引用画布已有或已经上传的素材；不采纳上一轮关于在 Dock 直接上传的建议，已上传但尚未放入画布的素材如何建立来源节点仍待确认 |
| Q8 | 显式指定视频参考角色 | 在 Dock 明确指定普通参考、首帧、尾帧，不根据连线先后自动猜测；输入不符合当前模型能力时明确提示，禁止静默丢弃 |
| Q9 | 音频本轮保持文字输入 | 本轮完成音频卡创建、保存与生成流程，继续使用文字描述，不扩展音频参考输入能力 |

生成草稿节点尚未提交时不是 GenerationJob，也不是已生成 Asset。只有用户在 Dock 点击“生成”才提交任务。
Q4 不自动扩展生成模型的输入能力；音频引用能力不属于本轮范围。Dock 移除上传功能不表示移除 Canvas 其他入口的上传能力。

## 当前实现约束

以下为首轮代码调研时的快照，不能当作已确认的新产品规则，也不代表其他任务更新主分支后的最新实现：

- 侧栏三种媒体入口目前仅切换 Dock；文本入口会立即创建节点。
- 当前提交生成时才创建新的媒体节点；成功后在该节点填入结果。
- 媒体节点没有生成状态且无有效素材身份时，刷新会标记素材缺失；待生成草稿需要独立于素材缺失的语义。
- 当前媒体参考由 Dock 的 files/refs 提交，图片或视频媒体连线尚未转换为参考输入；已有文本连线输入仅适用于图片目标。
- 当前图片 Dock 在打开时展示附件快照，但服务端提交时读取最新画布；新的双向同步要求消除展示与实际输入的差异。

## 待确认边界

1. 生成中删除或编辑如何处理，以及再次生成的新卡何时创建、取消与失败重试的具体语义。
2. 已上传但不在画布的素材如何建立来源节点，移除引用后如何处理来源素材节点。
3. 图片与视频目标支持的参考类型、角色冲突，以及未完成节点能否作为参考。
4. 新节点放置与焦点、已有媒体节点生成入口，以及切换项目和保存失败时的行为。
5. 输入去重、数量或模型能力冲突，以及历史任务输入快照的稳定性。

## 验证目标

后续实现至少验证：侧栏先建卡并选中；首次结果保留节点身份与连线；关闭或刷新恢复草稿；重复点击新增独立草稿；Dock 与画布参考关系双向同步；再次生成保留旧结果；失败或取消保留草稿；Dock 不提供素材上传；视频参考角色显式选择且不静默丢弃；音频保持文字输入。未决边界确认后再补充对应验收场景。
