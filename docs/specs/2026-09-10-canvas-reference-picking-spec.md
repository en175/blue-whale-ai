# 画布参考节点持续选取规格

日期：2026-09-10  
状态：产品设计与测试覆盖方式均已确认，待实现。用户明确授权按本规格发布至项目工单。

## 问题陈述（Problem Statement）

用户为 Canvas 上的生成目标添加参考图片时，打开原目标的生成面板（Dock），选择从画布添加参考，再点击来源节点。参考已经添加，但 Dock 随即消失。用户必须重新选中原目标、再次进入选择入口，才能添加下一张参考，无法一次连续完成选图，也难以立即判断添加是否成功。

用户提供的 37 秒录屏中，同一金发人物目标连续添加三张参考，三次均出现这一中断。现有实现会在单次选择后退出模式，生成面板又受普通节点选中变化影响；这两条交互路径存在冲突。已确认录屏现象和对应源码行为，尚未通过真实浏览器事件插桩证明具体回调先后。

## 解决方案（Solution）

引入统一的“画布参考选取模式”：用户从图片、视频或音频生成面板进入后，始终针对原生成目标及当前参考槽位连续选择，Dock 持续可见。有效点击立即更新参考，直到用户点击“完成选取”、按 Esc 或关闭 Dock。

普通多参考列表连续添加；首帧、尾帧等单槽位连续选择时只替换当前槽位。已添加节点显示勾选标识，重复点击不重复添加，也不移除。参考移除统一使用 Dock 缩略图上的移除按钮。类型不符或数量满时提示原因并保持模式。

选取期间允许平移、缩放画布，点击空白不退出；节点拖动、框选、切换编辑目标以及提示词编辑、模型切换、生成须先结束选取。模式不跨刷新或画布恢复，参考继续使用现有保存机制。

## 用户故事（User Stories）

### 进入与连续选取

1. 作为图片创作者，我希望从图片生成面板进入画布参考选取模式，以便一次连续添加多张参考。
2. 作为视频创作者，我希望视频生成面板采用相同的持续选取操作，以便不必重新学习另一套交互。
3. 作为音频创作者，我希望音频生成面板的画布选择入口也保持持续，以便连续选择该入口允许的素材。
4. 作为创作者，我希望点击来源节点时原目标的 Dock 一直可见，以便确认参考是否已经添加。
5. 作为创作者，我希望连续点击时生成目标保持不变，以便参考不会被误加到刚点击的来源节点。

### 参考反馈与纠错

6. 作为创作者，我希望每次有效选择立即更新 Dock 中的参考，以便随时了解当前生成输入。
7. 作为创作者，我希望已添加节点显示勾选标识，以便分辨哪些素材已被采用。
8. 作为创作者，我希望重复点击已添加节点不新增也不移除，以便连续点击不会意外改变已有参考。
9. 作为创作者，我希望从 Dock 的缩略图移除参考，以便使用明确入口修正误选。
10. 作为创作者，我希望移除后能在同一模式继续添加，以便不必重新进入选择入口。

### 画布浏览与操作隔离

11. 作为创作者，我希望选取期间能够平移画布，以便找到当前视野外的参考节点。
12. 作为创作者，我希望选取期间能够缩放画布，以便检查密集或较远的素材。
13. 作为创作者，我希望点击画布空白不退出选取，以便操作画布时不会中断任务。
14. 作为创作者，我希望选取期间节点拖动、框选及切换编辑目标被隔离，以便点击仅用于选择参考。
15. 作为创作者，我希望先完成选取再编辑提示词、切换模型或生成，以便当前选择目标和素材限制保持清楚。

### 明确退出与模式生命周期

16. 作为创作者，我希望能点击明显的“完成选取”按钮结束模式，以便知道何时恢复普通编辑。
17. 作为键盘使用者，我希望按 Esc 结束选取，以便快捷完成同一操作。
18. 作为创作者，我希望正常结束选取后仍显示原目标的 Dock 并保留参考，以便接着编辑或生成。
19. 作为创作者，我希望关闭 Dock 直接结束选取且不撤销参考、不弹二次确认，以便自然离开当前操作。
20. 作为创作者，我希望重新打开 Dock、刷新或切换画布后恢复普通交互，以便不意外继续旧的选取模式。

### 槽位、限制与目标有效性

21. 作为视频创作者，我希望连续为首帧或尾帧选择素材时仅替换当前槽位，以便最后一次有效选择成为该槽位输入。
22. 作为视频创作者，我希望替换当前槽位不改变其他槽位，以便已有生成配置得到保留。
23. 作为创作者，我希望选择不兼容或无效素材时得到明确原因且模式继续，以便立即选择其他素材。
24. 作为创作者，我希望达到数量上限时不再添加但保持模式，以便移除参考腾出名额后继续选择。
25. 作为创作者，我希望当前生成目标被删除后立即结束选取并关闭 Dock，以便后续点击不会写入其他目标。

### 保存、恢复与正常行为回归

26. 作为创作者，我希望保存失败后本地参考和选取模式保留，以便不必重新选取。
27. 作为创作者，我希望失败时明确显示“未保存”并可重试，以便分辨本地结果与已经保存的数据。
28. 作为创作者，我希望只有保存成功后才显示已保存，以便成功保存的参考能在刷新后恢复。
29. 作为创作者，我希望版本冲突沿用已有处理且不自动覆盖，以便他人的更新不会被静默替换。
30. 作为创作者，我希望退出模式后普通节点选择、面板编辑及生成恢复既有规则，以便此次优化不会改变其他工作方式。

## 实现决策（Implementation Decisions）

### 页面、画布与生成面板的协调

| 决策 | 约束 |
| --- | --- |
| 修改模块 | Canvas 页面交互协调、画布节点交互与勾选呈现、图片/视频/音频生成面板及共同的完成选取入口。优先复用现有结构，不新建通用工作流框架。 |
| 模式身份 | 活动选取必须绑定当前画布、原生成目标和当前参考槽位。普通节点选中变化不改变该绑定。模式属于本次界面交互，不是需持久化的新业务对象。 |
| 模块间交互 | 生成面板发起针对当前目标及槽位的选择；画布上报用户的来源选择；页面协调添加、拒绝、替换与结束。必要时扩展现有组件交互接口，具体内部命名交由实现确定。 |
| 显示与事件 | 进入模式后选取来源、空白点击、平移缩放都不关闭原目标 Dock。正确性不得依赖普通选中回调与节点点击回调的固定先后。 |
| 正常结束 | 完成按钮与 Esc 结束模式并恢复原目标的普通编辑及 Dock；保留已添加参考，不触发生成、不额外确认，也不把源节点当成编辑目标。 |

### 参考关系与槽位

| 输入或动作 | 已确认行为 |
| --- | --- |
| 有效多参考选择 | 立即添加到原目标，使用既有参考关系与保存路径，更新 Dock 和节点勾选标识。继续保留模式。 |
| 重复选择 | 不新增、不移除、不形成重复参考；勾选必须针对当前目标和当前选择上下文，不能混用其他目标的参考。 |
| Dock 移除 | 移除对应参考并同步可见标识；保留来源素材和其他目标的参考，允许继续选择。 |
| 单槽位选择 | 当前首帧、尾帧等单槽位采用最后一次有效选择；只替换当前槽位，不因槽位已有值而禁止合法替换，也不改变其他槽位。 |
| 非法输入与上限 | 沿用各面板现有素材类型、有效性、槽位与数量限制，拒绝时给出明确原因并保持模式；不扩大任何模型能力，不新建失效素材清理机制。 |

### 操作与结束条件

| 场景 | 行为 |
| --- | --- |
| 浏览画布 | 允许平移与缩放；点击空白保持模式及原目标 Dock。 |
| 非选取操作 | 模式内隔离节点拖动、框选、切换编辑目标、提示词编辑、模型切换与生成；Dock 移除参考和结束选取入口仍可用。 |
| 关闭 Dock | 结束模式、关闭面板、保留参考；不弹确认。再次打开为普通编辑。 |
| 目标删除 | 结束模式并关闭 Dock；旧模式或迟到事件不得将后续参考写到其他目标。 |
| 刷新或实际切换画布 | 不恢复选取模式；成功保存的参考按既有加载流程恢复。继续遵守现有切换保存门禁，不改造地址栏或浏览器历史导航。 |

### 保存与接口边界

沿用画布文档与节点编辑草稿的现有持久化能力。“立即添加”指本地参考立即生效，不等同于网络保存已经成功。保存失败保留已有目标的本地参考及模式，显示未保存，提供既有重试入口；成功后更新保存状态。版本冲突沿用已有处理，不自动覆盖，不承诺未保存数据在刷新后恢复。

本规格不要求数据库迁移、新业务 API 或后端/Worker 改造，不把选取模式写入画布存储。继续遵守既有前后端分离边界；如实现中发现必须改变服务端合同，应作为独立范围报告，不能在本工单中静默扩展。

本次不增加参考增删的 Undo/Redo。错误选择通过 Dock 移除或单槽位重新选择纠正。

## 测试决策（Testing Decisions）

测试覆盖方式已确认：用户于 2026-09-10 回复「符合，按此写入规格并发布」。

1. **统一业务验收入口。** 以“Canvas 页面 + 原目标 Dock 的完整交互”作为最高且统一的业务验证边界。覆盖页面协调、真实生成面板、参考呈现与既有保存接口，不为每个内部状态变量另建测试层。
2. **复用页面级自动化。** 扩展现有 Vitest 页面集成测试及生成面板测试，覆盖进入、连续添加、拒绝、移除、退出、槽位替换和保存失败。画布事件桥及 API 可沿用已有测试替身，以不同事件顺序验证稳定行为；只断言用户可观察结果及保存接口收到的内容，不以内部字段或函数调用次数作为主要正确性证明。
3. **已有测试先例与限制。** 现有“图片参考连线与 Dock 双向同步”测试使用真实图片面板，但替换 Canvas 并直接调用事件回调，且有“选择一张后退出”的旧断言；本次必须更新该目标行为。已有“成品卡面板绑定与编辑”测试覆盖空白、多选与过渡选中事件，可复用其组织方式。已有媒体布局浏览器测试采用模拟 API，不能将其刷新结果当作真实持久化证据。
4. **真实交互人工回归。** 在 dev:test 的真实 Canvas 页面、真实 React Flow 交互和测试站接口上人工回归三个生成面板，提供可点击页面入口及下面的场景清单，记录明确的通过或不通过。实际检查保存后刷新恢复；模拟保存、未运行的测试或仅看到缩略图均不算持久化通过。本次规格不要求新增浏览器自动化框架、启动本地后端或修改测试站数据结构。
5. **验证与完成口径。** 实现阶段执行仓库当前前端检查及按影响面选择的收口验证，修复阶段遵循对应前端工作流；真实交互人工回归与自动化结果分别记录。文档检查通过、工单发布或标记 ready-for-agent 均不表示功能已实现、已验收或已部署。

### 验收矩阵

| 编号 | 操作与场景 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 | 从图片 Dock 进入一次后，依次选择三张有效来源 | Dock 持续可见、原目标不变、三次均立即更新参考、模式始终持续；连线与缩略图一致。 |
| AC-02 | 视频与音频面板使用各自允许的来源连续选择 | 具有相同的持续模式及退出方式，不突破原有素材类型与数量限制。 |
| AC-03 | 重复点击已有参考，再从 Dock 移除，再次选择 | 不重复或误删；明确移除后标识及参考同步，可以继续添加。 |
| AC-04 | 选择非法来源或达到多参考数量上限 | 明确说明原因，不写入、不退出、不关闭 Dock；移除后可继续添加。 |
| AC-05 | 同一单槽位依次选择 A、B，再次选择 B | 只有 B 占用当前槽位，其他槽位不变，无重复参考，模式持续。 |
| AC-06 | 点击空白、平移、缩放；尝试节点拖动与框选 | 前三者可用且模式持续；拖动节点、框选与切换编辑目标被隔离。 |
| AC-07 | 模式中尝试编辑提示词、切换模型、生成 | 须先结束选取；模式内不误改配置或触发生成，移除参考与退出仍可用。 |
| AC-08 | 分别使用完成按钮与 Esc，并触发迟到普通选中事件 | 正常退出后原目标 Dock 保持，参考保留，编辑恢复，不被迟到事件再次关闭或切换目标。 |
| AC-09 | 关闭后重开 Dock；活动目标失效或被删除 | 关闭与重开不恢复模式；目标删除后模式及 Dock 结束，后续点击不写入其他目标。 |
| AC-10 | 保存成功后刷新、切换画布再回来 | 已保存参考正确恢复，模式不恢复，恢复普通交互。 |
| AC-11 | 保存失败、重试成功及版本冲突 | 失败保持本地参考和模式并显示未保存；重试后正确保存；版本冲突不自动覆盖。失败注入可在页面测试中完成，真实成功保存须另有人工作证。 |
| AC-12 | 普通编辑模式下选中、拖动、框选、编辑与生成 | 模式外既有行为不被持续选取改动破坏；本次不引入新的撤销历史。 |

## 范围外（Out of Scope）

1. 暂选后统一提交、取消整轮选择、点击已选节点切换移除，以及新增 Undo/Redo。
2. 跨刷新恢复选取模式、离线持久化或保证未保存参考在刷新后恢复。
3. 模型能力、素材类型与数量限制变更，新增参考角色或独立素材失效清理机制。
4. Agent 对话引用、素材库上传流程、普通画布多选与拖动机制重构，以及浏览器导航保存门禁的整体改造。
5. 数据库、后端与 Worker 改造；工单拆分、功能实现、推送 PR、合并及部署不属于本次规格发布动作。

## 补充说明（Further Notes）

产品决定来自同一会话中的三轮确认：Q1–Q3 确认持续范围、立即生效及三个面板；Q4–Q8 确认退出、重复点击、操作隔离、单槽位和拒绝反馈；Q9–Q11 确认关闭/删除、撤销范围与保存失败。用户随后明确回复“整体设计确认”。本次 to-spec 仅补齐实现与测试表达，不重新访谈产品行为。

录屏为“录屏2026-09-10 16.07.24.mov”：约 10 秒进入选取，12 秒 Dock 消失，16 秒点回原目标后出现一张参考；后续两次重复，约 30 秒可见三张参考及连线。源视频位于报告者本机，工单不假定接手者可访问该本地路径；上述步骤和验收矩阵应可独立复现。

代码核查采用项目知识图谱及定向源码，测试证据路径的覆盖元数据无记录缺口；该信号不保证图谱绝对完整。现有单次选取退出、面板选中态隐藏、保存失败保留参考与重试均有源码依据；具体真实事件先后仍应通过人工回归验证结果，不在规格中虚构时序。

沿用“画布参考选取模式”“节点编辑草稿”“生成草稿节点”和 BottomDock 的项目领域定义。遵循既有前后端分离、画布保存及冲突处理边界，不重启已被后续决策取代的历史公共 API 改造。本次为可逆的局部交互优化，不另立架构 ADR。

发布目标：Blue-Whale-AI 工程项目下的 blue-whale-ai 仓库，需求型根工单，标签 ready-for-agent。产品状态保持待实现，不因为规格发布而流转为进行中或已完成。
