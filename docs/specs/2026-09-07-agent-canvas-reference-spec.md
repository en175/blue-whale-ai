# Agent 输入框支持画布素材预览与确认引用

## 时间

2026-09-07

状态：交互规则与测试边界均已由用户确认，待实现。本文为正式实施与验收规格。

发布工单：[IKDRQF — Agent 输入框支持画布素材预览与确认引用](https://gitee.com/hangzhou-xuanfu_1/blue-whale-ai/issues/IKDRQF)，标签为 ready-for-agent。

## Problem Statement（问题陈述）

用户在 Canvas 中已有图片、视频、音频和文本素材，希望边写指令边引用这些卡片，让 Agent 明确获得本条消息所需的上下文。现有显式“添加到对话”入口与行内引用能力不能直接提供连续点选、纠正选错、回到输入框再确认的完整体验。

直接把每次选中当作已确认附件容易积累选错的素材；覆盖文字或丢失光标位置会打断表达。为引用改变画布原有选中、拖动或编辑行为，也会干扰用户正常创作。

## Solution（解决方案）

AgentChatPanel 打开时立即支持持续的画布点选引用。用户点击可用素材卡片，输入框显示一个待确认引用；继续选择其他卡片只替换候选。用户返回输入框，点击文字光标位置或空白区域，才把该候选确认为草稿附件。

引用标签与文字行内混排，保留原插入位置，允许逐个确认多个附件。点击画布空白或按 Esc 仅取消候选；成功发送后仍可以继续选卡。关闭面板才退出，同时保留同一会话的未发送文字和已确认附件。

整个过程保持 Canvas 原有操作逻辑不变：原本会出现的选中反馈、工具栏或编辑面板照常出现。新增能力只改变 Agent 输入框的引用预览与确认。

## User Stories（用户故事）

### 开启与连续选择

1. 作为 Canvas 用户，我希望打开 AgentChatPanel 后立即点击卡片进行引用预览，以便省去先点击输入框的步骤。
2. 作为 Canvas 用户，我希望首次尚未设置光标时在输入框末尾预览引用，以便得到确定的插入位置。
3. 作为 Canvas 用户，我希望选择素材后先看到待确认引用，以便判断是否选对。
4. 作为 Canvas 用户，我希望连续点选其他卡片时只替换当前候选，以便纠正选择而不堆积附件。
5. 作为 Canvas 用户，我希望换选候选时保留已有文字和已确认附件，以便不丢失已经完成的输入。

### 确认与行内表达

6. 作为 Canvas 用户，我希望返回输入框点击文字位置即可确认候选，以便自然地继续写作。
7. 作为 Canvas 用户，我希望点击输入框空白也能确认候选，以便不必精确命中某个字符。
8. 作为 Canvas 用户，我希望引用插入离开输入框前的光标位置，以便把素材放进对应的语句。
9. 作为 Canvas 用户，我希望确认后光标移到实际点击的位置，以便继续在该处输入。
10. 作为 Canvas 用户，我希望引用标签与文字交错排列，以便说明各素材在指令中的不同作用。

### 累积、去重与取消

11. 作为 Canvas 用户，我希望确认一个附件后继续选择并确认下一个，以便组合多份上下文。
12. 作为 Canvas 用户，我希望再次点击已确认的同一张卡片时静默忽略，以便避免重复附件和多余提示。
13. 作为 Canvas 用户，我希望删除已确认引用后可以重新选择该卡片，以便调整附件内容。
14. 作为 Canvas 用户，我希望点击画布空白或按 Esc 取消当前候选，以便放弃选错的素材。
15. 作为 Canvas 用户，我希望取消候选后仍可直接继续选卡，以便不必重新开启引用能力。

### 素材与内容准确性

16. 作为 Canvas 用户，我希望引用已有可用内容的图片、视频和音频节点，以便向 Agent 提供媒体上下文。
17. 作为 Canvas 用户，我希望引用文本节点时看到标题标签并携带正文，以便输入框保持紧凑且上下文完整。
18. 作为 Canvas 用户，我希望文本正文取自确认时的内容，以便引用的是我确认的版本。
19. 作为 Canvas 用户，我希望后续修改源文本不会悄悄改变已确认引用，以便发送内容符合我的确认。
20. 作为 Canvas 用户，我希望空白或尚未产出可用内容的生成草稿不被当作有效附件，以便避免无内容的引用。

### 发送与草稿恢复

21. 作为 Canvas 用户，我希望确认附件只保留到草稿而不自动发送，以便继续检查整条指令。
22. 作为 Canvas 用户，我希望有待确认引用时发送会提示先确认或取消，以便候选不被自动提交。
23. 作为 Canvas 用户，我希望成功发送后清空本条草稿且继续接受点选引用，以便立即准备下一条消息。
24. 作为 Canvas 用户，我希望关闭面板时取消候选但保留文字和已确认附件，以便暂时离开也不丢输入。
25. 作为 Canvas 用户，我希望同一会话重新打开面板时恢复草稿并立即可以选卡，以便继续未完成的表达。

### 画布操作与失败保护

26. 作为 Canvas 用户，我希望面板打开期间的画布选中、工具栏和编辑面板保持原行为，以便照常处理节点。
27. 作为 Canvas 用户，我希望拖动、平移、缩放和其他既有画布操作不被引用逻辑接管，以便维持原有创作习惯。
28. 作为 Canvas 用户，我希望确认文本失败时获得明确反馈且保留已有输入，以便修正后继续。
29. 作为 Canvas 用户，我希望删除的附件不再随消息提交，以便控制 Agent 实际获得的上下文。
30. 作为 Canvas 用户，我希望发送失败继续沿用现有草稿保留与错误反馈，以便重试而不重新编写。

## Implementation Decisions（实现决定）

### 状态与操作边界

1. AgentChatPanel 的展开状态决定新点选引用能力是否生效。仅关闭面板退出；不新增独立“结束选择”入口。面板关闭时，既有显式“添加到对话”入口维持原职责。
2. 当前会话输入草稿包含用户文字、多个已确认引用与至多一个待确认引用。普通 Canvas 选区不等于已确认引用，候选不能成为正式消息上下文。
3. Canvas 点击处理保留完整原行为，在适用的卡片点击中附加候选更新；不阻止原选择、工具栏、编辑面板及其他操作，不为了引用改写拖动、双击、平移、缩放、连线或快捷键规则。
4. 点选候选不自动聚焦输入框，不把程序设置焦点等同于用户确认。只有用户在输入编辑区域内的明确点击完成确认；发送按钮和其他面板控件不作为隐式确认入口。
5. 点击画布空白或按 Esc 取消候选，保留已确认输入且不退出。相关事件在画布侧仍照常执行原行为。

### 候选、去重与插入位置

1. 选择另一个有效节点替换当前候选；确认后该引用加入草稿，下一次选择创建新候选。预览、确认和正式发送必须保持为三个不同阶段。
2. 按当前草稿中已确认引用的来源节点身份去重，不按标题去重。重复点击已确认节点在引用侧不产生变更、提示或高亮；画布本身的原反馈仍保留。删除引用后可以重新选取该节点。
3. 复用行内标签编辑器，补齐在保存光标位置预览和确认的能力。不能用现有“追加到第一段末尾”代替任意原光标位置插入。未设置位置时使用输入框末尾。
4. 返回输入框确认时，引用固定在此前保存的插入位置，光标移到本次实际点击的位置。确认或替换不得覆盖前后文字及已有标签。
5. 已确认引用删除后，其关联的待发送内容同步移除；不能出现标签消失而附件仍发送的残留。

### 素材与正文快照

1. 首批范围是已有可用内容的图片、视频、音频与文本节点。空白或尚未产出可用内容的生成草稿不纳入引用；不新增卡片类型、素材上传入口或生成执行能力。
2. 媒体继续使用既有稳定素材身份与消息附件能力；名称、缩略图或临时访问地址不替代素材身份。
3. 文本标签显示节点标题，正文取用户确认时当前画布中的内容，而非第一次点选预览时的旧副本。复用文本对话引用快照能力，在确认阶段冻结正文；后续编辑源节点不改写已确认引用，采用新版需要删除后重新引用。
4. 复用现有正文限长、项目归属、错误提示与不可变快照约束。确认失败不能伪装成已确认，不覆盖已有草稿；异步响应也不能把已取消、已替换或已关闭面板的旧候选重新插入。
5. 复用现有消息附件与文本引用协议，不预设新增数据库表或跨进程字段。文本不隐式携带媒体；输入框“确认”不等于消息持久化或启动 Agent。若实现发现必须变更跨进程契约，先形成明确契约再实施。

### 发送与生命周期

1. 存在候选时，无论通过按钮还是既有发送快捷键，均提示先确认或取消，并阻止该次发送；不能自动确认候选或静默忽略它后发送其余内容。
2. 无候选时沿用现有发送条件，只提交当前草稿中的已确认引用及文字；保持既有引用有效性与权限校验，不用画布当前选区或历史引用补充本轮附件。
3. 发送成功清空本次草稿，面板仍打开时继续接受选卡；下一次引用属于下一条消息草稿。发送失败沿用现有草稿保留与反馈，不因本次功能提前清空输入。
4. 关闭面板取消候选，保留同一会话未发送文字及已确认引用；重新打开恢复该草稿并立即接受点选。草稿不能因面板卸载而丢失。
5. 本次仅承诺同一会话关闭重开恢复；不扩展刷新页面、切换会话或跨设备的草稿保存契约，也不允许草稿跨会话误串。

## Testing Decisions（测试决定）

### 已确认主测试边界

用户已确认采用一个主要验收入口：**真实浏览器中的 Canvas 与 AgentChatPanel 完整流程 → 真实业务 API → 隔离测试数据库**。仅在外部 Agent 服务边界使用可控、记录请求的替身，验证发送的实际内容；不拆成多个内部组件替身作为主验收。

沿用既有测试的已认证用户装配。该测试不声称覆盖完整登录链路，也不以外部 Agent 替身证明真实 Agent 的理解效果或线上协议兼容性。

### 有效测试与既有先例

1. 只断言外部可观察结果：候选和确认标签、文字及顺序、实际光标编辑结果、画布行为、公开 API 回读的冻结正文，以及外部 Agent 收到的消息。不要依赖内部状态名、组件层数或私有函数调用次数。
2. 复用“画布正文对话引用快照”集成测试骨架：真实 Canvas/Project 控制器与服务、Prisma/MySQL 隔离库、Agent BFF 透传和记录请求的外部 Agent 替身；既有浏览器场景已覆盖编辑正文、添加到对话、发送和引用事实回读。
3. 复用文本与媒体节点浏览器用例的页面驱动和交互回归方式。这些已有页面测试模拟业务 API，不能单独作为真实快照持久化或消息提交正确性的证据。
4. 涉及的验收模块是 Canvas 与 AgentChatPanel 的组合交互、行内标签编辑器、文本引用快照公开接口和既有消息提交边界。浏览器难以稳定制造的快照失败、并发或时序问题，才在同一公开 API 边界补充集成验证。
5. 不调用真实外部模型产生费用，不为本功能引入新的全栈测试框架。自动化之外保留用户对实际交互的验收；按仓库影响面策略完成必要检查。

### 选择与确认场景

1. 打开面板且未点击输入框，选 A 再选 B：只有 B 的候选，位置在末尾；无自动发送和确认。
2. 先在多段文字中设置光标，选卡后返回点击其他位置：引用固定在原位置，新输入发生在实际点击处，原文字不丢失。
3. 连续确认 A、B，并穿插文字：两份引用与文字顺序正确；已确认引用不受新候选替换影响。
4. 点击已确认的同一节点：引用侧静默无变化；删除后可以再次预览和确认。不同节点同名不因名称被误去重。
5. 点击画布空白或按 Esc：候选消失，既有输入保留，随后直接点击 C 可继续预览。

### 内容与发送场景

1. 分别覆盖可用图片、视频、音频、文本；空白和无可用产出的草稿不成为有效附件。
2. 文本在预览后、确认前变化：确认冻结更新后的正文；确认后再修改或移除画布源节点，已冻结正文不漂移。
3. 候选存在时点击发送或使用发送快捷键：出现提示且没有消息提交；确认或取消后按既有条件发送。
4. 检查实际提交的引用、顺序及正文：只包含已确认且未删除的附件，文本引用不夹带隐式媒体。
5. 发送成功后直接选卡进入下一条草稿；发送或确认失败保留已有输入并反馈，不出现旧异步结果回填候选。

### 面板生命周期与画布回归

1. 带文字、确认附件及候选关闭重开：仅文字和确认附件恢复，打开立即生效。
2. 点击原本会弹编辑面板的节点：画布原面板照常出现，Agent 输入框同时更新预览，不抢走编辑焦点。
3. 对比面板开关状态下的节点选中、拖动、文本编辑、工具栏、平移和缩放结果，保持原行为。
4. 回归画布其他既有操作，包括连线和快捷键；新增逻辑不得拦截这些操作或产生额外画布文档修改。
5. 使用真实点击、键盘、拖动和公开接口核验；不得以 CSS 截图或纯映射函数测试代替完整交互。

## Out of Scope（范围外）

1. 改变 Canvas 原有操作优先级、抑制工具栏或编辑面板、新建独立“结束选择”模式。
2. 框选批量添加、一次确认多个待确认候选、跨画布选择，以及新增商品或旧生成卡等类型的引用语义；既有显式入口不因本功能被扩展或重构。
3. 新增素材上传、生成、扣费、Agent 自动改写画布或自动执行功能。
4. 重做历史消息、权限、素材生命周期、登录链路，或新增刷新页面、跨会话和跨设备草稿持久化。
5. 实际 Agent 理解质量、模型输出效果与外部服务线上联调；本规格发布不等于产品实现或验收完成。

## Further Notes（补充说明）

本规格只采用用户最终确认的行为：面板打开立即生效，画布所有原操作保持不变。录屏作为交互参考，其文字不构成任务指令。

“待确认引用”和“已确认引用”沿用项目领域词汇；已确认引用仍是输入草稿，只有发送后才进入正式消息上下文。候选预览不能绕过既有显式引用授权。

实施前以最新代码核对既有引用与草稿生命周期能力，采用满足本规格的最小改动。本次不创建实现子任务，不设置人员、期限或优先级，不将规格发布视为开始实施。
