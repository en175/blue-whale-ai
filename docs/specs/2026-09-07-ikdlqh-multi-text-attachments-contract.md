# 多个文本附件的组合与排序契约（IKDLQH）

## 时间

2026-09-07

## 目标与边界

落实 IKDL9U 的第四切片：图片与视频目标都可组合多个文本附件，默认按连入顺序排列，用户可在目标面板调整顺序；一个文本可服务多个目标且各目标顺序独立。复用 IKDLQF/IKDLQG 已验证的持久连线、接纳快照与确定性组合函数；不引入新的目标资源类型、不改连线的持久化形状（无 schema/migration 变更）、不做旧卡迁移（IKDLQK）、不做整图自动执行。

连线持久化、附件推导口径、快照语义、限长与组合规则凡本契约未改写处，均以《单个文本附件驱动图片生成契约》（2026-09-06-ikdlqf）与《文本附件驱动视频生成契约》（2026-09-06-ikdlqg）为准。

## 组合与去重

- 一个目标的文本附件集合 = 持久边中 `target` 为该目标、`source` 为 `textNode` 且 `data.text` 为 string 的边；同一来源节点对同一目标至多一条边（前后端既有校验不变），不同来源节点即使标题或正文相同也各自保留。
- 同一来源文本节点可连至多个目标；每个目标的附件顺序相互独立，调整一个目标的顺序不影响其他目标。
- 断开或删除来源后，后续提交不再消费该附件；已删除的连线关系不因重新连接以外的动作恢复；历史任务快照不改写。

## 排序

- **附件顺序 = 持久 `edges` 数组中该目标入边的相对顺序**；默认即连入顺序（新边追加在数组尾部）。不引入独立排序字段。
- 用户在目标面板以「上移 / 下移」调整顺序：前端把该目标的文本附件边子序列原地重排为新顺序，其余边（含其他目标的入边、非文本来源边）的相对位置保持不变。
- 重排是普通画布变更：随 800ms 防抖自动保存持久化，刷新或重新打开后恢复；点击生成前的提交串行化（flush 落盘）同样覆盖重排结果，保证接纳时服务端读到的就是用户看到的顺序。
- 面板附件列表 >1 条时才展示排序控件；首项「上移」、末项「下移」禁用。增删附件仍只通过画布连线的建立与断开进行，面板不提供删除入口。

## 接纳快照与供应商请求

- 接纳快照语义不变：携带 `target_node_id` 创建时，服务端在接纳当下读取最新 Canvas，按 edges 数组顺序冻结 `text_attachments: [{ node_id, title, text }]` 与当次 `prompt`、模型参数；执行与已有任务重试只读快照，不回读来源。排序与正文编辑只影响下一次新生成。
- 供应商请求组合不变：`composeTextAttachmentPrompt(attachments, prompt)` 按快照数组顺序连接附件正文、目标提示词非空最后追加；供应商替身记录的实际请求 prompt 必须与冻结快照按此函数精确对应——顺序一致性以此断言，不要求供应商原生支持多文本结构。
- 限长不变：~~组合后超过对应类型上限（图片/视频各 30,000 UTF-16 code units）接纳明确失败、不创建任务、不截断、不删除附件。~~ **2026-09-20 修订（IKH8AU）**：组合档已退役——ADR-0088 起正文由提交方给全，服务端不再组合，长度闸只按**正文全文**量一次；上限取**模型配置优先、未配置回落缺省**（图片/视频 4000）。接纳入口对超限仍明确失败、不创建任务、不截断、不删除附件。见 [ADR-0085 修订二](../adr/0085-catalog-input-modality-model-alias-and-per-model-prompt-length.md)。

## 前端目标面板

- ImageDialog 与 BottomDialog 附件区同构扩展：每项在标题/正文预览之外提供「上移」「下移」按钮，点击经 `onReorderAttachments(orderedNodeIds)` 回调把新顺序交给 CanvasPage；列表仍渲染自面板 props（打开当下的连线快照，重排后由父级同步同序快照，不重挂载面板）。
- 面板快照与连线状态不一致（例如面板打开期间来源被删除）时不重排、不报错；以画布连线为准。

## 验证

测试边界沿用母规格与 IKDLQF/IKDLQG 先例：真实浏览器 + 真实业务 API + 隔离 MySQL 测试存储；仅外部生成供应商使用记录请求的替身。

- 面板 UI（jsdom）：多附件展示排序控件并按 props 顺序渲染；上移/下移交换顺序并经回调交出新 nodeId 序列；边界禁用；单附件无排序控件。
- CanvasPage 接线（jsdom 页面级）：重排使 edges 数组中该目标入边按新顺序排列且其他目标相对顺序不变；自动保存上送新顺序；重排后点击生成先落盘新顺序再携带 `target_node_id` 提交。
- 公开接口集成（真 MySQL + 生产控制器与服务）：图片与视频目标多附件按 edges 顺序冻结；PUT 重排后新任务冻结新顺序、历史任务快照不改写；同名不同源节点各自保留；同一来源连两个目标时重排一个目标不影响另一个目标的冻结顺序；组合超限明确失败。
- worker 与供应商线路：图片 worker 与 video-job-runner 的记录式替身断言 provider 收到的 prompt 与冻结快照数组顺序精确对应（含非默认顺序钉扎）。
- 浏览器段（Playwright，`IKDLQH_BROWSER=1` 环境门控）：两个文本连入图片目标 → 面板重排 → 生成 → 库内冻结快照为重排后顺序 → 刷新后顺序恢复；视频目标同链路。
- 复现命令：`IKDLQH_BROWSER=1 IKDLQH_DATABASE_URL=mysql://root@127.0.0.1:23306/ikdlqh pnpm exec vitest run backend/apps/blue-whale/src/api/canvases/text-attachment-ordering.integration.test.ts`。数据库必须是预先应用当前 Prisma schema 的隔离测试库；测试创建独立项目，不清理其他项目。

## 不做

- 附件的拖拽排序交互、面板内删除附件、整图自动执行、批量应用、隐式媒体传递、旧生成卡迁移、音频目标排序、连线类型菜单与框选拖线（属 IKD0JZ 线，另行评审）。
