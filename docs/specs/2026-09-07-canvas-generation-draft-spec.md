# Canvas 先建生成草稿卡与 Dock 引用同步

## 时间

2026-09-07

已发布：[IKDMQM — Canvas 先建生成草稿卡与 Dock 引用同步](https://gitee.com/hangzhou-xuanfu_1/blue-whale-ai/issues/IKDMQM)，标签 `ready-for-agent`。

## 问题陈述

> 2026-09-07 后续修订：本文成功卡再次编辑立即创建新草稿的方案、用户故事 31–32 及相关实现与验收描述，已由[节点编辑草稿交互修订](2026-09-07-canvas-node-editing-draft-interaction.md)的已确认决定替代。新规则为保存原节点编辑草稿、手动发送后在原卡替换素材。其余未冲突规则保持有效；修订已获用户整体确认、待实施，外部工单尚未同步。

Canvas 侧栏图片、视频和音频入口目前先打开 Dock，用户只有提交生成后才得到结果占位卡，无法在编辑之前连接参考素材。图片参考生图、图片参考生视频的创作顺序因此中断。文本添加入口能够先建节点，使同一侧栏行为不一致。

旧 Dock 本地文件选择先产生预览，发送时才上传来源素材，且不会为来源创建画布卡片；这与用户要求的“上传素材必须先进入画布，再引用”不一致。该事实仅解释既有问题，不构成新增画布外素材入口的理由。

## 解决方案

统一为“点击侧栏 → 创建生成草稿节点 → 选中并打开对应 Dock → 配置参数和参考连线 → 点击生成 → 首次结果填回原卡”。Dock 编辑当前草稿，引用列表与画布连线双向同步。取消与失败保留创作输入；成功后的再次编辑立即复制新草稿以保留原结果。

Dock 不再提供上传或画布外素材选择；新文件先通过画布上传入口放入，再被引用。视频参考角色显式指定，音频本轮保持文字输入。草稿持久保存，生成输入按提交快照冻结。

## 实现决定

### 节点与生成生命周期

1. Canvas 编排、侧栏入口、媒体节点呈现和 Dock 协同承载图片、视频、音频草稿。草稿不是已提交的 GenerationJob，也不是已接纳的 Asset；不得把待生成显示为素材缺失。
2. 侧栏每次新增并选中草稿，位置为当前可见画布中心附近空位且避开 Dock；创建、连接和编辑不提交任务。首次提交与首次结果沿用该草稿节点身份。
3. 成功卡“再次编辑”立即在原卡旁创建复制参数和输入连线的新草稿并打开 Dock；此后提交不再额外建立结果卡，原结果保持不变。
4. 失败保留卡片和输入。未改输入的重试使用失败任务快照；修改参数或引用后属于新任务，仍在该失败卡承接结果。普通取消确认后回到待生成。
5. 执行中的目标参数及输入连线只读，仍可查看或取消。来源内容后续变化不得改变已接纳任务的输入。

### Dock 与参考关系

1. 移除图片、视频 Dock 的直接上传能力；Dock 仅引用当前画布已有素材，画布上传入口继续承担新文件上传。不新增画布外已上传素材选择入口。
2. Dock 添加或移除引用与画布建立或断开对应连线双向同步；移除引用不删除来源素材。显示输入必须与新生成提交使用的输入一致。
3. 媒体参考必须具有有效媒体结果，待生成、生成中或失败卡不能作为媒体输入。文本节点维持独立文本附件语义，不隐式携带媒体。
4. 视频普通参考、首帧、尾帧由用户显式指定，不按连入顺序猜测。复用真实模型输入能力约束，不兼容时明确提示，不能静默丢弃或降级。
5. 音频仅统一草稿创建、编辑、持久化和生成生命周期，不扩展媒体或文本节点引用能力。

### 保存、任务接纳与删除

1. Canvas 保存与恢复需要承载草稿类型、状态、配置和参考关系，使已保存草稿在关闭 Dock、刷新、重开项目后恢复；具体持久化字段和迁移方案在实现计划中确定，不在此虚构新资源表。
2. 复用现有 Canvas 保存及条件写入、生成接纳、任务查询、取消和重试边界。新任务使用已保存的当前输入并形成不可变快照；延续已有文本附件、素材归属和模型能力校验。
3. 保存失败保留当前编辑并提示重试，暂停生成和项目切换，保存成功后才能继续。
4. 删除执行中卡片先请求取消，确认成功后移除。取消失败保留卡片并显示原因；请求发出或网络返回不等同于取消已成功。
5. 删除过程中任务先成功时保留结果并提示“任务已完成”，停止自动删除；用户需要再次明确删除。不得因迟到响应覆盖已确认的新状态。

## 测试决定

测试边界已由用户明确确认：“按此测试边界继续发布”。

1. 主要测试边界采用真实浏览器驱动 Canvas 和 Dock，经真实业务 API 到隔离数据库，再到可记录请求的外部生成供应商替身。沿用图片及视频文本附件公开接口集成与浏览器测试先例，尽量复用同一应用装配和测试数据准备方式，不为各组件新建一套验收入口。
2. 好测试断言外部可观察行为：卡片数量与身份、显示状态、连线、Dock 输入、刷新恢复、任务输入快照和供应商收到的参数；不依赖组件内部 state、私有函数调用顺序或固定等待时间。
3. 覆盖 Canvas 编排、Dock、持久化与生成任务生命周期的完整链路，图片/视频/音频采用同一场景矩阵；供应商替身只控制外部执行结果和时序，不替代 Canvas 保存、任务接纳或输入校验。
4. 重点场景包括先建卡且未建任务、重复创建、首次原位结果、再次编辑保留旧结果、双向引用同步、无 Dock 上传、文本附件回归、角色校验、冻结输入、失败重试与编辑后新任务、普通取消、删除取消失败与成功竞态、保存失败恢复及刷新重开。
5. 难以由浏览器稳定控制的并发与保存故障，在现有公开 API 集成边界补充确定性用例，不 mock 内部业务状态。自动化通过后进行真实页面人工回归；测试不得调用真实付费生成供应商，不使用共享生产或测试站数据库。

## 范围之外

1. Agent Prompt 创作流程重构、SceneCard 迁移、多附件排序界面及整图自动执行；已有文本附件能力只做兼容与回归。
2. 音频参考输入、未完成生成节点之间的自动依赖执行，以及扩展模型自身不支持的能力。
3. Dock 本地上传、画布外素材选择与自动导入画布；本轮移除这些 Dock 入口，不扩展替代入口。
4. 覆盖已有成功作品、因断线删除来源素材或改写历史任务快照。
5. 本次规格发布不包含产品代码实施、部署、代码推送或 PR 发布；不擅自固定数据库表、接口新字段、开发分工或排期。
