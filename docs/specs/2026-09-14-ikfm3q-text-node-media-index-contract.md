# 文本卡正文媒体索引契约 v1（IKFM3Q）

日期：2026-09-14
状态：定稿（跨层实现前的版本化契约）。
来源：IKFLZT 统一画布文本节点规格用户故事 11–20、36、39–40 与实现决策 2；在《统一文本卡正文契约 v1》（IKFM3L，下称 v1 正文契约）的区间模型上扩展，前后端以此为准，不得各自发明字段。

## 1. 权威字段

- 正文权威不变：`data.text`（受限 Markdown 源，v1 正文契约 §1）。
- 新增两个 textNode 字段：
  - `data.mediaMentions: MediaMention[]` —— 正文媒体标签区间，锚定 `data.text` 字符下标（区间语义同 v1 §3）。
  - `data.mediaRefs: MediaRef[]` —— 标签身份的展示元数据快照。
- 形状（strict，packages/contracts/src/text-node-media.ts）：
  - `MediaMention = { start, end, nodeId, assetId }`；`assetId` 为数字字符串，`nodeId` 1–128 字符。
  - `MediaRef = { nodeId, assetId, mediaType: "image" | "video" | "audio", name, url }`；`name` 1–200 字符，`url` 为素材当时地址。
- **身份 = (nodeId, assetId) 显式绑定**：nodeId 是画布来源节点身份，assetId 是素材身份。显示名称与编号都不是身份，不凭名称、位置或相似性推断对象。
- `mediaRefs` 精确覆盖 `mediaMentions` 引用的身份：每个身份有且仅有一条 ref，每条 ref 至少被一个区间引用。**不保留未被引用的身份**——mediaRefs 是展示快照，不是引用权威，更不是隐藏的附件列表（IKFLZT 特别边界）。
- 与 Agent 方案绑定共存：`promptMentions/promptMaterials` 语义与防伪造规则不变（v1 §3）；mediaMentions 是所有统一文本卡的正文媒体索引，不需要 `promptSource`。两套区间互不重叠（同一文本段不同时属于两套标签）。方案绑定是否迁移到本模型由任务 3 决定，本契约不提前定。

## 2. 编号（派生，不存储）

- 每张文本卡内，**有效**标签按正文首次出现顺序、分 mediaType 派生连续编号：`图片1`、`视频1`、`音频1`……同身份重复标签复用同一编号；删除标签后有效编号紧凑重排。
- 编号是显示态派生物，不持久化。序列化（编辑器 DOM → data.text）时把派生标签文本写回标签区间——区间切片只是显示缓存，身份与区间才是权威。
- 目标参考栏有自己的实际顺序；任务 3 提交时按稳定身份对应，不把显示编号当目标素材序号。

## 3. 有效/失效状态（派生，不存储）

- 标签有效 ⟺ 来源节点 `nodeId` 在画布存在 **且** 带 `textIndex` 标记的关系线（nodeId → 本文本卡）存在。其余一律失效。
- 失效标签显示「已失效：name」（name 取自 mediaRefs 快照），保留句子位置，不参与编号。
- 失效修复只允许两条显式路径：
  - 删除失效标签（逐标签）；
  - 重新绑定：用户经 @ 菜单显式选择新素材，**以身份为单位**——该身份的全部失效标签一并指向新来源，并建立新关系线。
- 不凭同名自动恢复，不自动补回被手动删除的关系线；同名新素材不复活旧绑定。

## 4. 关系线（来源媒体 → 文本卡）

- 有效索引 ⟹ 一条来源节点到文本卡的连线，`edge.data.textIndex = true` 标记并随连线持久化（canvasEdgeSchema 的 data 通道）。
- 生命周期事件驱动，不做全量派生同步：
  - 插入标签（新身份）→ 建线；
  - 删除某身份的最后一个标签 → 删线（删部分重复标签线保留）；
  - 画布侧删线（剪刀、选中删除等任何路径）→ 该身份全部标签失效（派生），不得自动补回；
  - 删除来源媒体节点 → 连线随节点级联删除，标签失效（派生）；
  - 重新绑定失效身份 → 替换身份并按上两条建删线；
  - 撤销/重做经画布历史栈恢复节点与连线，标签有效性随派生翻转。
- **手工拖线 媒体节点 → 文本卡一律拒绝**并提示经正文 @ 建立：关系线只反映有效索引，画布不出现无索引的媒体→文本线。
- 唯一性与多重性：同一 (source,target) 至多一条线（后端既有校验）；同一来源可被多张文本卡索引（每卡一条线）；同素材的不同画布节点是不同身份，各自成线。
- 创建副本：mediaMentions/mediaRefs 随正文复制；来源节点仍在画布的关系线同步复制（副本获得有效索引）。

## 5. @ 菜单触发、悬停预览与点击定位

- **@ 菜单触发口径（IKFUTI）**：正文任意位置**逐键输入** `@` 即弹出素材菜单——`@` 前是汉字、中文标点、英文字母、数字、空格或行首同等触发，无词边界门槛；粘贴进来的 `@` 不触发（只认逐键输入）。文本节点编辑器与底部面板编辑器同一口径（面板侧 `matchMentionQuery` 光标前文本末尾命中 `@query` 即触发，同样不看 `@` 前字符）。菜单打开后的全部交互不变：焦点进搜索框、搜索框打字实时过滤、Esc / 点菜单外 / 选中素材关闭。
- **取消关闭后的光标恢复（IKFV91）**：Esc / 点菜单外取消关闭时，焦点回正文编辑器，光标恢复到**打开菜单时的位置**——insert 模式为 `@` 后（`@` 保留为普通文本，可退格删除）；「替换来源 / 重新绑定」菜单为打开前的光标位。统一心智模型：菜单来时光标在哪，走时光标还在哪。选中素材的插入路径不变。
- **选中 / 重绑定 / 删除后的光标落点（IKFXDB）**：三条路径都经全量重放重建编辑器 DOM（编号派生/失效样式的保障机制），旧选区随旧 DOM 销毁，重放后按锚点（身份 nodeId + 同身份第几张 + 标签前/后）在新 DOM 定位 chip 恢复光标。落点口径：**选中插入**→光标落**新标签后**（插完继续写）；**替换来源 / 重新绑定**→光标落**触发替换的那张替换后的新标签后**（选中是主动改写，落点跟改写结果走；「来时在哪走时在哪」仅适用取消关闭）；**删除标签**→光标落**被删标签原位置**（优先锚前一张标签后、其次后一张标签前；正文再无标签可锚时落编辑器末尾）。锚点恢复集中在重放出口一处，三条路径共用。底部面板编辑器（Lexical）不重放 DOM，无此机制。
- **素材标签（prompt #N）同口径（IKFXDB 追加）**：操作条的「新增素材标签 / 替换素材 #N / 删除标签 #N」与 media 标签同病同修——`editMaterial` 同样全量重放销毁旧选区，锚点模型泛化为（标签种类 media|prompt + 身份 key + 同身份第几张 + 前/后）共用同一重放出口恢复。落点同上：新增/替换落标签后（同编号多张取点击的那张），删除落被删标签原位置（幸存邻居锚定、序号按删除后 DOM 计）。非编辑态操作时编辑器无在位光标：锚点暂存，进入编辑时按锚点落位（编辑器内输入后锚点作废）。
- 悬停标签：图片/视频出约 280px 静音缩略预览，音频出类型标识与名称；沿用现有 MentionChip 预览形态与延迟（约 100–200ms）。
- 点击有效标签（非编辑态）：画布平移定位来源节点并短暂高亮。编辑态点击为选中标签，弹出「替换来源 / 删除标签」操作。
- 失效标签不可定位（来源已断），点击（任意态）弹出「重新绑定 / 删除标签」修复入口。

## 6. 渲染与序列化

- 渲染：Markdown 源 + promptMentions + mediaMentions 共用 v1 §3 的占位符遮罩模型；media chip 的缩略图、编号与失效样式全部由身份与有效性派生，不信任源切片文本。
- 视觉规范同源（IKG7NH）：正文 media 标签的胶囊视觉与生成面板输入框素材标签共用同一份样式定义（`web/src/pages/CanvasPage/components/mediaChip.module.css`），禁止内联样式字符串或第二份定义回流；文本卡差异仅整块选中（user-select:all）落在 TextNode 侧——音频图标占位与缩略图包裹已随 IKGABW（生成面板补齐能力）提升进共享模块。
- 预览浮层同源（IKGABW）：本契约 §5 的悬停预览浮层视觉（chipPreview 系列）与生成面板输入框素材标签共用同一份定义（同样位于 mediaChip.module.css）；两处形态一致，仅定位机制不同（文本卡 JS 计算、生成面板 floating-ui）。
- 序列化：media 标签切片写回派生标签文本（有效 = `图片1` 类；失效 = `已失效：name`），区间锚定规范化后的 Markdown 源（同 v1 §3）。
- 复制/粘贴：media 标签不参与富文本跨卡复制——text/plain 只携带标签字面文本，粘贴为普通文字；prompt 绑定的 `application/x-blue-whale-prompt` 通道不变。

## 7. 保存校验（backend canvas.service.ts save）

textNode 携带 `mediaMentions` 或 `mediaRefs` 时（缺省其一即拒绝，两字段须同现同缺）：

1. `mediaMentionSchema` 校验 + `validMediaMentions`：区间不重叠、不越界、同 nodeId 恒同 assetId。
2. mediaRefs 与 mentions 身份集合精确一致（§1）。
3. **新增身份**（上一版本该节点 mediaRefs 中不存在）：
   - 素材真实可及：`assets` 存在、归属当前用户、`is_delete=false`、`status="normal"`、`type=mediaType`、`url` 与素材一致（防伪造核心，与 promptMaterials 新增校验同口径）；
   - 若 nodeId 节点在本次保存节点中存在：必须是 mediaNode，节点 assetId 与本身份一致，节点 mediaType 与 mediaType 一致（身份一致性；节点不存在即来源已删的失效身份，豁免）。
4. **存量身份**：展示元数据不可变（nodeId/assetId/mediaType/name/url 逐项一致），引用可减不可伪造；失效身份（来源节点/连线/素材已不存在）允许继续携带并编辑正文。
5. 非 textNode 携带这两字段拒绝。
6. `promptSource` 防伪造规则不变（v1 §3）。节点与连线同一条件写入（saveIfVersion），保存要么全成要么全败。

## 8. 恢复一致性（用户故事 36）

刷新恢复 = 节点 JSON（data.text + mediaMentions + mediaRefs）+ 连线 JSON 同一事务读写；有效性、编号、失效展示全部由（节点， 连线）当时状态派生。不存在只有正文或只有连线的半恢复：标签在则身份在，线删则标签失效，源删则标签失效。

## 9. 测试接缝

- 契约单测（packages/contracts）：schema、validMediaMentions、编号派生、失效标签文本、refs 覆盖判定。
- 组件单测（web TextNode promptMentions 模块）：含 media 标签的渲染/序列化——编号复用与重排、失效文本、与 prompt 绑定混合。
- 后端集成（隔离 MySQL，`IKFM3Q_DATABASE_URL` 门控，沿用 text-node-unified 模式）：合法新增落库、伪造身份/越界/refs 不覆盖/非 textNode 拒绝、存量失效身份豁免编辑。
- 浏览器 e2e（Playwright + 动态画布夹具，沿用 text-node-layout 模式）：@ 插入三类、编号复用与重排、删最后标签除线、删线置失效不自动补回、删源节点置失效、重新绑定、悬停预览、点击定位、刷新恢复；核对 PUT body 的 nodes+edges 并截图。

## 10. 版本演进边界

- 本契约不改变生成输入：索引同步到目标参考栏、失效阻止发送、「输入已更新」提示由任务 3 建立，任务 4/5 扩展；届时按 (nodeId → assetId) 当时解析建立目标参考。
- 不引入文本卡附件列表、文本互引、表格/代码块/链接等 v1 子集外格式，不复活 `data.html` 通道。
- worker-java 只消费生成冻结快照，本契约不改变其输入形态，零适配。
