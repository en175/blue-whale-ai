# Canvas 四类节点卡片布局优化规格

## 时间

2026-09-05

## 状态

用户已确认 Q1–Q10 的全部产品设计。本文件将讨论结果整理为可实施、可验收的 spec，替代本文件此前的设计对齐记录。产品代码尚未修改；测试切入点已由用户于 2026-09-05 确认。

关联需求：[IKDICP — Canvas 四类节点卡片布局优化](https://gitee.com/hangzhou-xuanfu_1/blue-whale-ai/issues/IKDICP)，标签 ready-for-agent。

## Problem Statement（问题陈述）

用户在 Canvas 中同时浏览图片、视频、文本和音频时，当前卡片把类型、名称、元信息和正文包在同一个深色容器里。图片与视频最多显示为宽 280px、高 360px，而文本采用另一组最小尺寸，导致不同内容的视觉尺度与信息层级不统一。

内置标题栏占据内容容器，边框与常驻连接点抢占注意力；名称和元信息的位置也不符合参考设计。文本卡片已有外部操作条和编辑工具栏，如果直接再加外部标题，会造成重复标签与操作区挤占。

用户希望参考新截图，形成“外置标题行 + 独立内容区”的统一呈现。横竖媒体按短边建立协调的观看尺度，文本与音频使用固定比例，同时保留用户已建立的空间编排与现有操作。

这里的“卡片”指 Canvas 内节点的视觉呈现，不是领域词汇表中的对话 Card，也不新增 NodeItem、Asset 等产品资源类型。

## Solution（解决方案）

图片、视频、音频、文本四类节点采用同一套信息编排：内容区上方常驻一行标题，左侧显示类型图标与现有名称，右侧显示该媒体适用的元信息。媒体内容自身构成圆角主体，去掉将标题与内容包在一起的深色顶栏，减弱边框。

图片和视频保持原始比例、完整展示。默认短边为 280px；长边超过 840px 时，整体等比例缩小。文本内容区固定为 360×270px，超出的正文在卡片内部上下滚动；音频内容区固定为 280×280px，保留播放器。

选中操作工具栏放在标题上方，文本格式工具栏使用同一层操作位置。连接点平时隐藏，仅在悬停、选中或正在连接时显示，并定位在内容区左右两侧的中点。

本轮只修改单张节点的布局与呈现。已有节点位置、自由投放和拖动行为保持；卡片变大后可能出现的重叠由用户自由拖动整理，不自动移动其他节点。

## User Stories（用户故事）

### 浏览与信息层级

1. 作为 Canvas 用户，我希望图片节点的标题位于内容区外部，以便直接关注图片本身。
2. 作为 Canvas 用户，我希望视频、音频与文本采用一致的标题编排，以便在混合内容中快速识别节点。
3. 作为 Canvas 用户，我希望未选中卡片时仍能看到标题，以便不必逐个点击才能辨认内容。
4. 作为 Canvas 用户，我希望标题左侧显示类型图标与现有名称，以便沿用已有的文件名和生成名称寻找素材。
5. 作为 Canvas 用户，我希望图片边框和深色外壳更轻，以便画布呈现内容而不是突出容器。

### 媒体尺寸与比例

6. 作为 Canvas 用户，我希望竖版图片以宽度作为短边基准、等比例计算高度，以便保持原始构图。
7. 作为 Canvas 用户，我希望横版图片以高度作为短边基准、等比例计算宽度，以便横图与竖图具有协调的展示尺度。
8. 作为 Canvas 用户，我希望视频遵循与图片相同的比例规则，以便静态和动态素材在同一画布中协调呈现。
9. 作为 Canvas 用户，我希望方形媒体呈现为 280×280px，以便得到可预期的默认尺寸。
10. 作为 Canvas 用户，我希望极长或极宽的媒体受到 840px 长边上限约束且不被裁切，以便查看完整内容而不无限占据画布。

### 文本与音频

11. 作为 Canvas 用户，我希望文本正文位于 360×270px 的固定内容区，以便长短不同的便签保持稳定外形。
12. 作为 Canvas 用户，我希望超出文本可用区域的内容可以上下滚动，以便阅读全文而不撑大卡片。
13. 作为 Canvas 用户，我希望继续使用已有富文本编辑能力，以便修改内容时不丢失当前编辑体验。
14. 作为 Canvas 用户，我希望音频节点使用 280×280px 的方形内容区，以便与其他节点形成一致的尺度。
15. 作为 Canvas 用户，我希望音频播放器保持可操作，以便直接在画布中播放和查看音频。

### 名称与元信息

16. 作为 Canvas 用户，我希望图片标题右侧显示原始分辨率，以便辨认素材本身的清晰度与规格。
17. 作为 Canvas 用户，我希望视频标题右侧显示原始分辨率和时长，以便快速判断素材是否适合当前创作。
18. 作为 Canvas 用户，我希望音频标题右侧显示时长、文本右侧保持留空，以便只看到适用的信息。
19. 作为 Canvas 用户，我希望缺失的信息留空且分辨率不随画布缩放变化，以便不会把占位尺寸或展示尺寸误认为原文件信息。
20. 作为 Canvas 用户，我希望沿用现有名称并在详情查看文件大小，以便布局调整不改变命名规则且标题保持简洁。

### 选中、编辑与连接

21. 作为 Canvas 用户，我希望选中后的操作工具栏出现在标题上方，以便执行原有操作时仍能看清标题与内容。
22. 作为 Canvas 用户，我希望文本编辑工具栏与节点操作工具栏不叠放，以便编辑时不会发生控件遮挡。
23. 作为 Canvas 用户，我希望连接点在平时隐藏、悬停或选中时显示，以便需要操作时能找到入口，浏览时减少干扰。
24. 作为 Canvas 用户，我希望正在连接时相关连接入口保持可见且锚定内容区中点，以便准确连接到节点。
25. 作为 Canvas 用户，我希望拖动、播放、富文本编辑和右键菜单继续工作，以便视觉调整不损失现有能力。

### 加载、状态与既有编排

26. 作为 Canvas 用户，我希望生成中或加载中的媒体在已有可信比例时就按该比例占位，以便预先理解结果的展示形状。
27. 作为 Canvas 用户，我希望未知比例的媒体先显示 280×280px 占位，以便信息不足时仍有稳定可见的节点。
28. 作为 Canvas 用户，我希望实际尺寸取得后只更新卡片大小、保留节点位置，以便素材加载不会打乱我的空间编排。
29. 作为 Canvas 用户，我希望失败、取消或素材缺失时保留已知比例及已有提示与操作，以便了解状态并继续按现有方式处理。
30. 作为 Canvas 用户，我希望刷新后沿用保存的节点位置、自由拖动整理可能出现的重叠，以便新版卡片尊重我原有的画布布局。

## Implementation Decisions（实现决策）

### 范围与模块边界

1. 媒体节点呈现模块负责图片、视频、音频的统一外部标题、内容容器、尺寸、状态占位和元信息；文本节点呈现模块负责固定正文区、内部滚动和编辑操作区。
2. 画布节点集成层负责适配真实节点测量、连接锚点与既有交互，保证内容大小变化不会触发重排或改写节点位置。
3. 本轮不新建产品资源，不改变 Asset 身份、内容或现有名称，不修改数据库 schema 或公开 API 合同；布局计算属于前端呈现。
4. 尺寸判断优先复用已有媒体数据及浏览器可取得的真实媒体尺寸；若当前数据通路缺少已知比例，可在现有前端节点数据传递中补齐所需信息，不另造服务端事实。
5. 复用现有组件与回调。当前没有四类节点通用的卡片外壳；是否提取小型共享呈现组件由实施时的实际重复决定，本 spec 不要求建设通用卡片框架。

### 内容区尺寸

所有尺寸指画布缩放 100% 时的内容区，外置标题与工具栏另算。图片和视频不裁切、不拉伸。

| 类型或比例 | 内容区尺寸 |
| --- | --- |
| 图片、视频通用规则 | 默认短边 280px，长边按原比例计算，最大 840px |
| 3:4 / 4:3 | 约 280×373px / 373×280px |
| 16:9 / 9:16 | 约 498×280px / 280×498px |
| 1:1 / 1:10 / 10:1 | 280×280px / 84×840px / 840×84px |
| 文本 / 音频 | 360×270px / 280×280px |

已知原始宽高 W、H 时，缩放系数为 min(280 / min(W, H), 840 / max(W, H))，展示宽高分别为 W 与 H 乘以该系数。该规则允许小尺寸原图放大到默认展示基准；标题仍展示原文件分辨率。比例计算保留精度，渲染允许正常的亚像素取整误差。

文本的 360×270px 包含内容容器内的留白；正文在剩余可用空间内滚动，不能在固定高度外再叠加正文高度。音频的 280×280px 包含播放器所在的内容容器。

### 标题与元信息

| 节点 | 左侧名称 | 右侧信息 |
| --- | --- | --- |
| 图片 | 现有文件名或生成名称 | 原始分辨率 |
| 视频 | 现有文件名或生成名称 | 原始分辨率与时长 |
| 音频 | 现有名称 | 时长 |
| 文本 | 文本节点 | 留空 |

1. 标题常驻内容上方，使用画布背景，不保留原来的内置深色标题栏；类型图标与名称在左、元信息在右。
2. 不新增自定义命名和自动编号，原有名称数据不被重写。名称过长时沿用截断呈现能力，避免挤出卡片边界。
3. 原始分辨率与内容展示尺寸分开；临时目标比例和方形占位不能用来伪造原始分辨率。
4. 元信息缺失时对应项留空；可用的信息仍正常展示。文件大小放在详情中，不占用标题行。
5. 图片和视频以独立圆角内容主体呈现，弱化容器边框；文本保留清晰的正文容器与内边距。参考图的 JSON 不带来代码编辑或语法高亮需求。

### 操作区、连接点与交互

1. 常驻标题位于内容区上方，选中操作工具栏位于标题上方，两者不相互覆盖。
2. 文本编辑时格式工具栏使用同一层操作位置，避免与原有节点操作条叠成多行；原有“添加到对话”等能力保持可达。
3. 连接点平时隐藏，悬停、选中或正在连接时显示，定位依据为内容区左右两侧中点，不能因标题移出而锚定整个标题加内容容器的中点。
4. 标题和内容区域遵循现有节点拖动语义；播放器控件、编辑区与操作按钮继续保持各自输入行为，不能因结构变化被节点拖动吞掉操作。
5. 连线仅调整呈现，沿用现有连接行为；不增加连线保存、生成依赖、执行引擎或自动工作流。

### 状态、尺寸来源与位置保持

| 情形 | 内容区处理 | 元信息处理 |
| --- | --- | --- |
| 图片/视频生成中或加载中，已有可信目标比例或原始尺寸 | 按比例应用短边基准与长边上限 | 仅显示已知真实元信息，不把目标比例换算成原文件分辨率 |
| 比例和尺寸均未知 | 280×280px 占位 | 缺失项留空 |
| 随后取得实际尺寸 | 按真实比例更新大小，保持节点位置 | 显示已取得的真实元信息 |
| 失败、取消或素材缺失 | 保留已知比例对应的大小；仍未知则 280×280px | 沿用已知信息及原有状态提示、操作 |
| 文本、音频的各种适用状态 | 分别维持 360×270px、280×280px | 按该类型的信息规则展示 |

不修改已保存的位置，不触发全局排列，不因某张卡片完成加载而移动邻近卡片。外观变大导致既有密集布局重叠是已接受的影响，保留用户自由整理能力。

### 兼容边界

当前媒体卡片已有工具栏、生成占位、失败提示、素材缺失提示及右键菜单；文本已有富文本编辑器、外部操作条和格式工具栏。这些属于本次必须保留的行为，不因重做外观而替换为简化占位实现。

已有数据中部分节点没有完整原始宽高。必须区分“暂时不知道尺寸”与“素材不存在”；不能因缺少尺寸把正常素材判为缺失，也不能为了填满标题伪造元信息。

保留已有节点类型、标识、名称、媒体引用、位置和持久化通路，不做旧数据批量迁移。本 spec 的视觉术语不改变领域词汇表中的 Canvas、NodeItem、Asset 和对话 Card 定义。

## Testing Decisions（测试决策）

### 确认状态与主要切入点

以下测试方案已由用户明确确认，作为后续实施的测试切入点。

以现有 Canvas 节点集成边界作为主要测试入口：挂载真实画布与真实节点组件，输入节点数据和状态，模拟用户选择、编辑、拖动与状态更新，观察可见内容和对外行为。尽量在一个集成入口覆盖四类卡片，不为每个 CSS 类或内部函数新建测试边界。

复用已有媒体节点组件测试作为回归底线，不为追求单一入口删除已有有效测试。真实浏览器验收使用同一画布页面，负责验证 jsdom 无法可靠证明的布局、裁切、滚动、命中和遮挡。

### 什么是有效测试

1. 断言用户能看到的名称、元信息、提示和可执行操作，以及交互后的位置与内容；不依赖内部 state、组件层数或私有 helper 名称。
2. 用数据和实际媒体加载事件覆盖比例已知、比例未知、取得真实尺寸及失败/缺失转移，验证大小和元信息语义。
3. 实际边界框、可见滚动区域、连接点命中和工具栏遮挡由真实浏览器验证；jsdom 的伪测量值不能证明视觉像素正确。
4. 不以“某个 CSS 类存在”、整份 CSS 文本快照或实现公式的逐行复制作为完成证据。
5. 自动化测试的替身仅放在媒体网络、外部请求或无法由 jsdom 提供的浏览器能力边界；画布和节点交互优先使用真实实现。

### 实施阶段检查

实施时按仓库前端工作流和影响面测试策略执行类型检查、静态检查及定向测试。真实浏览器验收记录所用媒体比例、节点状态与可观察结果；自动化逻辑通过不替代视觉验收。

本次撰写 spec 仅进行文档验证，不宣称上述产品测试已完成。

## Out of Scope（范围之外）

### 布局与节点能力

1. 自动排列、新增节点自动避让、吸附对齐、批量重排或解决既有重叠。
2. 商品卡、角色等其他资产卡的外观重做。
3. 节点自定义命名、自动编号、手动缩放卡片的新交互。
4. 新的连线保存机制、编组、生成依赖或工作流执行。
5. 文本代码编辑器、JSON 语法高亮或富文本能力重构。

### 数据与交付

1. 数据库迁移、新产品资源、公开 API 合同改造、历史数据批量补齐。
2. 媒体文件裁切、拉伸、转码、内容修改或以相同 Asset 身份替换原文件。
3. 生成流程、供应商、任务状态语义及后端流水线改造。
