# Canvas 媒体节点编辑草稿持久化与原卡重新生成

## 时间

2026-09-07

已发布至现有任务：[IKDMQU — 【前端】成功卡原卡编辑与重新生成](https://gitee.com/hangzhou-xuanfu_1/blue-whale-ai/issues/IKDMQU)，标签 `ready-for-agent`。已回读核验完整正文与项目、仓库归属；工单原有进行中状态保持。

## 问题陈述

创作者在 Canvas 生成图片、视频或音频后，无法通过选中成功节点稳定恢复对应生成面板、最新提示词和完整配置。修改输入后离开节点，也无法可靠继续上次编辑。再次生成还可能新增卡片，使用户无法在原位置持续迭代同一素材。

源码核查表明，已有节点能够保存生成提示词，缺口主要在成功节点选中后的面板回填、编辑与节点持久化绑定、音频支持及原卡承接新结果。不能将问题描述为所有提示词均未保存。

## 解决方案

单选有生成记录的图片、视频或音频节点时打开对应生成面板，恢复节点编辑草稿。修改提示词和配置自动持久化，仅保留最新编辑内容；点击空白或多选隐藏面板，不丢弃编辑。上传素材不自动打开生成面板。

只有手动点击发送才重新生成，Enter 仅换行。重新生成固定为 1 个结果，全程沿用原卡身份、位置和引用连线；生成中继续显示旧素材，成功后替换，失败或取消保留旧素材与最新编辑。下游已有结果不自动改变，执行中的任务保持提交快照，下次手动生成使用替换后的素材。

## 实现决定

### 节点编辑草稿与持久化

1. 使用领域术语“节点编辑草稿”表示节点持有的最新提示词与完整生成配置。它可与当前显示素材的原生成输入不同，不是独立新卡，也不是提示词版本历史。
2. 复用现有 Canvas 保存、恢复及条件写入能力，使图片、视频、音频节点的编辑内容持久化。面板输入必须绑定目标节点，切换或迟到的保存响应不得将内容写入其他节点。
3. 用户将 A 改为 B 后，节点恢复 B；不新增 A 的查看、恢复或版本管理功能。既有 GenerationJob 输入快照与审计记录继续保留，不以此需求为由删除历史任务数据。
4. 恢复媒体类型适用的完整配置，沿用真实模型能力、素材归属与有效性校验；不可用或不兼容时明确提示并阻止发送，不静默丢弃、替换模型或降级。
5. 具体持久化字段与必要的数据兼容方式应基于最新实现确定，不预设新增数据库表或资源类型，不虚构缺失的历史配置。

### 选择与面板接口

1. Canvas 选择编排与三类生成面板建立明确的节点绑定、初值恢复和编辑回写关系；音频需要补齐对应能力。
2. 单选有生成记录的媒体节点展示对应面板；空白和多选隐藏；上传素材保持现有选中行为。
3. 面板隐藏不代表删除或丢弃编辑。不同节点的提示词和参数彼此独立，不因面板复用而串写。
4. 三类面板的提示词输入 Enter 均仅换行，创建生成任务只由手动点击发送触发。
5. 保存失败保留编辑并提示重试，暂停切换编辑目标、发送和项目切换；允许空白隐藏，保存成功后恢复操作。

### 原卡重新生成

1. 已有成功节点的再次编辑与发送都不新增卡片。复用任务接纳与执行链路，令新结果承接到原节点；节点身份、位置与引用连线保持。
2. 原卡重新生成固定为 1 个结果；面板恢复历史配置时也受此约束。该决定不改变侧栏新建草稿的数量规则。
3. 发送前保存当前编辑，接纳时冻结任务输入。生成期间目标配置与输入连线只读，仍允许查看和取消。
4. 旧有效素材与本次生成状态需要同时表达。生成期间显示旧素材与生成状态，成功后替换当前素材引用；失败或取消保留旧素材及最新编辑，失败显示原因。
5. 原卡替换指更新节点所展示的素材，不等于覆盖旧素材文件或删除历史 Asset。复用现有任务查询与恢复机制，迟到响应不得覆盖已确认的新状态。

### 引用与现行契约

1. 引用连线保持绑定节点，目标节点下次手动提交时解析当前有效素材；已有结果不变，已提交任务只使用冻结快照。
2. 替换素材不触发下游自动生成，不改写下游历史任务。
3. 既有文本附件、视频参考角色、当前画布引用与音频文字输入能力保持；本需求不扩展音频引用能力。
4. 既有删除、取消确认与成功竞态保护规则继续适用；本次重点是已有有效结果节点重新生成，不将首次失败草稿与保有旧素材的节点混为一谈。
5. 本规格替代成功卡“再次编辑立即复制新草稿”及“重新生成另建结果卡”的旧决定，侧栏新增草稿等未冲突行为保持。

## 测试决定

用户已确认：“按此测试边界继续发布。”

### 主要验收链路

1. 优先复用真实浏览器驱动 Canvas 和 Dock，经真实 Canvas／生成业务 API、隔离数据库与生成执行链，到可记录请求和控制结果时序的外部生成供应商替身；尽量共享一套应用装配及数据准备入口。
2. 已核实文本附件图片集成测试具有生产控制器与服务、隔离 MySQL、浏览器操作和刷新恢复先例。现有这条 API／浏览器用例不等于已覆盖供应商执行闭环，本需求应将原卡替换结果纳入完整验收。
3. 好测试断言用户可见行为、持久化内容、节点数量与身份、连线、创建任务数量、冻结输入及供应商实际请求。不依赖组件内部状态、私有函数调用顺序或固定等待时间。
4. 图片、视频、音频使用同一行为矩阵覆盖面板选择、最新编辑恢复、完整配置、显式发送、单结果原卡替换与失败保护。
5. 供应商替身只替代外部生成服务；不以模拟 Canvas 保存、任务接纳或内部业务状态代替持久化及生成集成验收。

### 核心场景

1. 编辑 A 为 B 后不发送，隐藏、重选和保存后刷新恢复 B；配置恢复完整；选中上传素材、多选及空白按规则显示或隐藏。
2. 编辑、自动保存与 Enter 均不创建任务；点击发送先保存最新输入，再产生一次单结果生成，节点数量与身份不变。
3. 生成中保留旧素材，成功原卡替换，失败或取消保留旧素材与最新编辑；刷新恢复后仍与持久化结果一致。
4. 替换来源后连线保持、下游下次手动任务使用新素材、执行中任务保持旧快照、已有结果不变且不自动创建下游任务。
5. 保存失败时编辑保留且切换目标、发送与项目切换被暂停；空白仍能隐藏；重开原节点可继续重试，保存成功恢复操作。模型或参考不可用时必须有可见提示并禁止未调整的发送。

### 补充验证

难以由浏览器稳定控制的保存故障、并发和迟到响应，在现有公开 API 集成边界补充确定性用例。自动化通过后保留真实页面人工验收；功能验收与仓库发布门禁分别报告。测试不调用真实付费生成供应商，不使用共享生产或测试站数据库。以上是实施要求，本次规格发布未运行功能测试。

## 范围之外

1. 提示词版本历史、旧提示词恢复、历史任务快照清理及历史 Asset 删除。
2. 上传素材自动打开生成面板、原卡重新生成产生多个结果或新卡、改变侧栏新增草稿规则。
3. 下游自动执行、修改已提交任务输入、扩展模型能力或音频参考输入。
4. Agent Prompt 创作重构、SceneCard 迁移、Dock 上传或画布外素材选择入口。
5. 本次规格发布不包含产品实现、代码推送、PR、合并或部署，也不新增重复实施任务。
