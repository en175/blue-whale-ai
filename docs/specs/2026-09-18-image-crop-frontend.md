# 图片裁切（前端本地执行）规格

> 需求共识来自 2026-09-18 两轮 grilling（15 项拍板，Kim 已确认共享理解）。需求工单 IKGV2J（ready-for-agent）。术语以根 CONTEXT.md「画布图片裁切」节为准，关键取舍见 ADR-0096。

## Problem Statement

画布图片素材卡选中后的工具栏没有裁切工具。用户想把一张图裁成目标比例或裁掉边缘区域，只能把图下载到本地、用外部工具处理后再传回来，链路断裂且丢失来源关系。

## Solution

在图片卡工具栏「高清 ▾」下拉菜单中新增「裁切」项（位于扩图与擦除之间）。点击进入裁切模式：源图卡上出现只许向内收的裁切框（4 边 + 4 角手柄），面板提供五个默认比例（1:1、4:3、3:4、16:9、9:16）与自由模式。裁切在前端本地完成，不调用生成服务；确认后立即在源卡右侧创建「裁切」成品卡并拉纯视觉来源连线，源图卡保留。

## User Stories

1. 作为画布用户，我想在图片卡工具栏的「高清 ▾」下拉里看到「裁切」项，这样不用离开画布就能裁图。
2. 作为画布用户，我想让「裁切」排在「扩图」之后、「擦除」之前，这样画质类工具的顺序稳定可预期。
3. 作为画布用户，我想让任何有有效图片素材的成品卡都能用裁切（上传图、生成图、webp、gif 均可），这样不必关心格式与尺寸限制。
4. 作为画布用户，我点击「裁切」后源图卡进入裁切模式、出现裁切框与面板，这样可以直接在图上操作。
5. 作为画布用户，进入裁切模式时默认自由比例、框为全幅，这样每次都是干净起点。
6. 作为画布用户，进入裁切模式时五个生成面板自动关闭，这样界面聚焦在裁切上。
7. 作为画布用户，我可以在面板选择 1:1、4:3、3:4、16:9、9:16 或自由，这样常见比例一步到位。
8. 作为画布用户，选中默认比例后裁切框自动变为内容区内最大内接该比例的矩形并居中，这样不用手动对齐。
9. 作为画布用户，锁定比例时边手柄禁用并视觉弱化、只有角手柄可拖，拖角以对角为锚等比缩放，这样比例不会被破坏。
10. 作为画布用户，自由模式下我可以拖 4 条边做单边调整，这样精细控制一条边。
11. 作为画布用户，自由模式下我可以拖 4 个角同时改宽高，这样快速改框。
12. 作为画布用户，自由模式下按住 Shift 拖角可临时锁定比例，这样与扩图手势一致。
13. 作为画布用户，我可以在框内按住拖动整体平移裁切框，这样把框挪到目标区域。
14. 作为画布用户，平移与缩放时框始终钳制在原图内容区内，这样不会裁出图外。
15. 作为画布用户，裁切框最小收到结果短边 64 像素（自然分辨率口径），这样避免拖出不可用的框。
16. 作为画布用户，编辑期间我可以缩放、平移画布，裁切框跟随内容区，这样大图裁小区域也能精确操作。
17. 作为画布用户，我点确认完成裁切并立即看到结果，这样没有等待。
18. 作为画布用户，我可以点面板取消、按 Esc、点框外暗区或画布空白退出，退出即丢弃、不留任何痕迹，这样误进零成本。
19. 作为画布用户，我点其他卡时裁切模式退出并丢弃，这样不会误留半成品状态。
20. 作为画布用户，同一时刻只有一张卡处于裁切模式，这样状态不互相干扰。
21. 作为画布用户，确认后在源卡右侧紧邻位置出现「裁切」成品卡（无草稿、无生成中过渡），这样即时拿到结果。
22. 作为画布用户，裁切卡与源卡之间有纯视觉来源连线，这样知道图的来历。
23. 作为画布用户，裁切按原图自然分辨率执行，这样画质不因画布缩放而降低。
24. 作为画布用户，产出格式跟随源图（JPEG 源出 JPEG 约 0.92 质量、PNG 源出 PNG、判不出时 PNG 兜底），这样文件不会莫名膨胀。
25. 作为画布用户，裁切卡不自动抢选中、源卡保持选中，这样选中态不跳变。
26. 作为画布用户，裁切卡可以再次裁切、擦除、扩图、高清放大，这样家族工具在结果侧闭环。

## Implementation Decisions

- 菜单：「高清 ▾」下拉为数组配置驱动，裁切以菜单项插在扩图与擦除之间，下拉组件本身不改；裁切项无置灰门槛（disabledReason 恒为空），生成中、草稿、失败卡不显示该工具栏由既有可见性规则管理。
- 执行通道：浏览器端离屏 canvas 按原图自然分辨率裁切，产物经既有资产上传链路入库；不新增任务类型、不进 worker、无网关配置、零 API 成本（ADR-0096）。
- 模式进入：点裁切关闭五个生成面板（同擦除口径），源图卡置为裁切编辑态；裁切框为屏幕空间覆盖层，作为 ReactFlow children 渲染拿 viewport context，手柄尺寸恒为屏幕像素，渲染期从 flow 坐标换算跟随内容区（复用扩图扩展框机制，方向镜像为向内收）。
- 初始状态：默认自由比例、框等于整个图片内容区，不记忆上次状态。
- 比例选择：六选项（1:1、4:3、3:4、16:9、9:16、自由）。选中默认比例即锁定：初始框为内容区内最大内接该比例矩形、居中；边手柄禁用并视觉弱化，角手柄以对角为锚等比缩放。
- 自由模式：拖边单边调整、拖角自由改宽高、按住 Shift 临时锁比例（锁拖动开始那一刻的比例，同扩图手势）、框内拖动整体平移并钳制在内容区内。
- 最小尺寸：裁切结果短边不小于自然分辨率 64 像素。
- 退出：确认、面板取消、Esc、点画布空白或框外暗区四路退出，确认前退出不留任何痕迹（无卡、无边、无状态残留）；点其他卡等同点外退出；编辑期间允许画布缩放平移。
- 结果落地：确认后在源卡右侧紧邻位置新建「裁切」成品卡（fileName「裁切」，同高清 fileName 先例），直接显示裁切结果，拉纯视觉来源连线；源卡保留、新卡不抢选中。
- 格式：产出跟随源图（JPEG 约 0.92、PNG、判不出 PNG 兜底）。
- 代码组织：定位计算拆同名纯函数文件 imageCrop.ts（内收缩放、锁比例、平移钳制、64 像素下限、最大内接比例框、格式决策）配套 imageCrop.test.ts，与组件分离，打法参考扩图 imageOutpaint.ts；比例选择器视觉复用共享 RatioIcon 组件。
- 分支基线：基于当前 release 分支开工；扩图整包（IKGOQ0，已完成未发布）发布时对下拉宿主数组机械合并，组件不动。

## Testing Decisions

好测试的标准：只测外部可观察行为，不测实现细节；一个行为一条断言主线；测试数据就地构造不依赖环境。

经 Kim 确认，本需求共三层测试接缝，全部复用现有测试打法，不新增测试设施：

1. **裁切纯函数层**（vitest 纯函数，先例 imageOutpaint.ts 同名纯函数测试）：内收拖边单边换算、拖角自由换算、锁比例对角锚等比缩放、Shift 临时锁比例、框内平移钳制、64 像素自然分辨率下限、最大内接比例框（居中）、产出格式决策（跟随源图、判不出 PNG 兜底）。这层是交互正确性的主要保险。
2. **组件级 jsdom**（先例 EraseMaskLayer.test.tsx、OutpaintFrame.test.tsx、ImageQualityMenu.test.tsx）：菜单项顺序与无置灰断言、裁切框组件指针交互（pointer 事件驱动平移与缩放、锁比例下边手柄不可拖）、裁切面板六选项切换与确认取消。
3. **页面级真实画布夹具**（先例 eraseEdit.test.tsx Canvas 页面级套件）：进入裁切模式关闭五个生成面板、四路退出丢弃不留痕（无卡无边无状态残留）、确认后建成品卡加来源连线且新卡不抢选中、编辑期间点其他卡触发退出、裁切结果卡可再次进入裁切（家族闭环）。

canvas 编码产出（toBlob）在 jsdom 里 mock，真实编码行为不进自动化（同擦除遮罩栅格化处理），由人工回归覆盖。

## Out of Scope

- 替换原图卡的就地裁切（本期一律新建结果卡，源图保留）。
- 记住上次框位置或比例选择。
- 数值输入精确尺寸、自定义比例数值输入。
- 旋转、翻转等正交变换；圆形裁切、异形遮罩。
- 多张批量裁切、视频裁切。
- 后端任务化与计费（纯前端本地执行，无任务、无网关、无计费语义）。
- 「高清 ▾」下拉按钮改名。
- 移动端触屏专项优化（pointer 事件天然兼容，不做专项）。

## Further Notes

- 裁切是「高清 ▾」家族中唯一不经任务链路的工具：无网关前置、无错误码契约，工单可纯前端交付，改动严格限定 web 目录。
- 与扩图（IKGOQ0 整包，已完成未发布）存在一处菜单数组合并点，发布时机械合并，组件不动。
- 输出为 canvas 重编码：JPEG 有一代编码损失（质量约 0.92），PNG 无损但体积可能大于源文件；连环裁切同格式时损失逐代累积，属可接受边界。
- 64 像素下限以原图自然分辨率为口径，与画布缩放和显示尺寸无关；裁切结果分辨率只由源图与框决定，恒不放大。
- 上线验收走本地 3000 环境人工回归：重点覆盖真实编码质量（JPEG 视觉无损度）、裁切卡显示与来源线、家族工具在裁切卡上的闭环可用性。
- 领域词条见 CONTEXT.md「画布图片裁切」节（裁切、裁切模式、裁切框、裁切卡四条）；关键取舍见 ADR-0096。
