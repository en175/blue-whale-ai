# 画布音频混合规格（AI MediaKit）

## 时间

2026-09-23

## 状态与目标

**已确认**：Kim 于 2026-09-23 确认本规格（含 API 依据与原型交互）。本文是后续实施与验收依据，当前**没有实现音频混合产品代码**。用户在画布选中一张已完成的音频卡，从工具栏「混合」进入源卡下方的单行发送条，添加其他音频并选择输出格式。所有输入从 00:00 同时叠加，原卡保留，结果以新的音频卡呈现。供应商任务异步执行，生成前没有混合试听。

术语以根目录 `CONTEXT.md`「画布音频混合」为准。本文将用户提供的 PDF 中的 API 限制、官方提交接口的补充字段，以及已确认原型中的可见交互同时固定下来。

## 已确认的产品边界

| 项目 | 规则 |
| --- | --- |
| 入口 | 仅已完成、可用的画布音频成品卡显示可点击「混合」；位于卡片悬浮工具条第三位，顺序沿用「截取、调速、混合、音视频合成、转码、下载」。 |
| 输入 | 点入口的卡是不可移除的固定源；可从画布音频卡、资产库或本地上传后入库的音频补充。一次提交 **2–100 段**（含固定源），以 `assetId` 去重，固定源对应的同一资产也不得再加入。节点身份用 `nodeId`，不靠文件名、画布位置或 URL 猜测。 |
| 混合语义 | 全部音频从 00:00 同时开始；短音频结束后不循环，输出持续至最长音频结束。不提供逐轨音量、起点偏移、淡入淡出、裁剪、排序编排或预混试听。 |
| 输出 | 新建结果卡，源卡和全部输入素材不变。输出格式为 `mp3`、`m4a`、`ogg`、`flac`、`wav`，默认 **MP3**；始终显式向供应商传 `format`。结果时长以供应商返回的 `result.duration` 为最终值。 |
| 费用 | 本期免费；发送条显示「⚡0 本期免费」，业务创建不预留积分、不走余额拦截，网关对客模型价格必须显式配 0。 |
| 来源 | 结果卡分别与本次参与的**所有画布音频卡**建立来源线，包含固定源；从资产库或本地上传加入而未在画布上选中的输入不凭空建卡或连线。来源线只表达溯源，不占音频生成参考位、不参与 @ 编号。 |
| 失败重试 | 失败保留结果卡并提供「重试」；重试复用**首次提交时冻结的资产、画布来源和格式**。如需改输入或格式，从源卡重新发起一次混合。 |

## 已确认的原型交互

**原型主证据**：本地分支 `chore/音频混合交互原型`，提交 `4366222fa`，文件 `web/prototypes/audio-mix.prototype.html`。可用 `git show 4366222fa:web/prototypes/audio-mix.prototype.html` 查看。原型是一次性评审件，不并入产品代码；本节是无需运行原型即可实施的交互契约。

### 布局与视觉

- 源音频卡沿用现有 `MediaNode` 的 480×240 深色卡、深槽波形、红色播放头和居中圆形播放钮；悬浮工具条、选材浮层及发送条复用仓库 `variables.css` 的深色浮层、描边、阴影、蓝色菜单选中态等令牌。不得使用原型早期的黄色主按钮。
- 点击「混合」后，源卡下方出现一条 24px 圆角胶囊发送条：`X`、标题「混合」、`＋ 音频 N/100`、预计输出时长、格式菜单、「⚡0 本期免费」、灰色方形 `↑` 发送钮。未加入第二段前发送钮置灰；无独立的混合试听钮。
- 点击 `＋ 音频` 打开浮层。顶部的可滚动清单列出固定源及已加入音频；固定源标记「固定」且无移除按钮，其他条目可移除。下方为「画布／素材库／上传」三页；已加入、与固定源同 `assetId` 或达到 100 段的候选项不可再加入。上传先完成资产入库，再作为候选音频加入。
- 格式菜单向上弹出，五个选项按仓库现有浮层菜单样式呈现，当前格式使用蓝色选中态。源卡及其他原卡仍可在各自卡片上播放；所选输入不会在发送条内合成试听。

### 状态流转

| 动作或状态 | 画布可见结果 | 持久化与约束 |
| --- | --- | --- |
| 进入/编辑 | 源卡下方显示发送条和选材浮层；预计时长按已知输入时长的最大值显示，任何时长未知时标明待确定。 | 进入不创建任务、资产、结果卡或来源线；X/Esc 退出仅丢弃未提交选择。 |
| 提交被业务 API 接受 | 编辑态退出，立即创建一张**不可播放**的生成中结果占位卡；来源线连接本次所有画布输入卡。 | 冻结有序输入身份与格式，保存任务、卡片和来源线；刷新或重新打开画布仍能看到任务状态并恢复查询。点击发送需防重复建任务。 |
| 任务完成 | 同一张卡原地变为普通可播放音频成品卡，默认名 `混合结果.{格式}`；用户此时才可试听、下载及使用普通音频卡能力。 | 将供应商结果先转存为我方长期资产，再用真实 `result.duration` 回填卡片；保留冻结来源与连线。 |
| 任务失败 | 同一张卡显示失败原因与「重试」，仍不可播放；来源线保留。 | 重试沿用冻结输入和格式，在**原卡**重新进入生成中；不复制结果卡或来源线。 |
| 创建请求未被接受 | 保持发送条及已选音频，展示可读错误。 | 不产生虚假的结果卡、来源线或成功任务；允许修正后再次发送。 |

来源线须有专用 `origin=audio-mix` 语义，持久化、刷新恢复，并从音频参考推导中排除。输入卡日后被删除时，结果资产仍独立存在；画布上已不存在的节点不留下悬空线，冻结任务输入仍可审计。结果卡优先放在固定源右侧的就近空位，不覆盖已存在的输入卡。

## 供应商 API 依据与映射

### 原始资料

1. **Kim 提供的 PDF**：《智能处理 · 音频混合》，本机 `/Users/kimjohn/Downloads/智能处理_音频混合_1785209606.pdf`，7 页，SHA-256 `24d2b5d5bd0c315261c8e77ae664e6887cf8a8efc90e605ff7abbb46999da4a4`。PDF 是能力、任务流程、输入限制、结果时长与 24 小时地址约束的原始资料；实施字段已摘录于本文，无需依赖本机文件才能实现。
2. [火山引擎《提交音频混合任务 API》](https://docs.volcengine.com/docs/Intelligentprocessing/submit-audio-mixing-task-api?lang=zh)：提供 `format`、幂等与回调等 PDF 指向的接口细节；核对日期 2026-09-23，页面显示最近更新时间 2026-07-22。

**已核对差异**：PDF 示例描述“默认输出 MP3”，在线提交接口将未传 `format` 的默认值写作 `m4a`。本产品默认选 MP3，服务端每次明确传 `"format":"mp3"` 或用户选择值，因此实现**不依赖供应商默认值**。如上线前接口文档再变化，应重新验证五格式白名单和实际返回格式，不静默回退。

### 上游请求与响应

| 项目 | 火山引擎契约 | 本产品约束 |
| --- | --- | --- |
| 提交 | `POST https://mediakit.cn-beijing.volces.com/api/v1/tools/mix-audio`，`Authorization: Bearer {API_KEY}`，JSON body。成功返回 `success=true`、`task_id`、`request_id`。 | 浏览器不持有供应商密钥，不直连此地址；经我方业务 API、执行侧及网关调用。 |
| `audio_urls` | 必填数组，供应商允许 **1–100** 项；支持公网 HTTP/HTTPS、`mediakit://`、`vod://`、`tos://`；输入格式含 mp3、wav、flac 等。单文件**建议**不超过 10 GB，此为建议而非已证实的硬限制。 | 我方要求 **2–100 个不同 `assetId`**；发送前将资产解析为网关/供应商可读的 URL，不把浏览器临时对象 URL 当作输入。服务端复核归属、媒体类型、可访问性与去重。 |
| `format` | 可选；支持 `mp3`、`m4a`、`ogg`、`flac`、`wav`。 | 我方总是显式传入；默认 `mp3`。 |
| 可选辅助参数 | `media_output_destination`、`client_token`（不超过 64 个可打印 ASCII 字符的幂等键）、`callback_args`（≤512 字节）、`callback_url`、`queue_id`。 | 首版不在 UI 暴露。网关/执行侧可用 `client_token` 防重复提交；轮询已足够，不要求新增回调或专属队列。未配置授权前不传 `media_output_destination`。 |
| 查询 | `GET https://mediakit.cn-beijing.volces.com/api/v1/tasks/{task_id}`，或事件回调。任务完成状态为 `completed`。 | 持久化供应商 `task_id`，沿现有异步任务恢复机制查询，失败终态需保留原因。 |
| 错误 | 提交参数或鉴权错误可同步返回 `success=false`、空 `task_id`、`request_id` 与 `error.code/message/param/type`。 | 记录 `request_id` 供排查；同步失败不得按已提交任务轮询或显示假完成。 |
| 结果 | `result.audio_url`、`result.duration`（秒）；时长由最长输入决定。未设置目标存储时 `audio_url` 为 **24 小时有效**的 HTTPS 临时链接；设置后可为 `vod://`/`tos://`。 | 不能把临时地址直接存成永久资产；任务成功后立即转存到我方存储，创建 audio Asset，再完成任务。最终时长以实际返回值回填，跨进程存储若采用毫秒需明确从秒换算。 |
| 处理时间 | PDF 给平均 RTF≈1，耗时与最长输入时长正相关。 | 这是均值，不是 SLA 或超时上限；不能直接复制截取任务固定约 60 分钟的轮询截止。 |

上游最小请求示意：

```json
{
  "audio_urls": [
    "https://example.com/voice.mp3",
    "https://example.com/bgm.mp3"
  ],
  "format": "mp3"
}
```

成功查询结果至少读取：

```json
{
  "success": true,
  "task_id": "amk-tool-mix-audio-1501200",
  "status": "completed",
  "result": {
    "audio_url": "https://example.com/mixed_output.mp3?auth_key=...",
    "duration": 60.0
  }
}
```

## 我方实施契约与前置条件

- **任务输入快照**：新增独立 `audio_mix` 任务类型。按选择顺序冻结 `inputs: [{ assetId, nodeId? }]`（首项必须是固定源，画布输入有 `nodeId`，资产库输入没有）、`format`、固定源 `nodeId`、预计时长与提交时所需的资产定位信息。`assetId` 用于去重和实际音频，`nodeId` 只用于画布来源线。重试读快照而不是读当前选中态或重算来源。
- **浏览器与业务 API**：前端预检 2–100、身份去重及可用状态；NestJS 创建入口权威复核用户对每份资产的访问权、音频类型、可用 URL、数量、去重和五格式白名单。创建成功才回 `jobId` 并由前端建占位卡；与现有音频截取一样，创建失败留在编辑态。免费任务不冻结费用、不预留成本、不拦余额。
- **执行与网关**：执行侧经 blue-whale-api 的 MediaKit 渠道提交并查询异步任务，供应商 `task_id` 持久化，进度/终态投影回画布。拟新增对客模型 `mediakit-mix-audio`、网关路由 `POST /v1/mediakit/mix-audio`，查询沿用 `GET /v1/mediakit/tasks/{task_id}`；这是**新增契约提案，并非当前已上线接口**，网关侧实现、模型价格 0、渠道与 API Key 配置均为上线前置。网关和本仓的字段、路由、模型名必须在实现前双端对齐。
- **结果资产**：成功后先完成安全下载与我方 TOS 持久化，再建 Asset、回填结果卡/任务终态。现有音频转存先例有 **1 GiB** 上限；不能假定它可覆盖混合任务允许的输入规模。实施时须升级/验证实际产物容量能力，或另行明确产品级容量限制并补 UI 说明，避免“供应商成功而用户结果丢失”。转存失败按任务失败呈现并可重试，不暴露临时供应商 URL 作为成品。
- **轮询与恢复**：现有截取执行器每 5 秒查询、最多 720 次的约 60 分钟界限只是先例。混合可随最长输入时长增长，必须在实施时制定可恢复的超时/退避规则，验证长音频不会仅因固定次数耗尽而误判失败；刷新画布可继续追踪生成中卡。
- **来源隔离**：为每个参与的画布 `nodeId` 建 `origin=audio-mix` 的纯视觉来源边；素材库输入只保留在输入快照。音频参考推导、@ 编号和生成素材槽应跳过该来源边，防止多输入线被误当作参考素材。边与结果卡一起持久化、刷新后恢复；重试不重复建边。

## 验收要点

1. 固定源 + 1 段、2 段、100 段可发送；仅源卡不能发送，第 101 段不可加入；同 `assetId` 的画布卡/资产库条目互斥，源资产不能重复加入。
2. 画布、资产库、本地上传后的音频均可选；不可用或非音频资产不可提交；发送 payload 顺序和格式冻结，五种格式逐一验证，默认显式为 MP3。
3. 发送即出现不可播放的生成中卡；原卡可以单独播放，编辑条无混合试听。刷新后生成中卡、任务和所有画布来源线仍在；资产库输入不生成来源线。
4. 成功时先转存再回填可播放成品，时长取供应商 `result.duration`；失败卡展示原因并以冻结参数在同卡重试。创建请求失败不留下假卡；连续点击发送/重试不建重复任务、卡或线。
5. 本期免费徽标、零价网关配置、无余额拦截均成立；临时 URL 过期、长音频轮询、超过现有转存 1 GiB 的情况有可验证的处理结果，不能被标记为成功却没有可用资产。
