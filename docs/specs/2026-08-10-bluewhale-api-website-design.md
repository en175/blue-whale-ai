# BLUE WHALE API 对外官网与 API 文档站设计

- **日期**：2026-08-10
- **状态**：待评审

- **视觉与文档参考**：主页参考可灵 AI 官网；文档交互参考 fal.ai 视频 API 文档。
- **实现边界**：本文定义对外官网与公开文档站的产品、内容与发布设计；不定义控制台、SDK、计费或网关业务逻辑的重建。

## 1. 目标与范围

BLUE WHALE API 面向外部开发者售卖视频生成 API。首期目标是让访客清楚理解产品能力，并能完成“注册、创建 API Key、提交异步任务、获得结果”的接入闭环。

本期交付两块对外前端：

1. 官网主页：产品表达、开发者转化、文档与控制台入口。
2. 公开 API 文档站：从快速开始到提交、查询、Webhook 与下载的完整接入说明。

以下内容明确不在本期：

- 注册、登录、控制台、API Key 生命周期和 Python/JS SDK 的重新开发；
- 价格表、充值、免费额度、在线 Playground；文档只保留“费用以官方公告为准”的中性说明，不写任何单价；
- Chat、Embeddings、Images、独立 Audio API、Realtime、Management API 等未开放能力；
- 完整英文内容。首期中文完整，保留现有语言切换框架。

## 2. 设计决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 对外模型范围 | 仅展示 `seedance-2.0` | D3 是已确认决策；PRD 概述中的“3 个模型”不进入对外内容。 |
| 页面形态 | 保留官网与文档站两套前端 | 符合现有 React 官网原型与 Mintlify 风格文档站基线，避免重建已存在的控制台。 |
| 对外入口 | 官网 → 文档站/控制台 → 网关 | 官网只负责表达与跳转；Key、计费、任务状态和结果 URL 始终由控制台与网关负责。 |
| 文档来源 | 受控的公开 API 契约 | 不使用完整网关 OpenAPI 直接生成公开站，避免内部和未开放接口泄露。 |
| 外部部署演进 | 先保持双站，正式环境优先统一为 `/` 与 `/docs` | 保持一期改造最小，同时获得统一导航、SEO 和分析入口。 |
| API 调用位置 | 客户服务端直连 Gateway | 浏览器、官网和文档站不保存或代理客户的真实 `sk-xxx`。 |

## 3. 公开 API 契约

官网、文档站和网关必须围绕一份经过发布审查的“公开 API 契约”工作。该契约是对运行时网关契约的白名单投影，而不是另行手写的一套事实。

它至少包含：

- 对外模型 ID 与展示名：`seedance-2.0`；
- 已公开的能力参数：分辨率、时长、比例、输入模式、输出格式及其默认值；
- 已公开的 API 操作：提交任务、查询任务、Webhook 回调与结果下载说明；
- 异步任务状态、建议轮询方式、错误码、限流口径；
- 任务提交的幂等机制、幂等保留期、重复请求返回规则和超时后的安全重试方式；
- Webhook 的回调地址配置方式、事件类型、签名原文/算法、时间戳与重放保护、密钥轮换、重复通知语义、确认响应和重试规则；
- 对外 `base_url`、控制台入口、SDK 版本化入口；
- 结果 URL 的平台托管策略与有效期说明。

对外模型名和供应商/渠道内部模型名必须分层。公开页面只使用 `seedance-2.0`，不得泄露渠道配置、上游密钥、TOS 签名 URL 或内部模型标识。

公开 API 契约必须带版本号、责任方、批准状态和生效时间。只有已批准版本可生成公开内容；每次契约变更都要复验官网参数区、文档示例、FAQ、站点地图和搜索索引。

“首尾帧”“参考图”“视频生成成片音频”等文案由公开 API 契约驱动：契约未声明的能力不展示。独立 Audio API 始终不在本期公开范围内。

## 4. 用户路径

```text
官网 Hero / 内容入口
  → 查看文档或进入控制台
  → 注册、登录并创建 API Key（已有控制台）
  → 客户服务端提交视频生成任务
  → 获得 task_id
  → 轮询查询，或接收并验签 Webhook
  → 下载平台返回的结果 URL
```

官网 CTA 只可跳转到注册、登录、控制台或文档。不得在官网嵌入请求调试器，也不得要求用户把 API Key 粘贴到浏览器页面。

## 7. 异步与安全体验

任务协议遵循“提交 → `task_id` → 轮询或回调 → 下载”的统一心智：

- 提交成功只代表网关已接收任务，不代表视频已生成；
- 网关必须提供提交幂等语义；网络超时后只能按公开契约规定的方式重试，避免重复创建任务和重复计费；
- 客户可以选轮询或 Webhook，不要求同时实现两条路径；
- Webhook 必须以事件级唯一标识去重，不能仅以 `task_id` 替代事件去重；
- Webhook 文档必须说明回调地址如何配置、签名原文、时间戳/重放窗口、密钥轮换、ACK 条件和重试策略；
- 客户服务端必须校验回调真实性并以成功响应确认处理结果；
- 结果必须通过中台/平台控制的 URL 返回，文档只描述公开的有效期和下载策略；
- 认证失败、配额/额度问题、限流、参数非法、任务失败和上游超时均使用网关最终确定的稳定错误语义。

## 8. 内容红线

以下内容不得出现在官网、文档、代码示例、SEO 元数据、搜索索引或静态资源中：

- “接入所有大模型”“50+ 顶级模型”以及 GPT、Claude、Gemini、Kling、MiniMax 等未开放模型；
- Chat、Completions、Embeddings、Rerank、Moderations、独立 Audio API、Realtime、Images 和 Management API；
- 价格、单价、免费额度、充值、付费方式和余额营销文案；
- 供应商内部端点、内部模型 ID、上游签名 URL、密钥、管理入口和运行环境地址。

## 9. 发布前验证

发布包必须同时提供以下证据：

1. 公开路由与 OpenAPI allowlist 校验通过，未开放页面与操作不存在。
2. 禁用模型、禁用 API、价格/额度词和旧通用网关话术扫描通过。
3. 官网、文档站、公开 API 契约中的模型名、参数、`base_url`、控制台链接和示例保持一致。
4. 使用测试环境凭据跑通一次“提交 → 查询或回调 → 下载”的最小真实闭环，且不打印密钥。
5. 主页与文档关键路径在桌面和移动视口可访问；样片在无自动播放或减少动画环境中可读。
6. 旧 `/pricing`、旧模型页和旧文档链接有明确重定向或受控 404 行为，不能继续宣传未开放能力。

## 10. 交付顺序

1. 网关团队冻结公开 API 契约并提供可发布的参数、端点、状态、错误、限流、Webhook 和下载策略。
2. 文档站以公开契约生成/校验内容，并从公开构建中移除非白名单页面。
3. 主页替换品牌文案、能力区、参数矩阵、三段式示例和 CTA。
4. 统一官网、文档站与控制台的导航、跳转、主题和语言框架。
5. 执行发布前验证，记录闭环和内容扫描证据后再发布。
