# 图片抠图（火山 AI MediaKit）规格

> 需求共识来自 2026-09-18 三轮 grilling（13 项拍板，测试接缝经 Kim 确认）。需求工单 IKGXJ8（ready-for-agent）。术语以根 CONTEXT.md「画布图片抠图」节为准，关键取舍见 ADR-0098。接口契约设计以官方 PDF `/Users/kimjohn/Downloads/AI MediaKit_提交图像背景移除任务 API_1788872061.pdf` 为唯一权威，禁止二手资料。

## Problem Statement

画布用户在加工图片时经常需要把主体从背景中分离出来（做贴图、合成、换背景）。现在只能去外部工具抠完图再传回画布，流程被切断，画布内的画质工具家族（高清、扩图、擦除、裁切）缺少抠图这一环。

## Solution

在图片素材卡工具栏的「高清 ▾」下拉里新增「抠图」（魔棒图标，位于「擦除」之后、裁切之前）。点击后源图卡下方浮出一条横向工具栏（形态同扩图工具栏）：场景上拉三选一（通用/人像/商品，默认通用）、人像与商品场景下追加主体描边上拉（启用开关+宽度滑杆 1~50 默认 10，颜色固定白色）与透明背景裁剪点亮开关、本期免费文案、圆形发送钮。点发送调用火山 AI MediaKit「提交图像背景移除任务」同步接口全自动抠图（无选区无遮罩输入，自动识别并保留主体、移除背景），在画布上创建透明 png 结果卡（图片区垫棋盘格底纹标识透明）并与源卡拉仅表达来源关系的纯视觉连线。源图卡不动。本期免费。

## 官方 API 要点（摘自 PDF，实施以 PDF 为准）

端点 `POST https://mediakit.cn-beijing.volces.com/api/v1/tools-sync/remove-image-background`，同步接口，MediaKit 家族平台级 Bearer API Key，结果 URL 24 小时有效。

- image_url 必选：png/jpg/jpeg/heic，单张 ≤30MB；分辨率上限分场景：general 长边 ≤10240px、短边 ≤6000px、总像素 ≤40MP；human/product 长边 ≤7680px、短边 ≤4320px。
- scene 必选三值：general（通用主体）/ human（人像）/ product（商品）。
- need_contour（默认 false，仅 human/product 生效，general 忽略）：主体描边；contour_color（默认 #FFFFFF）与 contour_size（[1,100] 默认 10）仅描边开启且 human/product 时生效。
- need_crop_background（默认 false，仅 human/product 生效）：透明背景裁剪到刚好包裹主体。
- output_format：png（默认，支持透明）/ jpeg（透明填黑）/ webp；本功能固定 png。
- queue_id 可选，不传。
- 响应：success/result/error/task_id/task_type/request_id/expires_at/queue_id；result 含 image_url、image_size、image_format、image_width、image_height；error 含 code/type/message/param。

## User Stories

入口与门槛：

1. 作为画布用户，我希望图片卡工具栏「高清 ▾」下拉里有「抠图」入口（位于擦除之后），以便在画布内直接抠图而不必去外部工具。
2. 作为画布用户，我希望「抠图」入口只在图片成品卡出现（草稿卡与生成中卡不出现），以免对未成型的图发起抠图。
3. 作为画布用户，当我的图是 webp 或 gif 格式时，我希望「抠图」置灰并悬停说明支持格式。
4. 作为画布用户，当我的图超过 30MB 或超过通用场景分辨率上限（长边 10240px、短边 6000px、总像素 40MP）时，我希望菜单项置灰并悬停原因。
5. 作为画布用户，我的存量图片宽高元数据缺失时，我希望菜单项不拦我，历史数据不阻塞新功能。

工具栏与参数：

6. 作为画布用户，点「抠图」后我希望源图卡下方浮出一条横条工具栏（X 关闭、场景上拉、本期免费、圆形发送），与扩图工具栏形态一致。
7. 作为画布用户，我希望场景上拉菜单三选一：通用（自动识别画面主体）、人像（只保留人物主体）、商品（只保留商品主体），每项悬停带说明。
8. 作为画布用户，我不主动切场景时默认选中「通用」，直接点发送就能得到合理结果。
9. 作为画布用户，选「通用」时横条上不出现描边与透明裁剪控件，界面不出现对我无效的参数。
10. 作为画布用户，切到「人像」或「商品」时描边与透明裁剪控件出现，我能用上这两组增强。
11. 作为画布用户，我希望打开「描边」并拖宽度滑杆（1~50px，默认 10px）为主体生成白色描边，抠出的主体贴到深色背景不发毛边。
12. 作为画布用户，我希望点亮「透明裁剪」开关把输出透明背景裁剪到刚好包裹主体，结果不带大片空白透明区。
13. 作为画布用户，进入抠图时画布视角不动，我的画布视角记忆不被打断。
14. 作为画布用户，我按 X、Esc、点其他卡或点画布空白时退出抠图且参数丢弃，误进不留垃圾状态。
15. 作为画布用户，选了人像或商品后若图超过长边 7680px 或短边 4320px，发送钮置灰并悬停原因，场景切换后的更严上限被正确拦截。
16. 作为画布用户，横条上显示「本期免费」，我知道现在不扣积分。
17. 作为画布用户，场景上拉菜单展开后点外或再点触发钮关闭，菜单不会卡在页面上。

发送与结果：

18. 作为画布用户，点圆形发送钮后立即退出工具栏、画布出现抠图结果卡（生成中），我能继续操作画布不等在原地。
19. 作为画布用户，结果卡与源卡之间拉一条仅表达来源关系的纯视觉连线，来源可追溯且不占参考位、不参与 @ 编号与媒体索引。
20. 作为画布用户，抠图后源图卡原样保留，原图不被破坏、可再加工。
21. 作为画布用户，抠图完成后结果卡展示透明 png 且图片区垫棋盘格底纹，我一眼确认背景已移除。
22. 作为画布用户，抠图失败时结果卡呈现失败态并可重试，网络或服务波动不用从零再配一遍参数。
23. 作为画布用户，结果卡可继续擦除、高清放大、扩图、裁切、再抠图，透明 png 进下游加工链不中断。
24. 作为画布用户，生成中我不需要取消入口，与高清/擦除同门行为一致。

工程与运维：

25. 作为开发人员，我希望 worker 在接口响应后立即下载结果图落入对象存储并建素材，24 小时过期的结果 URL 不造成资产失效。
26. 作为运维人员，我希望网关新增 remove-image-background 工具并配零价后功能可用，计费护栏与免费口径同时满足。
27. 作为开发人员，我希望抠图门槛与擦除门槛各自独立判定，两个接口不同的官方输入限制互不误伤。
28. 作为开发人员，我希望失败重试沿用上次参数原样重发创建接口，重试语义与高清/擦除一致。
29. 作为开发人员，我希望前端在通用场景不传描边与裁剪参数，请求体不携带接口会忽略的字段。
30. 作为开发人员，我希望抠图工具栏与扩图工具栏同构但独立实现，扩图整包尚未合入本分支时不产生跨包依赖。

## Implementation Decisions

- 菜单：「高清 ▾」下拉菜单项数组在「擦除」之后插入「抠图」（魔棒图标），仅图片成品卡可见；置灰预检独立判定（webp/gif 格式、>30MB、超通用上限），真实尺寸缺失不拦。
- 工具栏：扩图工具栏同构横条（跟随源卡下方锚定、领土豁免标记、置灰守卫口径）；场景上拉菜单（触发钮显示当前场景、向上弹出、点外关闭）；人像/商品下追加描边上拉（启用开关+宽度滑杆实时生效）与透明裁剪点亮开关；无标题字；圆形发送钮；进入不动视角；四路退出（X/Esc/点其他卡/点空白）参数丢弃。
- 参数映射：scene 直传 general/human/product；need_contour 布尔、contour_color 固定 #FFFFFF、contour_size 1~50 默认 10、need_crop_background 布尔，四者仅人像/商品场景随请求携带；output_format 固定 png；queue_id 不传。
- 链路：镜像高清放大与擦除整条模板，新任务类型 image_cutout、独立创建端点、edge origin 纯视觉来源连线（参考推导跳过）、发送时建结果卡（无草稿先行）、失败重试分流沿用 lastInput 原参数重发。
- 后端：创建入口校验（格式/大小/按场景上限）后入队；契约新增 image_cutout 章节（web 与 worker 双端共享）。
- worker：同步调用 remove-image-background（对客模型名 mediakit-remove-image-background）、下载结果落对象存储、建素材、终态回填。
- 计费：网关配零价（model_price=0），网关配置单另行建立（对标擦除 IKGOTD 模式）。

## Testing Decisions

五层测试接缝，全部复用高清/擦除既有接缝与打法，零新设施：

1. 前端纯逻辑层：门槛判定（格式/大小/尺寸上限/null 不拦）、场景上限精校（通用 10240/6000/40MP 与人像商品 7680/4320 两档）、发送参数组装（通用场景不带增强参数、描边参数钳制）——新模块纯函数测试，先例同擦除与裁切的纯逻辑层。
2. 前端组件与画布链路：菜单项置灰门槛、工具栏交互（场景上拉开合、增强控件显隐、滑杆、发送置灰）、发送建卡连线退出、结果卡棋盘格——组件测试加画布链路测试。
3. 后端创建入口：请求校验与入队——backend 集成测试。
4. worker 执行与回填：接口映射、下载转存、建素材、终态——worker 测试。
5. 双端契约对账：契约新章节双端一致性——契约对账套件。

好的测试只断言外部可见行为（渲染结果、请求体形状、状态流转），不断言组件内部状态变量。

## Out of Scope

- 描边颜色取色器（固定白色）。
- 输出格式选择（固定 png，jpeg 透明填黑与 webp 下游不兼容被否决）。
- 批量多张抠图。
- 通用场景下的描边与透明裁剪（接口忽略，UI 隐藏而非置灰）。
- 手动选区或遮罩式抠图（接口无此输入，全自动）。
- 透明 png 进入擦除/高清/扩图/裁切的下游特殊处理（如扩图对透明区填充异常），届时另立工单。
- 积分预估与实际扣费。
- 蓝图菜单中的「重绘」项。
- 抠图工具栏与扩图工具栏收敛为共享组件。

## Further Notes

- 关键取舍与被否决方案见 ADR-0098：一键直发被否决（scene 是效果决定性参数）、高清式竖向面板被否决（同门形态一致性）、通用场景置灰显示增强控件被否决（首屏死控件）。
- 扩图整包（含横条工具栏改版）尚在独立分支未合入 release，抠图工具栏为同构独立实现，不阻塞也不依赖其合入。
- 拆票建议五票量级：契约、后端创建入口、worker 执行回填、前端（菜单+工具栏+闭环，或拆两票）、网关配置单；在 to-tickets 阶段逐票过审。
