## 2. 项目列表 `GET /api/projects`

### 2.1 查询参数

| 参数 | 规则 |
| --- | --- |
| 不传 | 返回全部项目（数组），按「置顶 → 最近编辑 → id」倒序 |
| `page` + `size` | 必须成对；返回 `{ records, total, size, current }` |
| `limit` | 1–20；只取前 N 个；**与 `page`/`size` 互斥**，同传返回 400 |
| `keyword` | 项目名模糊匹配，1–64 字符；可与任意分页方式组合 |
| `source` | `dialog`（首页生成入口）/ `canvas`（新建画布）；不传返回全部 |
| `kind` | **已废弃**：传了返回 400「参数 kind 已更名为 source」，不会静默返回全量 |

错误示例：

```json
{ "code": 400, "msg": "limit 必须在 1-20 之间", "data": null }
{ "code": 400, "msg": "source 仅支持 dialog/canvas", "data": null }
{ "code": 400, "msg": "limit 不能与 page/size 同时使用", "data": null }
```

### 2.2 响应字段

```json
{
  "records": [
    {
      "id": "101",
      "name": "2026-10-28 14:30",
      "previews": [
        { "url": "https://.../a.png", "type": "image" },
        { "url": "https://.../b.mp4", "type": "video" }
      ],
      "created_at": "2026-10-28T14:30:00+08:00",
      "last_opened_at": "2026-10-28T15:00:00+08:00",
      "last_edited_at": "2026-10-28T16:00:00+08:00",
      "pinned_at": null
    }
  ],
  "total": 42, "size": 6, "current": 1
}
```

- `previews`：最多 3 个，元素是 `{ url, type: "image" | "video" }`；**按 `type` 决定用 `<img>` 还是 `<video preload="metadata">`**，不要按扩展名猜
- `thumb`：**已删除**，不再返回
- `last_edited_at`：最近编辑时间；只读打开、改名、置顶都不会改变它
- 列表暂不返回 `source`：按请求所用的分组即可，无需再判断

### 2.3 侧栏分组写法和建议（IKR63G）

```text
分组「生成」: GET /api/projects?source=dialog&page=1&size=6&keyword=<搜索词>
分组「画布」: GET /api/projects?source=canvas&page=1&size=6&keyword=<搜索词>
加载更多:    page + 1，直到 records.length === 0 或已加载数 >= total
```

- 两个分组各自维护页码与「已加载数」；换搜索词时两组都重置到 `page=1`
- 搜索覆盖两组：同一个 `keyword` 分别请求两组
- 存量项目全在「画布」组；「生成」组上线时为空，随首页发送逐步出现
- 排序即返回顺序（置顶优先，其次最近编辑），前端不要再二次排序

## 3. 项目创建 `POST /api/projects`

```json
{ "name": "可选", "source": "dialog" }
```

| 字段 | 规则 |
| --- | --- |
| `name` | 可选；空则后端用 `YYYY-MM-DD HH:mm:ss` 命名，重名自动加 `(2)` |
| `source` | 可选，`dialog` / `canvas`；非法值 400；**不传按 `canvas`** |

- 首页「生成」入口创建时传 `source: "dialog"`；「新建画布」不传或传 `canvas`
- 来源在进入画布后**不改变**；不要在打开项目时补写来源
- 旧客户端不传 `source` 不报错，统一落 `canvas`

## 4. 项目卡片封面

- 用 `previews` 渲染缩略图，视频项用 `<video src={url} muted playsInline preload="metadata" />` 取首帧
- 无 `previews` 时显示占位（示例文案「暂无内容预览」）
- 纯视频项目、混合项目都会返回视频封面，不再出现「空预览」

## 5. 模板库（首页案例）`GET /api/agent/templates/page`

### 5.1 参数

| 参数 | 规则 |
| --- | --- |
| `tagCode` | **可选**。场景标签；不传返回全部。传值时校验以数据库标签为准 |
| `isFeatured` | `1` 只看精选；不传不限；与 `tagCode` 同时传取交集 |
| `page` / `size` | 分页，默认 `1` / `10` |

标签非法时返回 400「非法标签: xxx」。

### 5.2 响应

```json
{
  "records": [
    {
      "tag_code": "goods",
      "title": "商品展示",
      "video": "https://.../a.mp4",
      "images": ["https://.../b.png"],
      "layout": "wide",
      "content": "提示词正文",
      "is_featured": 1
    }
  ],
  "total": 12, "current": 1, "size": 10, "pages": 2
}
```

- 「用途标签」用 `tag_code` 去 `/api/agent/templates/tags` 的映射取 `label`
- 媒体类型：`video` 非空即视频卡，否则图片卡；**不再用标签判断媒体类型**
- 标签栏与页签以 `/api/agent/templates/tags` 返回为准

> ⚠️ 标签语义（`tag_code`）从「视频/图片」改为「用途/场景」依赖上线后的数据操作（新建场景标签 + 存量卡片重新打标）。数据未配置前首页仍是旧的「视频/图片」标签。

## 7. 任务失败错误体（IKR63Z）

### 7.1 轮询 `GET /api/jobs/:id`（`status === "failed"`）

失败仍是 `code !== 200` 的信封，`apiRequest` 抛 `ApiError`：

```json
{
  "code": 1011,
  "msg": "服务暂时异常，本次生成失败。",
  "data": {
    "job_id": "1585",
    "status": "failed",
    "asset": null,
    "category": "transient",
    "retryable": true
  }
}
```

### 7.2 快照 `generation_jobs[].error`

```json
{ "code": 1016, "message": "结果保存失败，结果暂未恢复。", "category": "storage", "retryable": false }
```

### 7.3 分类与动作

| category | 前端动作 |
| --- | --- |
| `transient` | 满足重试条件时显示**一个**「重试」 |
| `content_rejected` | 「修改内容」 |
| `capability` | 「修改参数」 |
| `reference` | 「更换素材」 |
| `model_unavailable` | 「修改模型」；平台额度不足**不引导充值** |
| `quota` | 引导充值 |
| `storage` | 只显示保存失败状态，不重新生成 |
| `quote_changed` | 展示新报价，用户确认后再发 |
| `unknown` | 通用兜底，保留输入，不给重试 |

- `retryable` 只表示「属于可恢复临时异常」；还要同时满足：任务明确失败、内部重试已结束、输入仍有效、没有同次待核对请求
- `1014`（`submission_unknown`）是「结果不明」，走「核对状态」，**不要显示重试**
- 文案直接展示后端 `msg`，**前端不要再维护错误码到文案的映射**
- 无「问题详情」、任务编号或内部错误；退款只显示真实返回的状态

## 8. 登录设备上限

- 同账号最多 4 个有效设备会话；第 5 个设备登录时，最早登录的会话被踢
- 同一浏览器重复登录只占一个名额（`client_id` 存 localStorage；无痕/换浏览器算新设备）
- 被踢会话的请求按现有规则重新登录（错误码 `1113` 登录已失效）

---

## 9. 需要前端同步的破坏性变更

1. `ProjectRecord.previews` 由 `string[]` 改为 `{ url, type }[]`；`thumb` 删除（项目页已同步，其它消费方自查）
2. 失败错误文案全部换成 PRD 口径，所有展示后端 message 的页面需回归
3. 首页发送创建项目要传 `source: "dialog"`，否则都进「画布」组

---

## 10. 遗留与边界

- 项目创建幂等未做：重复点击/网络重试仍可能建出两个项目，前端需保持按钮锁
- 结果「保存中」状态未新增：现有状态机只有 queued/processing/succeeded/failed/cancelled，保存失败用 `1016`
- 首页「最近项目」用 `limit=3`；「首页发送不写入近期项目」未实现，如需排除需另提后端改动
