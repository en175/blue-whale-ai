# 上下文归档（context）

本目录归档项目的**上下文记录**——每一条 `NNN-context.md` 是某个时间点的一次开发上下文快照（技术栈盘点、功能实现、问题修复、样式复刻等），供后续开发与 AI 协作时回溯。

> 这是上下文记录的**单一权威目录**。新增上下文一律写在本目录下，遵守下面的序号规则与格式规范。

---

## 序号规则（硬约束）

1. **文件名固定为 `NNN-context.md`**，`NNN` 为三位零填充序号（`001`、`042`、`043`…）。
2. **现有序号冻结**：不重排、不重新连续编号——序号一旦占用即与该条上下文绑定，永不变更。
3. **缺号留痕，不补不挪用**：本目录存在缺号 `022`（见索引表标注）。缺号保持空缺，**禁止**用缺号给新内容占位，也**禁止**把后续序号前移填补。
4. **新增自增**：取当前最大序号 **+1**。当前最大为 `044`，**下一条上下文 = `045-context.md`**。
   - 新增前先确认本目录最大序号：`ls docs/context/*-context.md | grep -oE '[0-9]+' | sort -n | tail -1`
5. **一文件一事**：一条上下文聚焦一个主题（一次功能、一次修复、一次盘点）。多主题拆成多条，各占独立序号。

---

## 格式规范

现有文件存在两种合法内容形态，**二选一**，按主题性质挑选：

### 形态 A — 变更/任务记录（默认，适用于功能实现、修复、样式复刻）

```markdown
# <描述性标题>            ← 动宾或名词短语，说清"做了什么"，禁止只用"项目上下文 NNN"

## 时间
YYYY-MM-DD

## 背景 / 目标
<为什么要做这件事、要达成什么>

## 改动 / 关键变更
<按文件或模块分点罗列；贴关键代码片段>

## 验证
<如何确认生效：截图、测试、手动操作>

## Git 提交
<关联的 commit / 分支 / PR>
```

### 形态 B — 盘点/基线记录（适用于技术栈、架构、约定的阶段性快照）

```markdown
# <描述性标题>

## 时间
YYYY-MM-DD

## <分类小节，如：核心框架 / 样式方案 / 关键依赖 / 部署基础设施>
<表格或列表>

## 其他
```

### 字段要求

| 字段 | 必填 | 说明 |
|---|---|---|
| H1 标题 | ✅ | **描述性**，禁止仅写"项目上下文 NNN" |
| 时间 | ✅ | `YYYY-MM-DD`，写在 `## 时间` 下 |
| 正文小节 | ✅ | 至少一节说明背景/目标或盘点内容 |
| 验证 | 推荐 | 变更类记录强烈建议附验证方式 |
| Git 提交 | 推荐 | 关联 commit/PR，便于回溯 |

> 历史文件（尤其 001–009）部分字段缺失或标题泛化，属于既有现状；**新增条目必须遵守上表**，不再延续泛化标题。
