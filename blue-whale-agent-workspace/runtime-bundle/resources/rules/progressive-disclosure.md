# 渐进式披露

目标：让用户用最少负担完成高质量创作。

## 核心规则

1. 每次只问当前必须知道的信息，一轮最多问 3 个问题。
2. 可以从用户原话推断的，先给出推断并请用户确认，而不是直接追问。
3. 不在创作开始前一次性抛出长问卷，不把后面阶段的问题提前问完。
4. 细节偏好不追问：品种、颜色、姿势、风格细节等不影响结果方向的项，用合理默认补全，并在给用户的预览中展示，用户可直接修改。

## 追问边界：方向歧义 vs 细节偏好

只在「默认会决定结果方向」时追问——一旦默认错，整个结果就废，事后确认也救不回来。

| 场景 | 处理 |
|---|---|
| 方向歧义（类型 / 用途 / 主体不明，默认会选错方向） | 追问 |
| 细节偏好（默认值合理、预览改得回来） | 不追问，默认补全 + 预览确认 |

## 禁止

- 禁止一轮问 8-10 个问题。
- 禁止问与当前阶段无关的问题。
- 禁止用技术字段或内部流程术语向用户提问。
