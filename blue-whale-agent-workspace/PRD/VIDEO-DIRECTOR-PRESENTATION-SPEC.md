# 视频导演 Agent 呈现与交互规格（VIDEO-DIRECTOR-PRESENTATION-SPEC）

> **状态**：PM 权威规格，迭代中。Parent map: [IK5LR4](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LR4)。17 票逐章填——✅ 已 resolve 填入，⏳ 待 resolve。
>
> **读者**：后端（落地平台 UI）、前端（实现真卡）、PM（维护规格）。
>
> **双层载体**：本地 CC（markdown 模拟卡片，可跑验证）↔ 平台 UI（真卡片）。**卡片概念归属平台 UI**，本地版是对齐验证；每条规格须说明两层各如何呈现，字段一一对应。
>
> **PM 边界（红线）**：本规格只定产品行为（看到什么 / 怎么操作 / 各场景响应）；数据模型 / branch 路由 / 状态机 / AgentRun 持久化归后端（如 IK2D7Z）。生成管线本身（平台生成 API）也归后端，本地止于提示词交付包。

## 目的

定义 video-director 编排在双层载体下，所有用户可见的呈现与交互行为，核心回答三件事：

1. **何时出卡片**（结构化产物）vs **何时用流式文本**（过程信息）
2. **何时询问确认**（确认点 / 追问）
3. **产物如何聚合输出**（如脚本与分镜、分镜与提示词）

四链路：直生 / 完整创作 / 拆解 / 复刻 + 共享生图编排。

## 票1 ✅ 卡片 vs 流式文本 出现时机总则 + 双层映射（[IK5LRV](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LRV)）

### 判断准则（供后端执行的一句话总则）

**核心判据**：输出是不是「编排定义的阶段性确认点产物」？
- **是 → 出卡**（结构化、可确认、可复制、可回看）
- **否 → 流式**（过程性、辅助当前决策、过了不必回看）

三条可执行规则：
1. **确认点产物 → 卡**：走到「需用户确认才推进」的节点，交付的结构化产物出卡。清单：Brief 摘要 / 分镜脚本 / 生图提示词 / 结构配方 / 拆解报告 / 提示词交付包 / 审核摘要。
2. **过程性信息 → 流式**：思考摘要(visible_reasoning)、进度播报、追问问题本身、一句话轻告知（如 Skill 未选自动匹配告知）。
3. **追问依附卡的确认点**：确认类追问是流式文本形态，触发依附于卡（用户在卡上确认/驳回才推进），不独立成卡。追问 UI 细节见票2。

## 票2 ✅ 确认与追问 UI 呈现（[IK5LRY](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LRY)）

### 核心模型：两阶段

**1. 追问厘清 = 纯自然语言一问一答**
- agent 与用户自然语言对话，把创作要件问清楚
- **无按钮、无快捷芯片**（平台也是开放输入框对话）
- 一次可问清多个要点（已去 3 问上限），仍分阶段、不一次性长问卷

**2. 聚合确认 = 结构化卡 + 确认按钮**
- 信息齐了 → agent 整理成结构化卡（Brief 卡 / 场景卡 / 分镜卡，按阶段产物）
- 卡上展示聚合结果 + **确认按钮**（按钮文字 = 将执行的具体动作，如「按这个分镜出提示词」）
- 用户点确认 → 进入执行；要改 → 自然语言说，agent 更新卡

### 统一原则

**任何需用户拍板推进的点（信息聚合 / 不可逆动作 / 版权风险）= 聚合成卡 + 确认按钮。** 追问纯自然语言，不按钮化。

### 不可逆动作 & 版权 & 弱继续（安全规则保留）

- **不可逆动作**（覆盖已确认的结构化结果）：聚合展示影响（「将覆盖 N 镜」）+ 确认按钮，不接受弱继续。判据：多镜/整体重写=不可逆；单镜局部改=可逆直接改。
- **版权风险**（复刻照搬结构 + 商业发布）：警示色（黄/橙）条幅 + 确认按钮（【确认已授权】/【改为差异化复刻】）。
- **弱继续**（继续/好了/下一步）：只推进低成本可逆动作。

### 双层映射

| 元素 | 本地 CC（markdown） | 平台 UI |
|---|---|---|
| 追问 | 普通段落一问一答（无按钮） | 输入框对话（无按钮/芯片） |
| 聚合确认 | 结构化卡 + 「确认无误我进 X」 | 结构化真卡 + 确认按钮 |
| 不可逆动作 | 卡 + 「这将覆盖 X，确认？」 | 卡 + 影响说明 + 确认按钮 |
| 版权提示 | 「⚠️ 版权风险…」+ 确认 | 警示色条幅 + 确认按钮 |

### 编排源调和

`natural-confirmation`「不引入确认按钮」→ 本地版仍成立（markdown 文字确认）；平台版聚合卡带按钮（卡片天然形态 + 任务启动闸门），不违反「不设固定确认门话术」——按钮是聚合产物上的推进，非每轮固定门。

### 编排源修订 → IK5MNJ

`rules/progressive-disclosure.md` 删「每轮最多 3 问」硬上限 → 修订工单 [IK5MNJ](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5MNJ)。

## 票3 ✅ 脚本与分镜 聚合输出策略（[IK5LSB](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LSB)）

### 核心决策：串行两确认门

脚本与分镜**分开产出、各自一道确认门**，非一起出：

1. 先出**脚本摘要** → 脚本门确认 →
2. 再产**分镜表** → 分镜门确认 →
3. 才交 prompt-optimizer 出提示词

两门都用票2「聚合确认 = 结构化卡 + 确认按钮」。

### 两门形态 + 双层映射

| 门 | 卡内容 | 确认按钮（=将执行动作） | 本地 CC（markdown） | 平台 UI（真卡） |
|---|---|---|---|---|
| 脚本门 | 脚本摘要三栏：方向 / 核心钩子 / 情绪转化路径 | 「基于此脚本生成分镜」 | markdown 卡 + 「确认后生成分镜」 | 脚本摘要真卡 + 确认按钮 |
| 分镜门 | 分镜表（关键帧并入「关键视觉」栏） | 「基于分镜生成提示词」 | markdown 分镜表 + 「确认后生成提示词」 | 分镜表真卡（多张分组）+ 确认按钮 |

- **关键帧清单并入分镜表「关键视觉」栏**，不独立成节/成卡/成门（它是每镜的视觉锚点，拆出来反而碎）。

### 长视频多卡（分镜门）

- **触发阈值**：>30s **或** >3 镜头（居其一即多卡）
- 多卡**按顺序排列**展示
- **局部改**：用户针对某张卡用自然语言文字描述提改（呼应票2 追问一问一答）→ agent **局部刷该卡区块**，不重推全表
- **一个总确认按钮**「基于分镜生成提示词」（末张底部，不逐卡确认）
- 每卡几镜头 / 按什么段落分组 = **票7 IK5LUC** 范围，本票不定

### 复刻模式确认差异

| 模式 | 脚本门 | 分镜门 | 局部改 |
|---|---|---|---|
| faithful（照搬） | 轻确认（照搬配方钩子换产品内容） | 每镜标「源自配方 beat N」便于对照，结构不重确认（选 faithful 即授权配方结构） | 改内容→局部刷；改结构→触发「切 method?」门 |
| method（差异化） | 按 standard 正常确认 | 按 standard 正常确认 | 同 standard |

**faithful 局部改判据**（套票2 不可逆判据 = 是否覆盖已确认结构化结果）：

- **改内容**（换画面/产品，不动 beat 顺序/时长/意图）→ 局部刷，可逆
- **改结构**（增删 beat / 调顺序 / 改时长意图）→ 偏离配方结构 = 不可逆 → 聚合卡「是否切 method 模式？」+ 确认按钮

### 编排源修订 → IK5ODM

`agents/storyboard.md` 现状一次出齐脚本+分镜+关键帧、单确认门（「请先确认脚本和分镜方向」），与本规格「串行两门」冲突 → 修订工单 [IK5ODM](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5ODM)（独立于 map，改 storyboard 输出流程 + 确认提示 + 关键帧并入 + faithful 标注）。

## 票4 ✅ 思考摘要(visible_reasoning) 呈现（[IK5LTA](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LTA)）

### 核心决策：每回合顶部细字折叠

思考摘要是**流式**（票1 已定，非卡），本票定其呈现：每个 agent 回合回复顶部、细字、默认折叠。

- **位置**：每个 agent 回合的回复**顶部**（非全局固定顶），复述该回合上下文锚点（为谁/做什么/走到哪）
- **折叠态**：露**一行首句截断** + 展开图标（如 `🤔 思考摘要：我已经有分镜了，接下来只做稳定性优化… ▸`）；非纯标题（露首句才保摘要意义）
- **默认折叠**，点开展开 1-3 短句全文
- 记住展开偏好（展开了就一直展开）= **归后端状态机**，PM 只定「默认折叠」

### 三层视觉权重（低 → 高）

| 层 | 是什么 | 视觉 | 回答 |
|---|---|---|---|
| ① 思考摘要 visible_reasoning | meta 语境层 | 细字 + 灰度低对比 + 顶部折叠 | agent 方向判断（为谁/做什么/走到哪） |
| ② 过程消息 | 内容层 | 正常字号、正常色、流式 | 具体进展（解析素材/生成第3镜/追问要点） |
| ③ 卡片 | 确认产物层 | 标题+结构化、突出（边框/底色）、可操作 | 要用户确认的产物 |

### 摘要 vs 过程消息：分开但不互斥

- **可同回合并存**：顶部折叠摘要（meta）+ 下方过程消息（内容），视觉分层不混
- 摘要答「方向对不对」，过程消息答「现在在干嘛」——别把具体进展塞摘要，也别把判断散进过程消息
- **摘要不进卡片内部**，只在卡片**上方**，不污染卡字段；卡片是视觉重心，摘要和过程消息都不抢

### 双层映射

| 元素 | 本地 CC（markdown） | 平台 UI |
|---|---|---|
| 思考摘要 | 顶部 `> 🤔 思考摘要：首句…`（细字引用块，露首句） | 顶部细字折叠条（露首句+展开图标） |
| 过程消息 | 普通段落 | 流式消息气泡 |
| 卡片 | markdown 卡（标题+表/字段） | 结构化真卡（边框/底色突出） |

### 编排源

**无修订**。`agents/*.md` 的 visible_reasoning 节 + `references/output-boundary.md` 只定摘要**内容与约束**（1-3 短句、不暴露内部 JSON/路径/推理链/组件名），呈现（顶部折叠/视觉层级）归本规格。

## 票6 ✅ 用户选定 Skill 后的分歧厘清交互 · Skill v4（[IK5LTC](https://e.gitee.com/hangzhou_xuanfu_1/projects/883843/requirements/list?issue=IK5LTC)）

### Skill v4 总则

前端库保留、用户可选；选定后 agent **尊重**，分歧**不否定/不二选一**，按 Brief 追问机制多轮厘清到确认才执行；用户未选 → 自动匹配 + 一句话告知；复刻同机制。判据与 progressive-disclosure「方向歧义 vs 细节偏好」同构——整 map 追问判据统一。

### 分歧判据（何时追问 vs 直接用）

| 程度 | 判据 | 处理 |
|---|---|---|
| **分歧大** | ①用户选 Skill 的核心 pattern 与 Brief 结果方向（类型×主体×用途）**跨类别**；**或** ②Skill 适配链路 ≠ 需求链路（如脚本密集 Skill vs 直生单镜需求） | 多轮追问厘清（分支 B） |
| **轻分歧** | 同方向同链路内，风格/细分不最优但结果方向对 | 直接用，visible_reasoning 一句带过 |

> 锚点（供后端）：「分歧大」= 默认错会**决定结果方向**（跨类别/跨链路），与 progressive-disclosure「方向歧义」同构；「轻分歧」= 风格不最优但方向对，等同「细节偏好」默认补全。

### 三分支 + 复刻

**分支 A：用户选了 · 轻分歧** → 直接用，摘要一句「按你选的 X 来」。

**分支 B：用户选了 · 分歧大** → 多轮追问厘清（对齐票2 追问=纯自然语言一问一答无按钮）：
1. agent 先**透明陈述分歧点**（尊重选的 X + 观察到的冲突维度：方向 or 链路），再**开放问需求内核**——不二选一。把「选 A 还是 B」拆成「你真正要什么」。
2. 每轮聚焦一个维度（类型/主体/用途/链路），不一次问全（去 3 问上限见 IK5MNJ）。
3. **收敛**：用户回答覆盖分歧核心维度（pattern 类别 + 链路明确）→ agent 出**聚合确认卡**（最终方向 + Skill + 理由）+ **确认按钮**（按钮文字 = 将执行动作，如「用【产品广告带货】方向开始」）→ 点确认才执行。
4. 追问**依附 Brief/推荐卡**，不独立成卡（票1）。

**分支 C：用户未选** → agent 自动匹配 + **过程消息流式一句话告知**（正常权重，**非**票4 摘要细字）：「我看了你的需求，选了 X 套路，因为…想换其他风格告诉我」。**不出独立确认卡**（票1 未把 Skill 列确认点产物——Skill 是策略非产物，频繁确认卡拖沓；用户未选 = 信任 agent）。改的出口 = 文字说，或后续阶段回退（票16）。

**复刻链路** → **复用三分支机制**，pattern 作为 Skill 选择依据（非另立）：
- pattern = agent 从原片拆解的**推断**（非用户从零选），在**拆解卡（票11）**告知「识别结构是【开箱/痛点解决/…】，方法论是 X，要改告诉我」，用户可确认/微调（对齐 progressive-disclosure「推断+确认」）。
- **faithful（照搬）**：pattern 对应 Skill 直推 + 一句话告知（同分支 C 机制）。
- **method（差异化）**：pattern 作约束，agent 先陈述各候选与原片方法论契合点，再开放问用户风格方向（同分支 B，不二选一）。
- 分歧大同上判据。

### 双层映射

| 场景 | 本地 CC（markdown） | 平台 UI |
|---|---|---|
| 轻分歧直接用 | 摘要一句「按你选的 X 来」 | 摘要细字一句 |
| 分歧大·追问 | 普通段落：陈述分歧点 + 开放问（依附 Brief/推荐卡，无按钮） | 输入框对话（无按钮/芯片） |
| 分歧大·收敛 | 聚合卡（最终方向+Skill+理由）+「确认后用此方向」 | 聚合真卡 + 确认按钮（=将执行动作） |
| 未选·自动匹配 | 过程消息段落「选了 X，因为…想换告诉我」 | 流式消息气泡 |
| 复刻·pattern 告知 | 拆解卡内「识别结构是 X，要改告诉我」 | 拆解卡字段 + 可改 |
