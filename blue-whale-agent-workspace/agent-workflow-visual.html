主 Agent 如何把需求分流到正确工作流

这张页面讲清楚三件事：Director / CEO 如何识别意图，如何路由到不同 workflow，每条 workflow 会调用哪些 Worker、Skill 和数据对象。

Director / CEO first turn

先识别意图，不先生成

每轮都先看用户消息、Canvas 状态、Workflow Run、当前 Stage、节点状态，再决定是新建、修改、确认，还是普通咨询。

咨询 / 讨论直接回答，不启动生成 workflow。
新建图片路由到 image_generation_prompt。
轻量视频路由到 direct_generation。
上传图动起来先 image_understanding，再 direct_generation。
完整广告视频进入 video_agent_canvas。
修改 / 确认先走 revise 或 confirmation_gate。
1. 状态优先

awaiting_confirm、generating、failed、pending stage 的优先级高于用户最新一句话。

2. 路由分流

Direct Image / Direct Video / Image-to-Video / Full Canvas / Prompt-only。

3. 调用执行

Worker 产出过程消息，Provider 任务进入 GenerationJob，素材进入 Canvas。

主 Agent 的决策层

Director / CEO 不直接写脚本、不直接写提示词、不直接调用 Provider。它负责判断当前应该走哪条路径，并确保确认门和画布状态不被绕过。

Director / CEO

输入：用户最新消息 + Canvas 状态 + Workflow Run + Stage + Nodes + Skill 候选。

识别意图
选择 workflow
调度 worker / skill

Step 1

咨询 / 讨论

用户只问方法、架构、规则、建议。

  • 直接回答
  • 不创建 workflow_run
  • 不写 Canvas
Step 2

新建生成任务

根据目标是图片、轻量视频、图转视频还是完整广告，进入不同 workflow。

  • Route Decision
  • 必要时补问
  • 必要时图片理解
Step 3

修改当前画布

用户说改一下、重做、换风格、保留 A 重做 B。

  • 进入 revise flow
  • 不覆盖原节点
  • 局部重跑
Step 4

确认当前结果

确认不是文本匹配，而是状态约束。

  • ready 节点
  • 明确确认
  • 才 advance_stage
Step 5

切换 Skill

用户指定某个 Skill、Use、换套路、UGC、品牌广告、短剧。

  • forced 优先
  • auto 候选其次
  • 低置信度反问
Step 6

意图不明

不猜测、不硬跑生成。

  • 问一句关键问题
  • 确认目标
  • 再进入路由

具体 Workflow 分流

每条 workflow 都有不同触发条件、Worker 调用链、Skill 使用方式和数据落点。这里是工程实现时最需要对齐的部分。

Direct Image

直接生成图片

商品图、海报、关键帧、换背景、风格图。

1
Director 识别图片任务判断 image_task_type：产品图、图生图、关键帧等。
2
Image Understanding如果依赖上传图，先得到 asset_understanding。
3
Image Prompt Agent生成主体、场景、构图、光影、必须保留。
4
Prompt Optimizer适配图片模型语法，生成 optimized_prompt。
5
GenerationJob创建 image job，同步 image canvas node。

Skill 使用

  • 可调用 E-Commerce Product Image
  • 可叠加行业 Skill：美妆、3C、食品、家居
  • Skill 决定画面策略，不替代图片模型语法
Direct Video

轻量直接视频

主体和动作清楚，不需要广告策略或多阶段分镜。

1
Director 识别轻量视频例如小猫跑步、女孩跳舞、城市镜头。
2
Brief 轻量补全默认时长、风格、画幅、稳定约束；关键缺失才追问。
3
Generation Agent整理视频提示词草案。
4
Prompt OptimizerSeedance 等模型语法适配。
5
GenerationJob创建 video job，同步 video canvas node。

Skill 使用

  • 通常不调用复杂创作 Skill
  • 可调用镜头/导演辅助 Skill
  • 不进入 Storyboard Agent
Image-to-Video

上传图转视频

让图片里的产品、人物或场景动起来。

1
Director 识别“这张图”判断用户想让图片动起来，而不是只分析图片。
2
Multimodal Capability主模型视觉 / 视觉模型 / 请用户补充三选一。
3
Image Understanding Agent产出 subject、visual_traits、must_keep、usage_intent。
4
Direct Generation引用 asset_understanding 组织图转视频动作。
5
Prompt Optimizer + Job绑定 @图片N / <主体N>，进入 video job。

Skill 使用

  • 产品转动可用产品展示 Skill
  • 人物动作可用导演/镜头 Skill
  • 没有 asset_understanding 不能调用 Provider
Full Video Canvas

完整广告视频

产品广告、UGC、短剧、品牌片、多阶段创作。

1
Brief Agent收集目标、主体、平台、素材、卖点。
2
Skill Selector选择主创作 Skill，并说明理由和风险。
3
Director 生成阶段计划脚本分镜、首批视觉、视频生成、审核。
4
Storyboard Agent生成脚本、镜头表、关键帧清单。
5
Generation + Review首批视觉、视频生成、质量检查和修改建议。

Skill 使用

  • 必须选择主创作 Skill：UGC / TVC / 短剧 / 测评等
  • 可叠加行业 Skill 和镜头 Skill
  • Skill 确认后，Prompt Optimizer 不能改创意方向
Confirm / Revise

确认或修改

用户不是每句话都代表新任务，很多时候是在操作当前画布。

1
先检查 current_stage是否 awaiting_confirm、generating、failed。
2
Confirmation Gateready 节点 + 明确确认，才允许推进。
3
弱继续二次确认“继续 / 好了 / 下一步”不能自动 advance_stage。
4
Revise Flow保留原节点，不覆盖已确认资产。
5
局部重跑带 revise instruction 创建新的 GenerationJob。

Skill 使用

  • 修改方向不变：沿用已确认 Skill
  • 用户要求换风格：回到 Skill 或阶段计划
  • 已确认结果默认不重写
Prompt-only

只优化提示词

用户只想把一段 prompt 改成 Seedance 或图片模型可用。

1
Director 识别 prompt-only不创建 GenerationJob，不调用 Provider。
2
Prompt Optimizer根据目标模型改写提示词。
3
Skill Priority Rule保留用户指定创意结构，只做语法级优化。
4
输出 preview展示 optimized_prompt_preview，不展示原始内部 prompt。

Skill 使用

  • 可参考已选 Skill
  • 不调用图片 / 视频 Provider
  • 不写 Canvas Node

Full Video Canvas 阶段链

完整视频项目必须经过这些确认点。每个过程产物在 ChatMessage 中展示，只有图片/视频素材进入 Canvas。

Brief 收集

只收集启动创作必须的信息，不一次性抛长问卷。目标是把模糊需求变成可确认的最小 Brief。

1
输入视频目标、主体、平台/时长、素材、卖点或情绪方向。
2
WorkerBrief Agent。
3
输出brief ChatMessage + missing_fields + assumptions。

Skill 匹配

Skill Selector 从用户指定、auto 候选池或 Brief 推断中选择主 Skill。低置信度时反问，不默认兜底成固定 Skill。

1
forced_skill_id用户点 Use，本 turn 最高优先级。
2
auto 候选池后端自读我的 Skills 中 auto=true 的 Skill。
3
输出skill_recommendation ChatMessage，等待用户确认。

阶段计划与脚本分镜

先完成内容结构，不直接烧生成资源。用户只改局部时，只重写对应镜头。

1
Director生成阶段计划：脚本分镜、首批视觉、视频生成、审核修改。
2
Storyboard Agent脚本、分镜表、关键帧清单、每镜头提示方向。
3
确认门用户确认脚本/分镜后，才进入视觉生成。

首批视觉

先生成最关键的视觉锚点，而不是直接生成整条视频。如果依赖上传图，必须先完成图片理解。

1
Image Understanding如有图，先得到 asset_understanding。
2
Image Prompt + Optimizer生成可执行的首批视觉提示词。
3
Canvas写入 image 节点，ready 后等待确认。

视频生成与审核

基于已确认脚本、分镜和视觉锚点生成视频，再由 Review Agent 做质量检查和修改建议。

1
Generation Agent组织视频任务，Seedance 语法只做模型适配。
2
GenerationJob创建 video job，完成后绑定 video asset。
3
Review Agent检查是否符合 Brief、Skill、镜头结构和质量要求。

Skill 如何被调用

Skill 不是提示词模板。它决定内容结构、表达方式和广告策略；Prompt Optimizer 只把已确认内容翻译成模型语法。

Skill Selector 的输入来源

Agent 在 Skill 匹配阶段按优先级选择：用户手动 Use 最高，auto 候选池其次，最后才由 Brief 推断。无法确定时必须反问。

forced_skill_id用户点 Use，本 turn 必须使用，不改变 auto 状态。
auto 候选池后端从我的 Skills 中读取 auto=true，作为可选范围。
Brief 推断没有指定时，根据目标、品类、平台、卖点匹配。
用户确认推荐 Skill 后必须允许用户改选或调整方向。

主创作 Skill

决定广告怎么讲、怎么卖，用什么结构承接 Brief。

UGCTVC短剧测评

行业 Skill

按品类补足画面重点、合规边界和用户语境。

美妆3C食品家居

镜头 Skill

在主 Skill 之外补强镜头运动、转场、构图和导演语言。

每一步产物落到哪里

这部分是前后端最容易混乱的地方：过程内容不进画布，任务不是节点，素材节点只表示图片或视频事实。

ChatMessage

过程内容

  • visible_reasoning
  • brief / skill_recommendation
  • asset_understanding
  • stage_plan / storyboard / review
  • optimized_prompt_preview
Canvas Node

素材节点

  • type 只能是 image / video
  • status: queued / generating / ready / failed
  • 绑定 stage_id 和 asset_ref
  • ready 后才能确认
GenerationJob

生成任务

  • 承载 prompt / model / params
  • queued → processing → succeeded / failed
  • 输出 Asset
  • 任务不作为 canvas node
Workflow Run

阶段状态

  • current_stage_id
  • selected_skill
  • brief / stage_plan
  • awaiting_confirm / completed / failed

压缩后的硬规则

这些是实现时不能破的护栏。它们决定系统是否稳定、是否可控、是否不会泄露内部信息。

Canvas

画布只放素材

Brief、Skill、分镜、Review、思考过程都进对话消息，Canvas 只展示图片/视频节点。

Gate

没有 ready 不能确认

用户明确确认 + 当前阶段有 ready 节点，才允许推进。

Weak continue

“继续”不自动推进

继续、好了、下一步属于弱继续，只能二次确认。

Vision

上传图必须先理解

没有 asset_understanding，不能做图生图或图转视频。

Prompt

内部 Prompt 不泄露

只展示 optimized_prompt_preview，不展示原始 prompt、trace_event、worker 名或工具参数。

Skill

Skill 不被语法覆盖

Seedance / 生图规则只做模型适配，不能改变已确认的创意结构。
