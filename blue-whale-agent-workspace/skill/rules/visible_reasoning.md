# Visible Reasoning Rule

本规则定义用户在产品界面里可以看到的“思考过程”。

## 一句话规则

展示的是产品化编排过程摘要，不是模型真实推理链。

## 为什么需要

Video Agent Canvas 不是黑盒生成。用户需要知道：

- Agent 看到了什么
- Agent 判断用户想做什么
- Agent 为什么选择某个 Skill
- Agent 下一步准备做什么
- 当前为什么停下来等确认

这些信息可以增强信任，也方便用户纠偏。

## 两层信息

### 用户可见：visible_reasoning

可以展示在前端“思考过程”区域。

内容包括：

- 对用户输入的简短理解
- 对画布素材的可见观察
- 选择 Skill 的理由
- 当前阶段目标
- 下一步动作
- 等待用户确认的原因

### 内部不可见：trace_event

只能给系统调试、日志或开发者面板使用。

内容可能包括：

- worker 名称
- prompt
- tool call
- JSON 参数
- 文件路径
- 内部错误栈
- 模型原始输出

普通用户界面不得展示 `trace_event`。

## 用户可见内容示例

### 新任务识别

```text
我理解你想为这个产品创建一条视频广告。我会先确认产品信息和视频目标，再选择合适的创作 Skill。
```

### 画布素材观察

```text
我看到画布里已有一张保温杯产品图。这个任务可以先基于产品图做视觉方向，再进入分镜或视频生成。
```

### Skill 选择

```text
这个需求更适合使用「UGC 产品广告」方向，因为它需要自然演示、真实使用场景和低压推荐感。
```

### 生成前说明

```text
脚本和分镜已经确认。我会先生成首批关键视觉，不直接生成完整视频，方便你先确认画面方向。
```

### 确认门说明

```text
当前阶段已有可确认结果。我需要你明确确认满意后，才能进入下一步。
```

## 禁止展示

以下内容不得出现在用户可见思考过程里：

- “我正在读取某文件”
- “我将调用某 Worker”
- “根据 `workers/storyboard_agent.md`”
- “使用 tool 参数如下”
- JSON / API payload
- 本地文件路径
- 完整 prompt
- 模型真实 chain-of-thought
- 未过滤的内部日志

## 生成格式

每个阶段可以输出 1-3 条短句：

```text
思考过程
1. {我看到了什么}
2. {我判断什么}
3. {我接下来做什么}
```

如果前端只支持一段文本，可压缩成一段：

```text
我看到 {观察}。这个需求更适合 {判断}。接下来我会 {下一步}。
```

## 后端落地建议

每次 Agent turn 建议同时保存：

```text
visible_reasoning: 用户可见摘要
trace_event: 内部调试事件
user_message: 给用户的正式回复
canvas_updates: 本轮写入或更新的画布节点
```

前端默认只展示：

- `visible_reasoning`
- `user_message`
- `canvas_updates`

开发者模式才允许看：

- `trace_event`

## 质量标准

好的 visible_reasoning：

- 用户能看懂
- 能解释当前动作
- 不暴露内部实现
- 不像空泛套话
- 不替用户做确认

差的 visible_reasoning：

- 只有“正在思考”
- 暴露文件名或 worker
- 把 prompt 或 JSON 展示给用户
- 长篇推理，用户看不出下一步
