# Progressive Disclosure Rule

渐进式披露的目标：让用户用最少负担完成高质量创作。

## 核心规则

1. 每次只问当前阶段必须知道的信息。
2. 一轮最多问 3 个问题。
3. 如果可以从用户原话中推断，先给出推断并请用户确认。
4. 不要在创作开始前一次性问完整长问卷。
5. 不要把后面阶段的问题提前问完。
6. **细节偏好不追问，走默认 + preview**：品种、颜色、姿势、风格等不影响「结果方向」的细节，默认补全并在 `optimized_prompt_preview` 里展示给用户改，不算追问。

## 追问边界：方向歧义 vs 细节偏好

**只在「默认会决定结果方向」时追问**——一旦默认错，整条链路 / 整个结果就废，preview 确认也救不回来。

| 场景 | 处理 |
|---|---|
| **方向歧义**（视频类型 / 用途 / 主体不明，默认会选错链路或错主体） | **追问** |
| **细节偏好**（品种 / 颜色 / 风格 / 姿势，默认值合理，preview 改得回来） | **不追问**，默认补全 + `optimized_prompt_preview` 确认 |

正例（该追问）：「做个视频」→ 追问类型；「做成视频」@ 图 → 追问用途；「做个广告」→ 追问主体；「用画布的图」但画布多图未指明 → 反问带候选（候选图消歧，见 `image_understanding.md`）。
反例（不追问）：「生成一张猫图」→ 不问品种颜色，默认补全 + preview。

## 分阶段问题

### 新任务启动

只确认：

- 要做什么类型的视频？
- 主体是什么？
- 用途或平台是什么？

如果用户已经说了，就不要重复问。

### Brief 阶段

只补：

- 产品/人物/服务是什么
- 核心卖点或情绪方向
- 是否有图片、链接或参考视频

### Skill 阶段

只确认：

- 推荐套路是否合适
- 是否要换成其他风格

### 脚本分镜阶段

只确认：

- 脚本方向是否对
- 镜头结构是否满意
- 是否有必须保留或删除的内容

### 视觉生成阶段

只确认：

- 主视觉是否满意
- 哪些图保留
- 哪些图重做

### 视频生成阶段

只确认：

- 视频是否可用
- 是否需要局部修改
- 是否完成

## 标准追问格式

```text
我先补齐当前阶段最关键的信息：
1. {问题一}
2. {问题二}
3. {问题三}
```

## 推断确认格式

```text
我先按这个方向理解：
- 视频类型：{推断}
- 主体：{推断}
- 风格：{推断}

如果没问题，我会先进入 {下一阶段}；如果要改，直接告诉我。
```

## 禁止

- 禁止一次问 8-10 个问题。
- 禁止问和当前阶段无关的问题。
- 禁止用技术字段问用户，比如 `stage_id`、`workflow_type`。
- 禁止让用户自己选择复杂内部流程。
