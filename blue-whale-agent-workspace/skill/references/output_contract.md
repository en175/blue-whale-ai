# Output Contract

所有对用户可见输出都要短、清楚、可确认。

## Brief 卡

```text
Brief 摘要
- 视频目标：
- 主体：
- 核心卖点：
- 风格方向：
- 素材情况：
- 仍待确认：

请确认这个理解是否准确。
```

## 用户可见思考过程

```text
思考过程
1. 我看到 {画布/用户输入中的关键信息}。
2. 我判断 {当前任务类型或 Skill 选择原因}。
3. 接下来我会 {当前阶段下一步动作}。
```

要求：

- 只展示产品化摘要。
- 不展示内部 prompt、worker、工具参数、JSON 或文件路径。
- 每次 1-3 条短句即可。

## Skill 推荐

```text
我建议用：{Skill 名称}

原因：
- {原因 1}
- {原因 2}

你确认用这个方向，还是要换成其他风格？
```

## 阶段计划

```text
我会按 4 步推进：
1. 脚本和分镜
2. 首批关键视觉
3. 视频生成
4. 审核和修改

每一步完成后都会先放到画布上让你确认。
```

## 确认门

```text
当前阶段结果已完成。你可以：
1. 确认进入下一步
2. 告诉我哪里要改
3. 要求重做这一阶段
```

## 修改提示

```text
我会只修改你指出的部分，已确认的内容先保留。
```

## 完成摘要

```text
已完成：
- {结果 1}
- {结果 2}

还可以继续做：
- {可选下一步}
```

## 禁止

- 不输出内部 prompt。
- 不输出文件路径。
- 不输出 worker 名称。
- 不输出 JSON 参数。
- 不让用户自己理解技术状态。
- 不输出模型真实思维链，只输出用户可见编排摘要。
- 不输出原始 `optimized_prompt`（发给 Provider 的版本，含系统指令 / 格式 token）；直生链路给用户看的是 `optimized_prompt_preview`（中文友好版）。
