# Start a handoff

Use this procedure when the user invokes `handoff start`. Treat any words after `start` as the next session's focus. Apply the summary, suggested-skills, artifact-reference, and redaction rules in `../SKILL.md`; replace only its instruction to save a document with the dispatch procedure below. Name suggested skills without assuming the recipient has a tool literally named `Skill`.

1. Add the current workspace path, branch, HEAD, and uncommitted paths to the summary when the work involves a repository. Point to existing artifacts and state the next concrete action. If code exploration matters, include the graph evidence and coverage limits required by the repository's discovery rules. Explain which uncommitted files a separate workspace cannot see. The summary is ready when the recipient can locate the work and take that action without reconstructing this conversation.
2. Start a fresh task in the current agent product using its native task or session creation capability. Give it the summary as its initial prompt and use an accessible workspace that follows the repository's worktree rules. Use Claude Code's `claude --bg --name` for a Claude Code background session. In Codex desktop, use its new-task tool when available. In Kimi Code or ZCode, use a native task creation capability only if the current host exposes one. A CLI print or one-shot execution is not a managed background task. This step succeeds only when the host returns a task identifier or another verifiable handle.
3. Verify and report the new task's name or ID, workspace, and actual state: running, queued, or finished. If the host cannot create and identify a suitable task, save the summary to the operating system's temporary directory as a private file readable only by the current user, then give the user one concrete action to open a new task in that product with the summary. Report explicitly that the new task has not started.
