## 生成步骤

1. **计算时间窗口**：上周五 00:00 ~ 本周四 24:00（本周四 = 创建当天）
2. **拉取数据**：用 gitee-ent MCP 对三个项目分别调 `list_enterprise_pulls` / `list_enterprise_issues`，按时间窗口过滤。PR 用于团队合并总数统计（排除老板）；Issue 重点梳理：本周关闭工单、新增 P0/P1 工单、遗留问题。**不对个人做数量统计**
3. **创建文档**：`lark-cli wiki +node-create --parent-node-token <团队会议节点token> --title "团队周会汇报 YYYY-MM-DD" --as user`
   - 团队会议节点 token：`V05hwDCOdirplmkpR0Fcyxu3nnh`（空间 7670789579678501830）
4. **填充底稿**：`lark-cli docs +update --doc <URL> --command append --content <XML>`，按模板结构写入：元信息区 + 一、二、三（从数据提炼）+ 六 + 附录 A；四、五留空
5. **继承上周待办**：fetch 上周文档「五、待办清单」未勾选的 checkbox，复制到新文档五、待办清单开头（保留原责任人，截止时间顺延一周）
6. **交付**：告知用户文档链接，标注 🔄 底稿状态，等待人工修改

## 注意事项

- PR/Issue 数字以 Gitee 拉取结果为准，不要编造
- **个人不量化**：成员详情禁止出现任何个人数量指标；数字只出现在团队层面概览表
- 贡献描述用价值语言：方案设计、救火、协调、评审等非 PR 工作必须计入
- 概览禁止"一大坨"：必须用加粗引导句分点（亮点。/风险信号。）
- 敏感信息（密码、AK/SK、Token）禁止写入文档
- 生成底稿后等待用户修改定稿，不要自行宣称定稿
- 附录 B 用于本周专题存档（如 CI/CD 治理），正文保持精炼
