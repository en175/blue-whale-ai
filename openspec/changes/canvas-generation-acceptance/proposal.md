# 提案：Canvas 生成全链路验收

关联工单：`IK4AJJ`。本变更是父工单中的 Canvas 生成验收纵向切片，不声称 Java/Python 已整体退役。

## 目标

在当前 master 上证明并修复以下真实链路：

`Canvas -> Next 路由处理器 -> Node 持久化与运行时 -> BullMQ 视频 Worker -> New API/TOS -> MySQL 素材`

图片走现有 Node 生成运行时；视频必须经过独立 BullMQ Worker。所有可付费生成先通过契约测试、假实现和免费模型能力检查，再执行受控真实调用。

## 范围

- Canvas 图片/视频上传、生成配方、任务 ID、快照水合、刷新恢复和并发。
- 图片 10 并发压力；视频真实任务串行执行。
- New API 登录、用量、模型能力发现以及图片/视频请求契约。
- 首帧、尾帧、参考素材的素材 ID 语义和供应商请求体证据。
- TOS 公网 URL、素材/生成任务持久化和成功后刷新展示。
- 音频只验证上传、播放器和当前生成假实现边界，不建设真实音频供应商。

## 非目标

- 不修改 `blue_whale_api/`。
- 不改 Nacos、线上配置或提交任何凭证。
- 不在本变更中声称所有 Java/Python 服务已退役。
- 不把音频假实现结果写成真实音频迁移完成。

## 真实调用预算

- 图片：最多 10 个并发真实任务，使用最小输出数量和同一测试用户。
- 视频：一次只运行一个真实任务，完成并检查数据库、素材和刷新结果后才运行下一个。
- 真实视频优先顺序：文生视频、单首帧、首尾帧、跨模态回填；若 New API 能力不支持某语义，停止扣费并记录为“后端能力缺失”。
- 模型列表和配置组合通过免费能力接口、单元测试和假供应商全量穷举；真实调用只覆盖预算内的关键路径。
